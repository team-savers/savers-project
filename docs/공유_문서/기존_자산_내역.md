# 기존 자산 내역 - 지금 코드에 무엇이 있는가

평가 하네스 작업의 입력 문서입니다.
**저장소 `main`(2026-08-21 기준)을 직접 세어 만든 실측**이며, 추정치는 없습니다.
"없다"고 적힌 것은 전 확장자 검색 결과 **0건**이라는 뜻입니다.

> 하네스 작업자가 먼저 볼 곳: **3절(지표 함수 13개)**과 **6절(채워야 할 자리)**.
> **7절은 구독/계정 자산**입니다 - 지금 돈이 나가고 있는 것, 키가 발급된 것, 아직 없는 것.
> 지표 목표값과 검증 설계는 [정량목표_검증설계.md](정량목표_검증설계.md)에 있습니다.

## 1. 한 문장

**평가 하네스의 자리와 규칙은 이미 코드로 고정돼 있습니다. 비어 있는 것은 두 가지입니다 -
채점 대상(실측값)과 골든셋 규모(현재 6건).**
그리고 **지표 함수 13개는 "행동요령 코퍼스 인용"을 전제로 만들어졌으므로,
검색 대상이 이벤트 로그로 바뀌면 그중 일부는 의미가 달라집니다.** 3절을 보세요.

| 파일 | 규모 | 역할 |
|---|---|---|

**설계 원칙 두 개가 코드로 강제돼 있습니다.**

1. **못 잰 것은 0이 아니라 `null`** - 모든 지표 함수가 `float | None`을 반환합니다.
   측정 불가와 0점을 구분하지 않으면 제출 지표가 거짓이 됩니다.
2. **채점 코드는 채점 대상을 import하지 않는다** - `eval/`이 `src/ai_engine/`에 의존하지 않습니다.
   자기가 만든 답을 자기가 채점하는 구조를 막습니다.

**전체 테스트 수** - ai-engine 157, backend 86, e2e 7 = **250건**.

## 3. 지표 함수 13개 - 무엇을 재고, 무엇이 바뀌어야 하는가

| 함수 | 무엇을 재나 | 이벤트 로그 전환 후 |
|---|---|---|
| `sentences(text)` | 문장 분리 | **그대로 씀** |
| `bigrams(text)` | 바이그램 집합 | **재검토** - 아래 |
| `strip_frame(body, frame_phrases)` | 정형 문구(인사말 등) 제거 후 본문만 | **그대로 씀** |
| `support_ratio(sentence, source_quotes)` | 문장이 근거 인용문에 얼마나 겹치는가 (바이그램 기준) | 주의: **의미가 달라집니다** - 아래 |
| `unsupported_sentences(...)` | 지지되지 않는 문장 목록 | 주의: 위와 동일 |
| `source_fidelity(...)` | 근거 일치율 (주지표 후보) | 주의: 위와 동일 |
| `hallucination_rate(...)` | 환각 발생률 | **개념은 유지**, 판정 근거가 바뀜 |
| `suppression_rate(baseline, guarded)` | 가드레일 on/off 대비 억제율 | **그대로 씀** |
| `directive_present(body)` | 응답에 행동 지시가 있는가 | **보호자 응답에는 부적합** - 보호자 답변은 상태 보고이지 지시가 아닙니다 |
| `fact_echo_ratio(body, facts)` | 주어진 사실이 응답에 반영된 비율 | **여기가 새 주지표의 뼈대** - 아래 |
| `percentile(values, q)` | 백분위 | **그대로 씀** (p95 지연) |
| `latency_summary(samples_ms)` | 지연 요약 | **그대로 씀** |
| `mean(values)` | `None` 안전 평균 | **그대로 씀** |

### 주의: `support_ratio`가 그대로 쓰이지 않는 이유

현재 `support_ratio`는 **문장과 원문 인용구의 바이그램 겹침 비율**입니다.
국민행동요령처럼 **원문을 그대로 인용해야 하는 코퍼스**에는 맞는 설계입니다.

그런데 보호자 RAG의 근거는 **이벤트 로그 레코드**입니다 -
`PUSH_SENT 21:12`, `ROUTE_ENTER 21:14` 같은 구조화된 사실이지 문장이 아닙니다.
"21:14에 경로 안내 화면에 들어가셨습니다"라는 문장은
`ROUTE_ENTER 21:14`와 **바이그램이 거의 겹치지 않습니다.**
이 함수를 그대로 쓰면 **맞는 문장이 전부 미지지로 떨어집니다.**

**필요한 것은 새 함수 하나**입니다 -
"문장을 주장 단위로 쪼개고, 각 주장을 이벤트 로그 레코드와 **키-값 대조**한다".
기획서가 "주장 단위로 쪼개 로그와 1:1 대조"라고 쓴 것이 이것이고,
**`fact_echo_ratio`가 그 뼈대에 가장 가깝습니다**(주어진 사실 목록과 대조하는 구조).

### 주지표는 이렇게 정의됩니다

**"로그에 없는 사실이 섞인 응답 0건"** -
비율이 아니라 **건수**이고, 목표는 0입니다.
`unsupported_sentences`가 반환하는 목록의 길이가 그대로 이 지표가 됩니다.
**함수 시그니처를 바꿀 필요 없이 `source_quotes` 자리에 로그 레코드를 넣는 구조로 가면 됩니다.**

### 골든셋이 6건입니다

`golden_dataset/flood_v0.jsonl`이 **6건**입니다.
기획서가 약속한 평가셋 규모(예선 30~50건 -> 본선 확장)에 크게 못 미칩니다.
**보호자 응답 골든셋 40건**(추천 30 + 기타 10)을 별도로 만들어야 하고,
"기타"에는 **회수 0건이 나오는 질문을 일부러 넣어야** 합니다 -
[#24](https://github.com/team-savers/savers-project/issues/24)에서 과잉거절의 원인이
임계값이 아니라 **검색 문턱**으로 밝혀졌고,
회수 0건이면 생성 전에 반환되므로 **폴백이 버그가 아니라 정상 경로**임을 하네스가 확인해야 합니다.

### 실측치가 커밋되어 있지 않습니다

PU 파이프라인 실행 결과(P=73 / RN=504 / baseline 0.1353%)가
**커밋 메시지 산문에만 있고 `summary.json`이 레포에 없습니다.**
`.gitignore:131`이 `/outputs/`를 차단하고 있어서인데,
**예외 한 줄을 열어 `outputs/shelter_safety/summary.json`만 커밋하면**
심사에서 재현 가능한 수치가 됩니다. 가장 저비용, 고효과 조치입니다.

## 7. 구독/계정 자산 - 지금 무엇을 쓰고 있는가

코드가 아니라 **계정과 키**의 목록입니다.
"구독 중"은 지금 과금이 발생하거나 발생할 수 있는 것, "키만 있음"은 발급받았으나 코드가 쓰지 않는 것,
"없음"은 아직 만들지 않은 것입니다.
