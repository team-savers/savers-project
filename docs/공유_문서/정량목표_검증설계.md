## 1. 정량 목표 4종

기획서 2장 「제품 가설 세 개와 검증 이터레이션」 말미에 확정된 값입니다.
**가설 목표치가 아니라 판정 기준**이며, 미달 시 감추지 않고 실패 사례로 기재합니다.

| # | 지표 | 목표 | 무엇을 재는가 | 측정 주체 | 현재 |
|---|---|---|---|---|---|
| **M1** | 알림 도달 | **30초 이내** | 특보 수신 → 실기기 웹푸시 도달까지의 종단 시간 | Backend | 미측정 — FCM 실발송이 8/22에 붙습니다 |
| **M2** | 보호자 응답 정확도 | **100%** | **로그에 없는 사실이 섞인 응답 0건**. 응답을 주장 단위로 쪼개 이벤트 로그와 1:1 대조 | AI/RAG | 미측정 — 검증기가 8/26에 붙습니다 |
| **M3** | **위치정보 미수신** | **서버에 좌표가 도달하는 지점 0건** | 좌표를 받는 엔드포인트·저장하는 필드가 어디에도 없는가 | QA·보안 | `check_privacy.py`가 자동 점검 — PR #76 머지 후 CI 상시. **3절 참조** |
| **M4** | 폐루프 2차 발송 성공률 | **100%** | 30분 무응답 판정 후 보호자 2차 발송이 실제로 나가는가 | Backend | 미측정 — 페루프가 8/28에 붙습니다 |

**채점 스크립트·평가셋·학습 코드를 함께 제출합니다.**
못 잰 것은 0이 아니라 `null`로 남기는 것이 `eval/metrics.py`의 규칙이고, 이 표도 같은 규칙을 따릅니다.

## 2. 부합도 모델 검증 4겹

기획서 3장 「핵심 기술① 대피소 부합도 모델」의 검증 설계입니다.

| # | 검증 | 내용 |
|---|---|---|
| **V1** | 자치구 GroupKFold 공간 블록 교차검증 | 인접 시설이 학습·검증에 함께 들어가 성능이 부풀려지는 것을 막습니다 |
| **V2** | **비(非)학교 대피소 recall@top-20%** | **주지표.** 「학교 목록을 쓰면 되지 않나」에 답하려면 학교를 뺀 나머지에서 성능이 나와야 합니다 |
| **V3** | 침수예상도 베이스라인 대비 lift | 랜덤이 아니라 기존 침수예상도 대비 얼마나 나은가 |
| **V4** | 문자열·표준필드·모델 3자 비교 | 규칙으로 되는 일을 모델로 포장하지 않기 위한 대조군 |

**중단 조건.** 정답이 없는 16개 시·도에 적용했을 때
**외부 검증 lift가 사전 고정 임계값에 미달하면 PU 방식을 중단**하고 그 사실을 기재합니다.

### 라벨과 피처의 분리 (절대 원칙)

| 구분 | 무엇 | 어디에 쓰나 |
|---|---|---|
| **라벨·검증 전용** | 서울시 수해대피소 지정 목록, 침수예상도 | 정답과 검증에만. **모델 입력에 넣지 않습니다** |
| **모델 입력** | 표고 · 대피 여유고 · 지하층수 · 하천 최단거리 등 **전국 공통 공개 데이터 13개** | 학습·추론 |

서울 전용 데이터가 피처로 새면 「전국 이식」 주장이 성립하지 않습니다.
이 분리가 깨지는지를 하네스가 검사해야 합니다.

### 계단 효과 3단계

| 단계 | 방법 | recall | precision | 남는 한계 |
|---|---|---|---|---|
| 1차 · 규칙 | 주용도 = 「교육연구시설」 한 줄 | 75.7% | 13.2% | 학교가 없는 저지대 동을 통째로 비웁니다 |
| 2차 · 규칙 추가 | 「교육연구시설」 **또는** 연면적 3,000㎡ 이상 | 84.7% | 2.1% | recall은 오르지만 precision이 붕괴합니다 |
| 3차 · 학습 | 전국 공용 지정·건물 피처 학습 | 84.7% 유지 | 2배 이상 | **아직 측정 전** |

1·2차는 서울시 지정 목록을 정답으로 직접 계산한 값입니다.
3차는 유사 기법 선행연구의 보고치를 목표 구간으로 기입한 것이며(자세한 인용은 기획서 [표 3] 주석),
**본선까지 자체 실측으로 교체합니다.**

> **3차가 2차를 넘지 못하면 그 사실을 실패 사례로 기재합니다.**
> 규칙으로 되는 일을 모델로 포장하지 않는 것이 이 팀이 지키려는 선입니다.

## 3. M3을 「파기」에서 「미수신」으로 바꿉니다 ★ 2026-08-21 확정

### 왜 바꾸는가 — 「파기 100%」는 코드로 뒷받침되지 않습니다

`backend_core/sessions.py`의 `SessionStore`에는
`create` / `get` / `get_by_guardian_token` / `mark_opened` / `record_response` 다섯 메서드만 있고
**삭제·파기 메서드가 없습니다.**
TTL은 접근 차단이지 파기가 아니며, 만료된 레코드는 메모리에 무기한 남습니다.
게다가 `get_by_guardian_token`이 있어 **보호자 토큰으로도 같은 레코드에 도달**합니다.

「즉시 파기 준수율 100%」를 주장하려면 **지웠다는 것을 증명**해야 합니다 —
삭제 시점, 잔존 여부, 백업·스왑에 남았는지까지. 그런 기구가 없습니다.

### 무엇으로 바꾸는가

> **M3 · 위치정보 미수신 — 서버에 좌표가 도달하는 지점 0건**

**저장하지 않으므로 파기할 것이 없습니다.**
「없다」는 것은 **스캔으로 증명**됩니다 — 「지웠다」보다 증명이 쉽고, 증명이 더 강합니다.

### 이 문구는 기획서 4장과 이미 일치합니다

제출 기획서 4장 「보안성」이 스스로 이렇게 적었습니다 —

> 행정동 판정과 대피소 선정을 **클라이언트에서 처리해 좌표 수신 엔드포인트가 없습니다.**
> **「저장하지 않는다」가 아니라 「받지 않는다」**이며, 정책 문구가 아니라 **코드로 증명되는 구조**입니다.

**기획서 안에서 2장(정량목표)과 4장(보안성)이 서로 어긋나 있었습니다.**
2장은 「즉시 파기 100%」, 4장은 「받지 않는다」. 이번 변경은 **2장을 4장에 맞추는 것**이고,
새로 만드는 주장이 아니라 **원래 설계대로 되돌리는 것**입니다.

### 무엇을 말할 수 있고 무엇을 말하면 안 되는가

| | 내용 |
|---|---|
| ✅ **말할 수 있음** | 서버에 좌표를 받는 엔드포인트가 없습니다 |
| ✅ | 세션·이벤트 로그 스키마에 좌표 필드가 없습니다 |
| ✅ | `check_privacy.py`가 매 PR마다 전 트리를 스캔해 이것을 검사합니다 |
| ✅ | 브라우저는 좌표를 씁니다 — 경로 계산을 위해. **그 값은 기기 메모리에만 있고 서버로 가지 않습니다** |
| ❌ **말하면 안 됨** | 「즉시 파기」 · 「파기 준수율 100%」 — 파기 기구가 없습니다 |
| ❌ | 「좌표를 전혀 다루지 않는다」 — 클라이언트는 다룹니다. 숨기면 그 자리에서 무너집니다 |

### 측정 방법

1. **`scripts/check_privacy.py`** (PR #76) — 위치정보 미저장·민감정보 암호화 전 트리 자동 점검.
   **머지로 끝나지 않습니다.** ① PR #76 머지 → ② `.github/workflows/`에 연결 → ③ **시험 PR 1건에서 실제로 돌아간 로그 확인**.
   세 단계를 다 해야 「매 PR마다 검사가 돕니다」를 말할 수 있습니다. **8/25, 2h, PM 소관 P0.**
   8/29에 한 번 더 돌려 결과를 캡처해 발표 보안 슬라이드에 씁니다.
2. **이벤트 로그 스키마 검사** — 8/22 오전 확정 시 **좌표 필드를 넣지 않습니다**.
   Tech Lead PR 리뷰 3항목 중 하나가 「세션·로그에 좌표 필드가 들어갔는지」입니다.
3. **좌표 수신 엔드포인트 부재 확인** — OpenAPI 스펙에 좌표를 받는 경로가 없음을 확인.

### 본선 질의응답 대비

> **Q. 위치정보는 어떻게 파기하나요?**
> A. 파기하지 않습니다. **받지 않기 때문입니다.** 행정동 판정과 대피소 선정을 기기 안에서 처리해서,
> 서버에는 좌표를 받는 엔드포인트 자체가 없습니다. 매 PR마다 스크립트가 전 코드를 훑어 이걸 검사하고,
> 이 점검 도구는 실제로 결함을 한 번 잡아냈습니다 — `ShelterMap.tsx` 뒷부분이 검사에서 빠져 있던 것을요.

> **Q. 그럼 좌표를 아예 안 쓰나요?**
> A. 브라우저는 씁니다. 경로를 그리려면 필요하니까요. **다만 그 값이 기기를 떠나지 않습니다.**
> 「안 쓴다」가 아니라 「보내지 않는다」입니다.

## 4. 하네스가 채워야 할 자리

`apps/ai-engine/eval/`에 지표 함수 13개와 테스트 37건(지표 29 + 골든셋 8)이 이미 있습니다.
**자리와 규칙은 고정돼 있고, 채워야 할 것은 실측값입니다.**

| 하네스 항목 | 대응 지표 | 선행 조건 |
|---|---|---|
| 종단 지연 측정 | M1 | FCM 실발송 (8/22) |
| 로그 1:1 대조 채점 | M2 | 이벤트 로그 API (8/24) + 검증기 (8/26) |
| 미수신 회귀 테스트 | M3 | `check_privacy.py` 머지 + CI 연결 (파기 루프는 만들지 않기로 확정) |
| 페루프 발송 로그 대조 | M4 | 30분 페루프 (8/28) + 시연용 30초 단축 플래그 |
| recall@top-20% · lift | V2·V3 | 부합도 모델 실학습 (8/22~24) |
| 라벨-피처 분리 검사 | 절대 원칙 | 피처 목록 확정 |

**골든셋에는 회수 0건이 나오는 질문을 일부러 넣습니다.**
[#24](https://github.com/team-savers/savers-project/issues/24)에서 확인된 대로
과잉거절의 원인은 임계값이 아니라 **검색 문턱**이었고,
회수 0건이면 생성 전에 반환되므로 **폴백이 버그가 아니라 정상 경로**임을 하네스가 확인해야 합니다.
