# 공유 문서

기획서·인터뷰 가이드처럼 **계속 개정되는 문서**를 팀이 한 곳에서 보기 위한 폴더입니다.
같은 문서의 여러 판본이 메신저·개인 드라이브에 흩어져 "어느 게 최신인지" 묻는 일을 없애는 것이 목적입니다.

운영 방식(Tech Lead 신호정, 2026-08-05 협의): **문서 파일은 이 폴더에 올리고, 아래 표에 최종 수정일·버전·핵심 내용을 기록**합니다.
표가 곧 목차이자 변경 이력이므로, 파일만 올리고 표를 비워두면 이 폴더는 그냥 또 하나의 드라이브가 됩니다.

## 기록 규칙

- **최종 수정일**: `YYYY-MM-DD`. 파일을 고치면 같은 PR에서 이 칸도 같이 고칩니다(파일만 바뀌고 표가 그대로면 표를 신뢰할 수 없게 됩니다).
- **버전**: `v0.1`부터 시작해 내용이 바뀌면 소수점을 올리고(`v0.2`), 대외 배포·확정 시 `v1.0`으로 올립니다. 파일명에는 버전을 넣지 마세요 — 링크가 매번 깨집니다.
- **핵심 내용**: 한 줄. 문서를 열지 않고도 "지금 내가 찾는 문서인지" 판단할 수 있을 정도면 충분합니다.
- **상태 · 근거**: `확정`이면 근거(ADR 번호 또는 문서 경로)를 같이 적고, 근거를 댈 수 없으면 `검토 중`으로 적습니다. → [AGENTS.md](../../AGENTS.md) "Collaboration / Git"
- 문서 파일명은 한글 + 밑줄(`인터뷰_가이드.md`) — 문서 폴더의 명명 규약입니다. → [AGENTS.md](../../AGENTS.md) "Naming convention"

## 올리기 전 확인

이 저장소는 **public이고 심사위원이 직접 열어봅니다.** 올리기 전에 두 가지를 확인하세요.

1. **개인정보·서명**: 팀원 이름 외의 개인정보(연락처·주소·소속기관 담당자 실명), 서명란, 인터뷰 응답자 신원이 문서에 남아 있지 않은지. 남아 있으면 지우고 올립니다.
2. **제출 서류 여부**: 참가신청서 등 대회 제출 서류는 이 폴더에도 올리지 않습니다. `.gitignore`는 `docs/제출_자료/` **경로만** 차단하므로, 같은 파일을 이 폴더에 두면 차단이 풀린 채로 커밋됩니다. → [AGENTS.md](../../AGENTS.md) "Not in this repository"

문서 갱신은 다른 변경과 동일하게 **feature 브랜치 → PR → squash merge**를 거칩니다. → [pr-checklist.md](../pr-checklist.md)
