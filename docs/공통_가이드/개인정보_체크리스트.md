# 개인정보·위치정보 준수 체크리스트 (QA/보안 점검 계획)

담당: 안은남(PM · QA/보안 · 인프라). 역할 정의: [역할_가이드/01-기획총괄.md](../역할_가이드/01-기획총괄.md) ·
일정: [역할_일정/01-기획총괄.md](../역할_일정/01-기획총괄.md). 관련 승인 항목:
[외부_승인.md](외부_승인.md) E절. 관련 리스크: [리스크.md](리스크.md) ⑨.

이 문서는 자체적으로 법을 해석한 결과가 아니라, **개인정보보호위원회(PIPC)가 공개한
가이드라인·고시**를 이 프로젝트의 구체적 데이터 필드(위치정보, 장애 여부)에 매핑한
점검표입니다("자체 법률 해석 대신 공개된 가이드라인/체크리스트 활용" 원칙).
**8/29 시연 환경 배포 직후** 점검 스크립트(로그·DB 스캔)로 각 항목을 검증할 때 이 표를 기준 삼습니다.

> **검증의 성격이 바뀌었습니다.** 행정동 판정과 대피소 선정을 클라이언트에서 처리하도록 설계가 바뀌면서
> **좌표 수신 엔드포인트 자체가 존재하지 않습니다.**
> 「저장하지 않는다」가 아니라 「받지 않는다」이므로,
> 점검은 "지운 흔적을 찾는" 것이 아니라 **"받은 적이 없음을 확인하는"** 형태가 됩니다.
> **「위치정보 미수신 — 서버에 좌표가 도달하는 지점 0건」**은 이 구조 위에서 측정되는 4대 지표 중 하나입니다.
> (2026-08-21에 「즉시 파기 준수율 100%」에서 문구를 바꿨습니다 — `SessionStore`에 파기 메서드가 없어
> 「파기」는 코드로 증명되지 않고, 「받지 않는다」는 스캔으로 증명됩니다.
> 근거: [정량목표_검증설계.md §3](../공유_문서/정량목표_검증설계.md))

> ⚠️ **신뢰도 표기**: 아래 근거 법령·고시명은 높은 신뢰(공개 검색으로 확인)이나, 조항 번호·시행일은
> 시간이 지나면 개정될 수 있습니다. 실제 적용 전 [국가법령정보센터](https://www.law.go.kr)와
> [개인정보보호위원회](https://www.pipc.go.kr) 최신본으로 재확인하세요 — 이 표 자체가 법률
> 자문을 대체하지 않습니다.

## 1. 위치정보 — 위치정보의 보호 및 이용 등에 관한 법률(위치정보법)

SAVERS의 비타협 제약("상시 위치 추적 없음", [AGENTS.md](../../AGENTS.md))이 실제로
위치정보법의 개인위치정보 보호 의무와 일치하는지 확인하는 항목입니다.

| # | 점검 항목 | 근거 | 검증 방법(8/29 점검 스크립트 대상) |
|---|---|---|---|
| P1 | 개인위치정보 수집 전 **동의**를 받았는가 (알림 링크 진입 = 위치 조회 발생 시점에 별도 고지) | 위치정보법 제15조·제18조 | 알림 진입 플로우에 동의 UI/문구가 위치 조회 API 호출보다 먼저 실행되는지 코드 경로 확인 |
| P2 | 수집 목적을 달성한 즉시 **파기**하는가 (요청-응답 세션 범위를 벗어나 저장하지 않음) | 위치정보법 제16조 | 로그·DB 스캔: 원본 좌표(위경도)가 어떤 테이블/로그 파일에도 없음을 자동 확인. **좌표 수신 엔드포인트 부재**가 1차 근거이고 스캔은 그 확인입니다 |
| P3 | 동의 철회 시 **지체 없이 파기**하는가 | 위치정보법 제18조 | 세션 스코프 설계상 "저장 자체가 없음"이 철회 파기 요건을 자동 충족하는지 논리 검증 (저장이 없으면 파기할 대상도 없음 — 설계로 요건을 무력화하는 방식) |
| P4 | 위치정보 수집·이용·제공 **사실 확인자료**를 법정 기간 보관하는가 (원본 좌표와는 별개로, "언제 누구 위치를 조회했는지"의 메타 로그) | 위치정보법 제16조제2항 | 원본 좌표 없이 조회 시각·사용자 ID만 남기는 감사 로그가 있는지 확인 — 이 메타 로그 자체는 "개인위치정보"가 아니므로 즉시 파기 대상 아님 |

## 2. 장애 여부 등 민감정보 — 개인정보 보호법 제23조

| # | 점검 항목 | 근거 | 검증 방법(8/29 점검 스크립트 대상) |
|---|---|---|---|
| S1 | 장애 여부를 **일반 개인정보 동의와 분리된 별도 동의**로 수집하는가 | 개인정보 보호법 제23조 | 등록(보호자/복지관/지자체 대행) 플로우에서 동의 항목이 "일반 동의"와 "민감정보 동의"로 UI/데이터 모델상 분리돼 있는지 확인 |
| S2 | 민감정보 수집·이용 목적이 구체적으로 명시돼 있는가 (예: "개인 맞춤 행동지침 생성"으로 한정, 포괄 동의 아님) | 개인정보 보호법 제15조·제23조 | 개인정보처리방침·동의 문구 텍스트 검토 (자동화 어려움 — 사람이 문구 존재 여부만 체크) |
| S3 | 민감정보를 **저장 시 암호화**하는가 | [개인정보의 안전성 확보조치 기준](https://www.law.go.kr) (PIPC 고시) | DB 스캔: 장애 여부 필드가 평문으로 저장돼 있지 않은지 자동 확인 (컬럼 값이 암호문 형태인지) |
| S4 | 지자체·복지관 대행 등록 시 **위탁 근거**가 명확한가 (위탁자-수탁자 관계, 위탁 계약서 필수 기재사항) | 개인정보 보호법 제26조 | 대행 등록 플로우에 위탁 근거를 남기는 필드/문서가 있는지 확인 (자동화 어려움 — 운영 문서 존재 여부 체크) |

## 3. 개인정보처리방침 — PIPC 처리방침 작성지침

| # | 점검 항목 | 근거 | 검증 방법 |
|---|---|---|---|
| N1 | 처리방침에 수집 항목(위치정보 세션 단위, 장애 여부 등 민감정보)이 실제 구현과 **1:1로 일치**하는가 | PIPC 개인정보 처리방침 작성 가이드라인 | 처리방침 문서 vs 실제 DB 스키마/수집 필드 diff 확인 — 문서에 없는 필드를 수집하고 있지 않은지 |
| N2 | 위탁 사실(지자체/복지관 대행 등록)을 처리방침에 명시했는가 | 개인정보 보호법 제26조·PIPC 가이드라인 | 처리방침 텍스트 검토 |

## 4. 본선 준비 구간에서 실제로 도는 시점

점검은 **8/29 시연 환경 배포 직후**에 실행합니다 — 배포된 환경에서 확인해야 의미가 있고,
그 결과가 8/31 4대 지표 취합표의 **「위치정보 미수신 — 좌표 도달 지점 0건」** 칸에 그대로 들어갑니다.

- P2/S3: 로그·DB 자동 스캔 (시연 환경 대상)
- 테스트 하네스 위치: `apps/backend/tests/`(스캔 대상이 `backend_core` 도메인 로직이므로) 또는
  운영 스크립트라면 `scripts/`. 앱 경계(`backend_core`는 `api`를 모름) 규칙을 지키는 형태로 배치합니다.
- 미구현으로 남아 있는 것: **파기·동의 이력의 개인정보 없는 이벤트 저널**(기획서 v3에 설계만 존재).
  본선에서 물어볼 수 있는 항목이므로 "설계는 있고 예선 시점 미구현"이라고 그대로 답합니다.
