# 워킹 스켈레톤 점검 가이드 — 단계별로 따로 확인하기

관통 경로의 **각 단계가 혼자서도 제대로 도는지**를 확인하는 실습 문서입니다. 구조 설명은 [워킹_스켈레톤_설명.md](워킹_스켈레톤_설명.md), 결정 근거는 [ADR-0007](../adr/0007-walking-skeleton.md)에 있습니다. 여기서는 **명령 → 기대 출력 → 통과 기준 → 실패 시 의심 지점**만 다룹니다.

쓰는 때:

- 자기 이음매(스텁 → 실물)를 교체한 뒤 **다른 단계를 망가뜨리지 않았는지** 확인할 때
- 관통이 깨졌을 때 **어느 단계에서 깨졌는지** 이분 탐색할 때
- 데모/발표 전 전 구간 동작을 눈으로 훑을 때

> 아래 출력은 2026-07-28 기준 실제 실행 결과입니다. **토큰·시각·지연시간(ms)은 매번 달라집니다** — 비교할 대상은 값이 아니라 **형태와 등급**입니다.

`/health`는 **의존성을 확인하지 않습니다.** ai-engine이 죽어 있어도 backend `/health`는 ok입니다 — 의존성 상태를 liveness에 섞으면 오케스트레이터가 멀쩡한 프로세스를 재시작합니다. 즉 `/health` 200은 "떠 있다"는 뜻이지 "관통된다"는 뜻이 아니며, 관통 확인은 §7입니다.

**점검 방법은 3계층**이고, 무엇을 의심하느냐에 따라 골라 씁니다.

| 계층 | 방법 | 쓰는 때 |
|---|---|---|
| 도메인 함수 직접 호출 | `python -c "from backend_core… "` | 서버 없이 로직만 볼 때. 검색·가드레일처럼 **엔드포인트가 없는 단계**는 이 방법뿐 |
| 단일 서비스 HTTP | `curl localhost:8100/…` | 계약(요청/응답 형태·상태코드)을 볼 때 |
| 관통 HTTP | `curl localhost:8000/internal/alerts/dispatch` | 두 앱이 실제로 맞물리는지 볼 때 |

## 3. 매칭 · 단계 매핑

```bash
python -c "
from backend_core.ingest import demo_flood_warning
from backend_core.matching import match_residents, stage_for
from backend_core.registry import seed_registry
e, r = demo_flood_warning(), seed_registry()
print('matched:', [x.profile.user_id for x in match_residents(e, r)])
print('stage:', stage_for(e.level))
print('다른 행정동:', match_residents(e.model_copy(update={'affected_dong_codes': ['1111000000']}), r))"
```

```
matched: ['p001', 'p002']
stage: 2
다른 행정동: []
```

**통과 기준** — 시드 2명 매칭, 다른 행정동이면 0명. `stage_for()`는 `preliminary→1`, `advisory→2`, `warning→2`이며 **어떤 입력으로도 3이 나오면 안 됩니다.**

위험구역 판정은 별개 함수이고, **판단 불가를 `outside`로 낮추지 않는 것**이 핵심입니다.

```bash
python -c "
from backend_core.ingest import demo_flood_warning
from backend_core.matching import hazard_match
e = demo_flood_warning()
print(hazard_match(e, dong_code='1162064500'))   # inside
print(hazard_match(e, dong_code='1111000000'))   # outside
print(hazard_match(e, dong_code=None))           # unknown ← never 'outside'"
```

## 5. 대피소

```bash
python -c "
from backend_core.shelters import ShelterRepository, CachedShelterSource, UnavailableShelterSource
repo = ShelterRepository(UnavailableShelterSource(), CachedShelterSource.from_jsonl())
for ok in (False, True):
    r = repo.search(dong_code='1162064500', disaster_type='flood', hazard='inside', stairs_ok=ok, limit=2)
    print(f'stairs_ok={ok}', r.availability, [(s.name, s.distance_m, s.has_stairs) for s in r.items])"
```

```
stairs_ok=False cache_only [('관악구민종합체육관', 359, False), ('난곡중학교 강당', 648, False)]
stairs_ok=True  cache_only [('서원동주민센터 다목적실', 186, True), ('서원초등학교 체육관', 230, True)]
```

**통과 기준**

- 지하 대피소(fixture 6곳 중 2곳)가 **목록에 없어야** 합니다. 프론트가 거르는 게 아니라 서버가 제거합니다.
- `stairs_ok=False`면 계단 없는 곳이 **먼저**. 계단 있는 곳도 목록에 남지만 맨 위에는 오지 않습니다("가장 가까운 대피소" ≠ "가장 가까운 **이용 가능한** 대피소").
- `availability`가 `cache_only` — 실시간 소스 미연결 상태의 **정상 값**입니다. `ok`가 나오면 오히려 이상합니다.

`items: []`의 4가지 의미가 구분되는지도 확인합니다.

| 상황 | 재현 | `availability` |
|---|---|---|
| 정상 | 실시간 소스 연결 후 | `ok` |
| 후보 전부 위험 | 지하만 있는 행정동 | `all_excluded` |
| 캐시 폴백 | 지금 상태(기본) | `cache_only` |
| 데이터 없음 | 없는 행정동 코드 조회 | `upstream_unavailable` |

⚠️ 실시간 소스를 붙일 때 **실패를 빈 목록으로 반환하지 마세요.** 빈 목록은 "주변에 대피소가 없다"로 읽혀 사용자를 그 자리에 머물게 합니다. 예외를 던져야 캐시 폴백이 발동합니다.

## 6. 검색 (엔드포인트 없음 — 직접 호출만)

```bash
python -c "
from ai_engine.retrieval import FixtureRetriever, build_query, profile_tags
from ai_engine.models import RecipientContext
r = FixtureRetriever.from_jsonl()
p = RecipientContext(dongName='서원동', housing='banjiha', mobility='slow', stairsOk=False,
                     easyText=True, language='ko', livesAlone=True)
print('tags:', profile_tags(p))
for x in r.search(build_query('flood', p), disaster_type='flood', tags=profile_tags(p), top_k=3):
    print(f'  {x.score:.3f} {x.id} {x.text[:30]}...')
print('무관 질의:', r.search('주식 전망 알려줘', disaster_type='flood', tags=profile_tags(p), top_k=3))"
```

```
tags: ['banjiha', 'mobility_assisted', 'stairs', 'lives_alone']
  0.500 placeholder-heavy-rain-006 계단을 오르기 어려운 경우에는 경사로가 있는 대피 장소...
  0.439 placeholder-heavy-rain-001 반지하 주택, 지하 상가, 저지대에 있을 때는 물이 차...
  0.389 placeholder-heavy-rain-005 혼자 계신 어르신, 몸이 불편한 분은 이웃이나 가족에게...
무관 질의: []
```

**통과 기준**

- 프로필 태그가 붙은 문단이 상위로 올라옴(부스트가 동작).
- **무관 질의는 0건.** 여기서 무언가 회수되면 최소 어휘 중첩 문턱이 무너진 것이고, "근거 없으면 생성하지 않는다"가 뚫립니다.
- 같은 입력으로 두 번 돌려 **순서가 동일**해야 합니다(KPI 재현성).
- 재난유형은 하드 필터입니다: `disaster_type='flood'` 대신 다른 값을 넣으면 0건이어야 합니다.

> ⚠️ Chroma·임베딩으로 교체하면 `score` 체계가 통째로 바뀝니다. 절대값을 비교하지 말고 **순위와 회수 여부**로 판정하세요. 교체 후에는 위 "의역 질의" 케이스(§12)가 회수에 성공하는지가 핵심 확인 지점입니다.

## 7. 가드레일

```bash
python -c "
from ai_engine.guardrail import GuardrailContext, verify
from ai_engine.models import Passage
ctx = GuardrailContext.from_passages(
    [Passage(id='p1', title='t', text='물이 차오르기 전에 높은 곳으로 이동합니다.', score=1.0)], ())
print('접지 문장:', verify('물이 차오르기 전에 높은 곳으로 이동하세요.', ctx))
print('환각 문장:', verify('서울시가 지원금 50만원을 지급하니 신청하세요.', ctx))
print('지시 없음:', verify('물이 차오르기 전에 높은 곳으로 이동합니다', ctx))
print('가드레일 off:', verify('아무 문장', ctx, enabled=False))"
```

```
접지 문장: enabled=True  passed=True  violations=[]
환각 문장: enabled=True  passed=False violations=['unsupported_claim']
지시 없음: enabled=True  passed=False violations=['missing_action']
가드레일 off: enabled=False passed=False violations=[]
```

**통과 기준** — 네 줄 모두 위와 같아야 합니다. 특히 마지막 줄의 `passed=False`:

> ⚠️ **가드레일 off는 "통과"가 아닙니다.** 검증하지 않은 출력이 통과로 집계되면 환각 억제율의 대조군 수치가 오염됩니다. 여기서 `passed=True`가 나오면 제출 지표가 통째로 무의미해집니다.

프롬프트 쪽(1단)도 함께 봅니다 — 규칙 7개와 `<근거>` 블록이 실제로 조립되는지:

```bash
python -c "
from ai_engine.guardrail import build_prompt
from ai_engine.models import Passage
print(build_prompt('상황 문장', '반지하 거주, 계단 이용 어려움',
      [Passage(id='p1', title='[더미] 호우', text='높은 곳으로 이동합니다.', score=1.0)],
      facts=['안내할 대피소: 관악구민종합체육관 (직선거리 401m, 계단 없음)']))"
```

`[상황]` / `[질문]` / `[대상자 특성]` / `[확정 사실]` / `<근거>` 5개 블록이 **각각 분리**돼 있어야 합니다. 사용자 질문이 "확정된 상황"으로 섞이면 안 됩니다.


### 8-1. 안전하게 지시할 수 없는 조합 → 거절

```bash
python -c "
import json,urllib.request
c=json.load(open('/tmp/ctx.json')); c['context']['shelter']=None
r=urllib.request.urlopen(urllib.request.Request('http://localhost:8100/v1/generate',
  json.dumps(c).encode(),{'content-type':'application/json'}))
print(r.status, r.read().decode())"
```

```
200 {"message":null,"refusalReason":"unsafe","guardrailApplied":true}
```

**통과 기준** — 대피소 없음 + 계단 이용 불가 = 남는 선택지가 수직 대피뿐인데 그게 불가능한 사람. **200에 `message: null`** 이어야 합니다(에러 아님). 여기서 엔진이 무언가 문장을 만들어내면 그게 곧 위험한 지시입니다.

`stairsOk`만 `true`로 바꾸면 수직 대피 지시가 나옵니다:

```

```

### 8-2. 가드레일 on/off 델타 — **환각 억제율의 근거**

스텁 생성기는 근거에서만 문장을 만들어 환각을 내지 않으므로, 델타를 보려면 환각을 내는 생성기를 주입합니다.

```bash
python -c "
from ai_engine.generation import generate_message
from ai_engine.retrieval import FixtureRetriever
from ai_engine.models import *
class Hallucinating:
    def complete(self, prompt): return '서울시가 대피 지원금 50만원을 지급합니다. 지금 신청하세요.'
req = lambda g: GenerationRequest(eventId='X', guardrail=g, context=GenerationContext(
    issuedAt='2026-07-28T12:00:00Z', disaster=DisasterContext(type='flood', severity='warning'),
    recipient=RecipientContext(dongName='서원동', housing='banjiha', mobility='ok', stairsOk=True,
                               easyText=True, language='ko', livesAlone=False),
    shelter=ShelterInstruction(name='관악구민종합체육관', distanceM=401, hasStairs=False)))
r, g = FixtureRetriever.from_jsonl(), Hallucinating()
on, off = generate_message(req(True), r, g), generate_message(req(False), r, g)
print('on  →', on.message, on.refusal_reason)
print('off →', off.message.body if off.message else None)"
```

```
on  → None unsafe
```

## 10. 세션 열람 · 응답

```bash
T=<위 응답의 sessionToken>
curl -s -D- localhost:8000/v1/session/$T -o /tmp/s.json | grep -i "^HTTP\|cache-control"
```

```
HTTP/1.1 200 OK
cache-control: no-store
```

**통과 기준**

- `Cache-Control: no-store` — 이 응답에는 이름·주거형태·보호자 전화가 함께 들어 있습니다. 헤더가 없으면 **프라이버시 결함**입니다.
- `message.body`가 §9에서 발송된 문안과 **글자 단위로 동일**(슬롯 치환 계층 없음).
- **같은 토큰으로 다시 GET 해도 200** — 소비형 토큰이 아닙니다. 두 번째 호출이 410이면 링크 미리보기 한 번에 사용자가 알림을 잃습니다.
- `openedAt`은 **최초 1회만** 기록됩니다(재열람해도 값이 바뀌지 않아야 함).

```bash
curl -s -X POST localhost:8000/v1/session/$T/response \
  -H 'content-type: application/json' -d '{"response":"home"}'      # {"ok":true}
```

이 엔드포인트는 **좌표를 받지 않습니다.** 요청에 `lat`/`lng`를 넣으면 422가 나야 정상입니다.

## 14. 저하 경로 — 여기가 진짜 점검 대상

성공 경로는 한 번만 확인하면 되지만, **이 프로젝트에서 검증 가치가 높은 것은 실패했을 때의 동작**입니다.

### 14-1. ai-engine 정지 → `official_fallback`

ai-engine 터미널에서 **Ctrl-C** 로 중지한 뒤:

```bash
curl -s -X POST localhost:8000/internal/alerts/dispatch
# dispatched: 2 | modes: ['official_fallback', 'official_fallback'] | meanMs: 10.4

T2=<이 응답의 sessionToken>     # 엔진 정지 상태에서 새로 발송한 세션
curl -s localhost:8000/v1/session/$T2
# [세이버스] 서원동 호우경보
# 지금 계신 곳이 침수 위험 지역입니다. 물이 차오르기 전에 지상에 있는 안전한 곳으로 이동하세요.
# 움직이기 어려우면 119에 연락하세요.
# mode: official_fallback | sources: 0

curl -s -X POST localhost:8000/v1/chat -H 'content-type: application/json' \
  -d "{\"token\":\"$T2\",\"question\":\"지금 어떻게 해야 하나요?\"}"
# {"answer":null,"sources":[],"refusalReason":"no_evidence"}
```

**통과 기준**

- 발송은 **200 + 폴백 문구**. 500이 나오면 설계 위반입니다 — 재난 중에는 "완벽하지 않은 문안"보다 "아무것도 안 오는 것"이 나쁩니다.
- 폴백의 `sources`는 **빈 배열**. 근거에서 나오지 않은 문장에 인용을 붙이면 그게 근거 일치율이 잡아내려는 실패 그 자체입니다.
- 챗봇은 반대로 **침묵**(`answer: null`). 발송과 챗봇의 비대칭이 여기서 눈에 보여야 합니다.

> `pkill -f ai_engine.service:app` 로 죽이지 마세요 — 패턴이 실행 중인 셸 명령 자체와도 매칭돼 자기 셸을 죽입니다. Ctrl-C 또는 `pkill -f "uvicorn ai_engine"` 를 쓰세요.

### 14-2. 세션 만료 → 410

TTL을 짧게 준 backend를 따로 띄워 확인합니다.

```bash
SAVERS_SESSION_TTL_S=2 python -m uvicorn api.main:app --port 8000
T3=$(curl -s -X POST localhost:8000/internal/alerts/dispatch | …)
curl -s -w " <- %{http_code}\n" localhost:8000/v1/session/$T3   # 200
sleep 3
curl -s -w " <- %{http_code}\n" localhost:8000/v1/session/$T3
# {"code":"SESSION_EXPIRED","message":"만료된 링크입니다."} <- 410
```

```bash
curl -s -w " <- %{http_code}\n" localhost:8000/v1/session/s_nope
# {"code":"SESSION_NOT_FOUND","message":"토큰을 찾을 수 없습니다."} <- 404
```

**통과 기준** — **404와 410이 구분**되어야 합니다. 프론트가 "잘못된 링크"와 "지난 알림입니다"를 다르게 보여주기 때문이며, 에러 본문은 `{code, message}` 계약 형태입니다(FastAPI 기본 `{"detail": …}`가 나오면 핸들러가 빠진 것).

> **이 절차는 이제 자동화돼 있습니다** — [e2e/tests/test_session_expiry.py](../../e2e/tests/test_session_expiry.py)가
> 계약 6경로(세션 2 · 대피소 · 챗봇 · 보호자 2) 전부를 검사하고,
> 같은 스택에서 없는 토큰이 여전히 404인지도 함께 봅니다(#67).
> 위 수동 절차는 로컬에서 눈으로 볼 때 여전히 유효하니 그대로 두세요.
>
> 자동화 쪽은 `SAVERS_SESSION_TTL_S=2` + `sleep 3` 대신 **`=0` + 대기 없음**을 씁니다.
> `expires_at`이 발송 루프 진입 시각 기준이라 짧은 양수 TTL은 발송 소요시간에 먹히는데,
> 0이면 그 경쟁이 사라져 결정론적입니다.
> ⚠️ **`=0`은 CI 러너 전용입니다** — VM의 `infra/.env`에 넣지 마세요.
> 발송은 건강한 200을 돌려주면서 모든 딥링크가 즉시 410이 되고,
> 배포 검증 어느 항목도 그걸 잡지 못합니다([배포_절차.md](배포_절차.md) §3 경고).

### 14-3. 저하 경로 점검표

| 상황 | 재현 방법 | 기대 |
|---|---|---|
| 엔진 정지 | Ctrl-C | 200 + `official_fallback` |
| 엔진 타임아웃 | `SAVERS_AI_ENGINE_TIMEOUT_S=0.001` | 동일 |
| 엔진 근거 없음 | 코퍼스 비우기 / 무관 질의 | `message: null` → 폴백 |
| 대피소 실시간 장애 | 기본 상태 | `cache_only` + `dataAsOf` |
| 대피소 데이터 없음 | 없는 행정동 코드 | `upstream_unavailable` |
| 기기 없음 | 시드에서 devices 제거 | `skippedNoDevice`에 집계, 세션은 발급 |
| 세션 만료 | `SAVERS_SESSION_TTL_S=2` | 410 |
| 프로세스 재시작 | backend 재기동 | 기존 토큰 전부 404 (인메모리 — 알려진 한계) |

```bash
cd apps/ai-engine && python -m pytest -k "guardrail or refus" -v
```

관통 시나리오(HTTP only, 서비스 기동 필요):

```bash
SAVERS_E2E_BASE_URL=http://localhost:8000 python -m pytest e2e -v
```

환경변수가 없으면 **전부 skip** 됩니다(하네스만 있고 대상이 없는 상태를 초록으로 유지하는 설계). 즉 "skip 0건 통과"는 통과가 아니라 **미실행**입니다 — 반드시 실행 건수를 확인하세요.

## 17. 자주 걸리는 것

| 증상 | 원인 / 해결 |
|---|---|
| `ModuleNotFoundError: api` | 루트에서 editable 설치 필요. `pip install .`(루트 패키지)은 잘못된 명령 |
| `from src.…` import 오류 | src 레이아웃이라 `src.` 접두어는 런타임에 깨짐. 린트가 못 잡음 |
| mypy/pytest가 설정을 무시 | cwd가 앱 디렉토리가 아님 |
| 코퍼스를 고쳤는데 반영 안 됨 | `get_retriever()`가 `lru_cache` — **ai-engine 재시작** 필요 |
| 시드/설정을 고쳤는데 반영 안 됨 | `api.deps`의 provider들도 `lru_cache` — **backend 재시작** 필요 |
| 발송 후 토큰이 갑자기 404 | 프로세스 재시작(인메모리 세션). 재발송해서 새 토큰 사용 |
| `Address already in use` | 이전 uvicorn 잔존. `pgrep -af uvicorn` 확인 후 종료 |
| 전부 `official_fallback` | ai-engine 미기동 또는 `SAVERS_AI_ENGINE_URL` 불일치 |

## 18. 점검 결과로 남길 것

데모·제출 준비에서 의미 있는 기록은 **값 하나**가 아니라 **분포와 등급**입니다.

- `POST /internal/alerts/dispatch`의 `meanLatencyMs` / `p95LatencyMs` — 반복 실행하여 100회 분포로. ⚠️ 지금 값은 **스텁 기준**이라 HyperCLOVA X·FCM 실호출 뒤 반드시 재측정해야 합니다.
- `messageMode` 분포(`grounded` vs `official_fallback`) — 폴백 비율이 곧 생성 실패율입니다.
- 가드레일 on/off 각각의 위반 유형 분포 — 환각 억제율의 원자료.
- `availability` 분포 — `cache_only` 비율이 대피소 소스 안정성 지표입니다.
- 챗봇 `refusalReason: no_evidence` 비율 — 검색 재현율의 대용 지표.

> ⚠️ **근거 일치율은 지금 측정하지 마세요.** 번들 코퍼스가 `[더미]`라, 지금 재면 "더미 텍스트와의 일치율"이 나옵니다. 실제 국민행동요령 원문·Chroma 인덱스로 교체된 뒤가 측정 시점입니다.
