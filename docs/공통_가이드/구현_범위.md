# 세이버스(SAVERS) 구현 범위 분석 — 직접 구현 vs 외부 모듈 대체

4개 모듈 + 인프라/평가 영역별로, 반드시 직접 구현해야 하는 부분과 외부 API·오픈소스·관리형 서비스로 대체 가능한 부분을 구분한 문서입니다.

## 1. 실시간 위치 매칭 엔진

| 기능 | 직접 구현 필요 | 외부 모듈로 대체 가능 |
|---|---|---|
| 좌표 → 행정동 변환 | — | 카카오맵 역지오코딩 API (계획대로 사용) |
| 현재 위치 확보 | — | 브라우저 Geolocation API (플랫폼 표준) |
| 위험구역 폴리곤 판정(point-in-polygon) | 위험구역 데이터 자체의 수집·정제 | 기하 연산 로직은 Shapely로 대체 (Python 백엔드 표준, 대량 판정 시 GeoPandas·STRtree 공간 인덱스 활용, 직접 알고리즘 구현 불필요) |
| 행정동 코드 매핑 테이블 | 사내 스키마로 적재하는 파이프라인 | 원본 데이터는 공공데이터포털의 법정동/행정동 코드표 활용 (자체 제작 불필요) |
| 대피소까지 도보 경로·거리 | 최종 판단 로직(거리 임계값 등 비즈니스 규칙) | 실제 경로 계산은 카카오맵 길찾기 API로 대체 가능 (직선거리만 필요하면 하버사인 공식은 직접 구현) |
| **등록 사용자 ↔ 실시간 위치 매칭 로직, 세션 단위 미저장 처리** | **반드시 직접 구현** (서비스 핵심 로직, 프라이버시 요구사항이 걸려 있어 대체 불가) | — |

| **재난유형+취약계층 프로필 조건부 검색(메타데이터 필터+시맨틱 검색 결합)** | **직접 구현** — 세이버스 고유 비즈니스 로직 | Chroma의 메타데이터 필터 기능은 활용 가능하나 조합 로직 자체는 직접 구현 |

| 기능 | 직접 구현 필요 | 외부 모듈로 대체 가능 |

| 오케스트레이션 | — | LangGraph (상태·분기·가드레일 폴백이 있는 에이전틱 흐름의 실무 표준, LangChain 생태계) |
| 다국어 번역 | — | 파파고 API, Google Cloud Translation 등 |
| TTS(음성 변환) | — | 클로바보이스, Google TTS 등 |
| 근거 일치·환각 자동 채점 인프라 | 세이버스 지표 정의에 맞춘 채점 스크립트 | RAGAS, TruLens 같은 오픈소스 RAG 평가 프레임워크를 뼈대로 활용해 구현 부담 축소 가능 |
| **가드레일 프롬프트(근거 인용 강제, 이탈 시 폴백 규칙)** | **반드시 직접 설계** — 프로젝트의 핵심 차별화 요소이자 안전장치, 외부 모듈로 대체 불가 | — |
| **페르소나별 메시지 톤·쉬운말 치환 규칙** | 직접 설계 (국립국어원 쉬운 공공언어 용어집은 참고 데이터로만 활용 가능) | 용어 사전 자체는 공개 자료 활용 가능하나, 적용 로직은 직접 구현 |

## 4. 무설치 사용자 터미널

| 기능 | 직접 구현 필요 | 외부 모듈로 대체 가능 |
|---|---|---|
| 알림톡 발송 인프라 | 발신 프로필·템플릿 신청/운영 | 카카오 알림톡 API 발송 대행사 — **솔라피(Solapi)** 또는 **알리고(Aligo)** 후보.<br>솔라피: 알림톡 13원(VAT 별도)·SMS 18원, Python SDK 통합 편의 + 대량 발송 시 최대 ~57% 볼륨 할인.<br>알리고: 알림톡 약 7.5원·SMS 8.4원으로 저볼륨 단계에서 저렴(통합은 상대적으로 수작업).<br>**예선·데모(저볼륨)는 알리고, 대량 발송 전환 시 솔라피 할인구간 재비교** (알림톡 실패 시 SMS 폴백 단가까지 합산 비교 필요) |
| PWA 서비스워커/오프라인 캐싱 | — | Workbox 등으로 상당 부분 대체 가능 |
| 웹푸시 인프라 | — | Firebase Cloud Messaging(FCM) 등 |
| 챗봇 UI 컴포넌트 | — | 오픈소스 채팅 UI 라이브러리로 뼈대 구성 가능 |
| **Interactive Care 대화 흐름/의도 분기 로직** | **직접 구현** — 세이버스 고유 시나리오 | — |
| **접근성 통합(쉬운 글 표시 + 음성 재생 + 원문 대조 UI)** | 직접 통합 작업 필요 | 개별 요소(TTS, 번역)는 외부 API지만 조합 UX는 직접 구현 |

### 프론트엔드 형태 — PWA(웹) 확정, 네이티브/하이브리드 제외

프론트엔드 배포 형태는 취향이 아니라 **하드 제약에서 강제**됩니다. 후보와 판단은 다음과 같습니다.

| 형태 | 채택 | 판단 근거 |
|---|---|---|
| **PWA(웹)** | **채택** | 모듈명 "무설치 사용자 터미널"·"당사자 설치 부담 없음" 원칙과 정합. 알림톡 딥링크 → 브라우저 진입 → 위치 1회 확인 흐름이 웹 권한 모델과 일치 |
| 네이티브 앱 | 제외 | 스토어 검색·설치·로그인 필요 → **무설치 원칙 위반**. 알림톡 링크 진입 시 앱 미설치면 스토어로 튕겨 진입 자체가 깨짐.<br>스토어 심사가 5주 일정 리스크. 유일한 이점(백그라운드 위치)은 "상시 추적 금지" 원칙상 **우리가 쓰면 안 되는 기능**이라 메리트 0 |
| 하이브리드 앱 | 제외 | 네이티브의 이점이 없는 상태에서 개발 난이도만 상승 |

- **위치 권한**: 웹 Geolocation(HTTPS+제스처 1회 프롬프트)이 "알림 열 때 1회·세션 미저장" 설계와 정합. 권한 거부/실패 시 **등록 행정동 기반 매칭으로 degrade**(단일 실패점 아님).
- **알림톡은 프론트 통합 대상이 아님**: 발송은 백엔드가 대행사(솔라피/알리고) API 호출. 프론트는 알림톡에 담긴 **딥링크로 진입하는 랜딩**(세션 토큰 수신 → 개인화 페이지 렌더)일 뿐.
- **웹푸시 iOS 한계 대응**(확실한 사실): iOS Safari는 홈 화면 추가(A2HS) PWA에서만 웹푸시 가능. 그러나 **알림톡을 1차 푸시 채널, 웹푸시를 보조 fallback**으로 두는 구조라 iOS 한계를 우회.
- **권장 스택**: React + Vite + `vite-plugin-pwa`(Workbox 기반 SW/오프라인 캐싱). 별도 의사결정 기록은 ADR로 유지(→ `docs/adr/0004-pwa-over-native.md`).

## 5. 인프라/운영

| 기능 | 직접 구현 필요 | 외부 모듈로 대체 가능 |
|---|---|---|
| 서버 이중화, 오토스케일링 | — | **예선/데모는 단일 VM(서울 리전, docker-compose)으로 운영** — 관리형 이중화(ALB·ASG·RDS Multi-AZ)는 확장 시로 유보(→ [ADR-0003](../adr/0003-single-vm-seoul.md)) |
| 일반 로깅/모니터링 | — | CloudWatch, 또는 Datadog류 APM |
| **종단 지연시간 계측(API 수신 → 알림 발송)** | 세이버스 고유 파이프라인 단계에만 커스텀 스팬·속성(재난유형, 취약계층 프로필 등)을 추가하는 계측 코드 | **OpenTelemetry 분산 트레이싱으로 종단 지연·p95 계측**(스팬 연결로 "API 수신 → 발송" 구간 자동 측정), 집계·시각화는 OTel 백엔드(Grafana Tempo·Jaeger 등) 활용 — 타임스탬프 로깅을 처음부터 직접 구현할 필요는 없음 |
| **오프라인 예비모드(사전 캐시 대피소·행동요령 전환 로직)** | **직접 구현** — 서비스 고유 장애 대응 정책 | — |

> **인프라 기준선: 서울 리전 단일 CPU VM + docker-compose** (→ [ADR-0003](../adr/0003-single-vm-seoul.md)). 생성 모델(HyperCLOVA X)과 임베딩을 외부 API로 사용하는 설계를 유지하므로 **GPU 인스턴스는 불필요**하고, 예선/데모 단계에서는 관리형 이중화 대신 단일 VM에 전체 스택을 올려 운영합니다. GPU는 오픈 LLM 자체 호스팅으로, 이중화는 트래픽 확장 시점에만 재검토 대상입니다(현재는 아님).

## 정리

**대체 불가·직접 구현이 필수인 부분** (= 팀의 실제 차별화·핵심 역량이 들어가야 할 지점):
- 위치 매칭 + 세션 단위 미저장 처리
- RAG 청킹 전략 + 프로필 조건부 검색 로직
- 가드레일 프롬프트 및 근거 강제 로직
- Interactive Care 챗봇 시나리오
- 오프라인 예비모드 (종단 지연시간 계측은 OpenTelemetry로 대체하고, 세이버스 고유 스팬·속성만 직접 추가)

**외부 모듈로 상당 부분 대체 가능한 부분** (= 직접 만들 필요 없이 통합만 하면 되는 지점):
- 벡터 DB, 임베딩, LLM, 번역, TTS, 알림 발송, 푸시 인프라, 문서 파싱, PWA 캐싱, 클라우드 이중화

## 업계 관점

5주라는 일정을 감안하면, "대체 가능" 항목에 개발 리소스를 쓰지 않고 기성 라이브러리·API로 빠르게 채운 뒤, "직접 구현 필수" 항목(가드레일, 위치 매칭, 청킹 전략, 오프라인 예비모드)에 팀 역량을 집중하는 것이 [리스크.md](리스크.md)에서 지적한 일정 리스크(⑧)를 줄이는 실질적 방법입니다.
