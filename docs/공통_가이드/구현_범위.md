# 세이버스(SAVERS) 구현 범위 분석 — 직접 구현 vs 외부 모듈 대체

핵심 기술 셋 + 기반·전달·인프라 영역별로,
반드시 직접 구현해야 하는 부분과 외부 API·오픈소스·관리형 서비스로 대체 가능한 부분을 구분한 문서입니다.
기준은 제출 기획서 v3(2026-08-10)이며, 본선 준비 구간(**8/22 ~ 8/29 · 인당 52시간**)의 범위 결정도 함께 담습니다.

## 1. 기반 · 실시간 위치 매칭

| 기능 | 직접 구현 필요 | 외부 모듈로 대체 가능 |
|---|---|---|
| 좌표 → 행정동 변환 | — | 카카오맵 역지오코딩 API (계획대로 사용) |
| 현재 위치 확보 | — | 브라우저 Geolocation API (플랫폼 표준) |
| 위험구역 폴리곤 판정(point-in-polygon) | 위험구역 데이터 자체의 수집·정제 | 기하 연산 로직은 Shapely로 대체 (Python 백엔드 표준, 대량 판정 시 GeoPandas·STRtree 공간 인덱스 활용, 직접 알고리즘 구현 불필요) |
| 행정동 코드 매핑 테이블 | 사내 스키마로 적재하는 파이프라인 | 원본 데이터는 공공데이터포털의 법정동/행정동 코드표 활용 (자체 제작 불필요) |
| 대피소까지 도보 경로·거리 | 최종 판단 로직(거리 임계값 등 비즈니스 규칙) | 실제 경로 계산은 카카오맵 길찾기 API로 대체 가능 (직선거리만 필요하면 하버사인 공식은 직접 구현) |
| **등록 사용자 ↔ 실시간 위치 매칭 로직, 세션 단위 미저장 처리** | **반드시 직접 구현** (서비스 핵심 로직, 프라이버시 요구사항이 걸려 있어 대체 불가) | — |

## 2. 핵심기술① 대피소 부합도 모델

| 기능 | 직접 구현 필요 | 외부 모듈로 대체 가능 |
|---|---|---|
| 학습 알고리즘 | — | LightGBM (그래디언트 부스팅 그대로 사용) |
| 기여도 설명 | — | SHAP 라이브러리 |
| 공간 블록 교차검증 | 자치구 단위 GroupKFold 분할 정의 | scikit-learn `GroupKFold`로 연산 자체는 대체 |
| 원천 데이터 | 좌표계 정합·결측 처리 파이프라인 | 서울 열린데이터광장(수해대피소·침수예상도·침수흔적도), 국토지리정보원 DEM, 건축물대장 |
| **라벨-피처 분리 설계** | **반드시 직접 설계** — 서울 전용 데이터는 정답·검증에만, 입력은 전국 공통 13개 피처만. 이 분리가 깨지면 "목록 없는 16개 시·도 적용" 주장이 무너짐 | — |
| **spy 기법 PU 구조** | **직접 구현** — 미분류에 정답 일부를 위장해 섞고, 그보다 정답 같지 않은 것만 신뢰 negative로 학습 | 참고 문헌은 있으나 이 데이터에 맞춘 구현은 직접 |
| **대피 여유고 산출** | **직접 구현** — 출입구 표고에서 주변 도로 최저점 표고를 뺀 값. 공개 데이터에 없는 파생 피처 | — |

**본선 범위 결정**: 검증은 **3겹**(공간블록 CV · 비학교 recall@top-20% · 침수예상도 대비 lift)이며,
④ 문자열·표준필드·모델 3자 비교는 생략합니다.
16개 시·도 적용 지도도 만들지 않고 발표 서술로만 다룹니다.

## 3. 핵심기술② 침수 회피 경로

| 기능 | 직접 구현 필요 | 외부 모듈로 대체 가능 |
|---|---|---|
| 도로망 데이터 | — | OpenStreetMap |
| 라우팅 엔진 | — | **OSMnx + networkx** (그래프 구축·최단경로 탐색). [ADR-0017](../adr/0017-route-engine-osmnx-networkx.md)(Accepted, 2026-08-28 Backend 확인)이 R0 ~ R3 등급·R2/R3 제거·「경로 없음」 재선정을 본선 구현 규칙으로 확정했고, [PR #220](https://github.com/team-savers/savers-project/pull/220)(OPEN, main 미병합)에 NetworkX 최단경로 core가 구현돼 있습니다. 기획서는 OSRM으로 적었으나 확정 A안은 OSMnx+networkx이며, OSRM 전환은 본선 이후 → [정정 항목](../공유_문서/서비스_기획서.md) |
| **링크별 침수 위험 등급 R0 ~ R3 부여** | **직접 구현** — 침수예상도·지하차도·하천변을 링크에 매핑하는 규칙. ⚠️ 실제 등급 데이터·RiskAnnotator 연동은 미완료([PR #220](https://github.com/team-savers/savers-project/pull/220)은 외부 주입 경계만 마련) | — |
| **통과 가능 여부를 먼저 정하는 필터** | **직접 구현** — R2(침수심 0.5 ~ 1.0m)·R3 제거 후 최단. "최단이 아니라 지나갈 수 있는 길"이라는 주장의 실체. [PR #220](https://github.com/team-savers/savers-project/pull/220)(OPEN, main 미병합)에 core 구현됨(R2/R3 제거, `found`/`no_route`/`engine_error` 결과 구분) | — |
| **「경로 없음」 → 대피소 재선정 폴백** | **직접 구현** — 서비스 고유 안전 동작이자 실패 모드 시연 케이스. [PR #220](https://github.com/team-savers/savers-project/pull/220)(OPEN, main 미병합)에 `no_route`일 때만 다음 후보를 재선정하는 core 구현됨 | — |

**계획**: 데모 행정동 **1곳**으로 좁히고, 등급은 **사전 계산한 정적 표**로 붙일 계획이었습니다.
실시간 등급 계산까지 가면 52시간 안에 끝나지 않는다는 판단이었습니다.

**구현 현황(사실, 2026-08-29 갱신)**: [ADR-0017](../adr/0017-route-engine-osmnx-networkx.md)이
이미 본선 구현 규칙을 확정했으므로, 남은 것은 범위 판정이 아니라 아래 세 층의 진행 상태입니다.

- **실제 링크 위험 등급 데이터·RiskAnnotator 연동**: 미완료
- **R2/R3 필터·`no_route` 재선정 core**: [PR #220](https://github.com/team-savers/savers-project/pull/220)에서
  구현됨 — 현재 OPEN이며 main에는 아직 미병합
- **실제 데이터, OSM node mapping, shelter adapter, pipeline/API 연결, 실기기 시연**: 미완료

이 표는 "직접 구현 필요/외부 대체 가능"만 판정하며, 위 세 층의 진행 상태는 각주로만 답니다.
후속 진행은 [후속_과제.md](후속_과제.md) P0 #20 참조 (머지 과정에서 #18에서 번호 재부여.
같은 항목이 인용하는 케이스 4 대본은 `docs/cctv-scope-removal` 브랜치에 머지된
[PR #213](https://github.com/team-savers/savers-project/pull/213)에만 있고, main 반영은
아직 OPEN인 [PR #212](https://github.com/team-savers/savers-project/pull/212)에 달려 있어
이 브랜치에서는 링크가 깨져 있습니다 — #20 본문의 안내 참고).

## 4. 핵심기술③ 보호자 상황 확인 RAG

| 기능 | 직접 구현 필요 | 외부 모듈로 대체 가능 |
|---|---|---|
| 생성 모델 자체 | — | HyperCLOVA X API |
| 채팅 UI 뼈대 | — | 기존 `ChatDock` 컴포넌트 재사용 |
| **이벤트 로그 스키마·저장·조회** | **직접 구현** — 기존 `SessionStore`에 `events` 배열을 얹는 형태. 인덱스·페이지네이션 없음(한 세션 상한 수십 건) | — |
| **생성부(추천 3질문)** | **직접 구현** — 세션 로그 전량을 컨텍스트로. **벡터 검색 없음.** 「안전합니다」·「괜찮습니다」는 금지어 | — |
| **로그 1:1 대조 검증기** | **반드시 직접 구현** — 문장을 주장 단위로 쪼개 로그와 대조, 미대응 1건이면 문장 전체 차단. 「기타」 폴백 판정도 겸함 | — |
| **폐루프 5단계 오케스트레이션** | **직접 구현** — 30분 무응답 시 관측으로 재진입. 「에이전틱」 주장의 유일한 증거 | — |

**범위 밖**: 세션을 넘는 시계열 질의(「평소에도 이랬나요」)는 인덱싱이 필요해 제외하고
「확인할 수 없습니다」로 폴백합니다.

> **국민행동요령 코퍼스 RAG**(청킹·Chroma 인덱싱·조건부 검색·가드레일 프롬프트)는
> 예선 구간의 산출물로 `apps/ai-engine`에 그대로 남아 있습니다.
> 벡터 저장/검색은 Chroma, 임베딩은 HyperCLOVA X 또는 공개 한국어 모델로 대체하고,
> 직접 구현 대상은 **청킹 전략**과 **가드레일 프롬프트**였습니다.
> 보호자 RAG와는 검색 대상도 방식도 다르므로 **둘을 섞지 마세요.**

## 5. 무설치 사용자 터미널

| 기능 | 직접 구현 필요 | 외부 모듈로 대체 가능 |
|---|---|---|
| 웹푸시 인프라 | 발송 트리거·토큰 관리 | Firebase Cloud Messaging(FCM) |
| PWA 서비스워커/오프라인 캐싱 | — | Workbox 등으로 상당 부분 대체 가능 |
| 지도 렌더링 | 부합도·경로 오버레이 | 기존 `ShelterMap` 컴포넌트 확장 |
| TTS(음성 변환) | — | 클로바보이스, Google TTS 등 |
| 다국어 번역 | — | 파파고 API, Google Cloud Translation 등 |
| **행동 권고 3단계 신호등** | **직접 구현** — 특보 등급을 상황 주시/대피 준비/즉시 대피로 바꾸는 매핑이 세이버스 고유 판단 | — |
| **SHAP 기여도 표시** | **직접 구현** — 대표 대피소 3곳 **고정 카드**(점수 + 기여도 상위 3개). 조건부(P2), 컷오프 8/28 저녁. 지도 클릭 인터랙션은 본선 이후 | SHAP 값 계산 자체는 라이브러리 |
| **모르는 것을 숨기지 않는 표기** | **직접 설계** — 기준 시각 표기, 「등록하신 동 기준」·「판정 불가」·「경로 없음」 | — |

**본선 범위 결정**: 1차 구현 범위는 **Android 무설치 웹푸시**이고,
iOS는 홈 화면 추가(A2HS)를 거쳐야 웹푸시가 열리므로 반응이 좋으면 추가 공수를 투입합니다.
목업 비주얼 통일(`tokens.ts`)과 외국인 근로자 다국어 데모는 압축으로 잘라냈고,
페르소나는 **반지하 고령자 1인**으로 좁혔습니다.
신호등은 색·라벨·전환만 구현하고 애니메이션은 넣지 않습니다.

### 프론트엔드 형태 — PWA(웹) 확정, 네이티브/하이브리드 제외

프론트엔드 배포 형태는 취향이 아니라 **하드 제약에서 강제**됩니다. 후보와 판단은 다음과 같습니다.

| 형태 | 채택 | 판단 근거 |
|---|---|---|
| **PWA(웹)** | **채택** | "무설치 사용자 터미널"·"당사자 설치 부담 없음" 원칙과 정합. 웹푸시 링크 → 브라우저 진입 → 위치 1회 확인 흐름이 웹 권한 모델과 일치 |
| 네이티브 앱 | 제외 | 스토어 검색·설치·로그인 필요 → **무설치 원칙 위반**. 링크 진입 시 앱 미설치면 스토어로 튕겨 진입 자체가 깨짐.<br>스토어 심사가 단기 일정 리스크. 유일한 이점(백그라운드 위치)은 "상시 추적 금지" 원칙상 **우리가 쓰면 안 되는 기능**이라 메리트 0 |
| 하이브리드 앱 | 제외 | 네이티브의 이점이 없는 상태에서 개발 난이도만 상승 |

- **위치 권한**: 웹 Geolocation(HTTPS+제스처 1회 프롬프트)이 "알림 열 때 1회·세션 미저장" 설계와 정합.
  「밖이에요」 분기는 `POST /v1/shelters/search`로 좌표를 **받되, 그 요청 안에서만 쓰고 저장·로깅하지 않습니다**
  (클라이언트 이관으로 엔드포인트를 없애는 안은 본선 창구 부족으로 기각 — [ADR-0011](../adr/0011-m3-no-storage-not-no-receipt.md), 승인).
  권한 거부/실패 시 **등록 행정동 기반 매칭으로 degrade**(단일 실패점 아님).
- **채널은 웹푸시 단일**입니다(→ [ADR-0005](../adr/0005-webpush-primary-channel.md)).
  문자 링크는 발신자를 위조할 수 있지만 웹푸시는 권한을 준 도메인에서만 발송되므로,
  「링크가 위험해 보여 누르지 않을 것 같다」는 설문 지적에 대한 해법이기도 합니다.
- **웹푸시 iOS 한계 대응**(확실한 사실): iOS Safari는 홈 화면 추가(A2HS) PWA에서만 웹푸시가 가능합니다.
  **1차 구현 범위를 Android로 좁히고**, 시연 환경은 안드로이드·데스크톱 크롬으로 고정합니다.
- **권장 스택**: React + Vite + `vite-plugin-pwa`(Workbox 기반 SW/오프라인 캐싱). 별도 의사결정 기록은 ADR로 유지(→ `docs/adr/0004-pwa-over-native.md`).

## 6. 인프라/운영

| 기능 | 직접 구현 필요 | 외부 모듈로 대체 가능 |
|---|---|---|
| 서버 이중화, 오토스케일링 | — | **예선/데모는 단일 VM(서울 리전, docker-compose)으로 운영** — 관리형 이중화(ALB·ASG·RDS Multi-AZ)는 확장 시로 유보(→ [ADR-0003](../adr/0003-single-vm-seoul.md)) |
| 일반 로깅/모니터링 | — | CloudWatch, 또는 Datadog류 APM |
| **종단 지연시간 계측(API 수신 → 알림 발송)** | 세이버스 고유 파이프라인 단계에만 커스텀 스팬·속성(재난유형, 취약계층 프로필 등)을 추가하는 계측 코드 | **OpenTelemetry 분산 트레이싱으로 종단 지연·p95 계측**(스팬 연결로 "API 수신 → 발송" 구간 자동 측정), 집계·시각화는 OTel 백엔드(Grafana Tempo·Jaeger 등) 활용 — 타임스탬프 로깅을 처음부터 직접 구현할 필요는 없음 |
| **오프라인 예비모드(사전 캐시 대피소·행동요령 전환 로직)** | **직접 구현** — 서비스 고유 장애 대응 정책 | 특보 API 캐시 자체는 Redis로 대체 |

> **인프라 기준선: 서울 리전 단일 CPU VM + docker-compose** (→ [ADR-0003](../adr/0003-single-vm-seoul.md)). 생성 모델(HyperCLOVA X)과 임베딩을 외부 API로 사용하는 설계를 유지하므로 **GPU 인스턴스는 불필요**하고, 예선/데모 단계에서는 관리형 이중화 대신 단일 VM에 전체 스택을 올려 운영합니다. GPU는 오픈 LLM 자체 호스팅으로, 이중화는 트래픽 확장 시점에만 재검토 대상입니다(현재는 아님).

## 정리

**대체 불가·직접 구현이 필수인 부분** (= 팀의 실제 차별화·핵심 역량이 들어가야 할 지점):
- 부합도 모델의 **라벨-피처 분리**와 spy 기법 PU 구조, 대피 여유고 파생 피처
- 링크별 침수 위험 등급 부여와 **통과 가능 여부를 먼저 정하는** 경로 필터, 「경로 없음」 재선정
  — [ADR-0017](../adr/0017-route-engine-osmnx-networkx.md)(Accepted)이 본선 구현 규칙으로 확정.
  R2/R3 필터·`no_route` 재선정 core는 [PR #220](https://github.com/team-savers/savers-project/pull/220)에서
  구현됨(OPEN, main 미병합); 실제 위험 등급 데이터·pipeline/API 연결·실기기 시연은
  미완료(3절 표 참조)
- 이벤트 로그 스키마와 **로그 1:1 대조 검증기**, 폐루프 5단계 오케스트레이션
- 위치 매칭 + **좌표를 받지 않는** 클라이언트 처리 구조
- 행동 권고 3단계 신호등 매핑과 「모르는 것을 숨기지 않는」 표기 규칙
- 가드레일 프롬프트 및 근거 강제 로직
- 오프라인 예비모드 (종단 지연시간 계측은 OpenTelemetry로 대체하고, 세이버스 고유 스팬·속성만 직접 추가)

**외부 모듈로 상당 부분 대체 가능한 부분** (= 직접 만들 필요 없이 통합만 하면 되는 지점):
- LightGBM·SHAP·GroupKFold, OSM·OSMnx·networkx, 벡터 DB, 임베딩, LLM, 번역, TTS,
  푸시 인프라(FCM), 문서 파싱, PWA 캐싱, Redis 캐시, 클라우드 이중화
