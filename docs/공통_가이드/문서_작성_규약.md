# 문서 작성 규약

문서를 **어떤 문체와 어떤 문자로 쓰는가**에 대한 규약입니다.
무엇을 어디에 두는가(폴더 배치, 한글과 영어 명명)의 정본은
[AGENTS.md](../../AGENTS.md) 의 `Naming convention` 절이며 여기에 복제하지 않습니다.

| 목적 | 문서 |
|---|---|
| 폴더 배치, 한글과 영어 명명 | [AGENTS.md](../../AGENTS.md) `Naming convention` |
| 커밋되는 `.md` 의 줄바꿈 | [AGENTS.md](../../AGENTS.md) `Markdown line wrapping` |
| **문체와 문자** | 이 문서 |
| 리뷰 코멘트 작성법 | [코드_리뷰_가이드.md](코드_리뷰_가이드.md) |
| 팀 메신저에 보낼 텍스트 | [메신저_규약.md](메신저_규약.md) |

이 문서는 3절(문자)의 적용 대상이 아니지만 스스로 지켜 쓰여 있습니다.
규칙을 어긴 문서가 규칙을 설명하면 아무도 믿지 않기 때문입니다.

## 1. 적용 범위

문체(2절)와 문자(3절)는 적용 범위가 다르므로 따로 표기합니다.

| 문서 | 문체 | 문자 | 왜 |
|---|---|---|---|
| `docs/adr/` | 평서형 | 예 | 확정의 유일한 출처이고 저장소 밖 문서가 인용합니다. 기존 9건이 평서형이라 문체는 현행을 유지합니다 |
| `docs/공유_문서/` | 경어체 | 예 | 인터뷰 결과와 회의 결과가 제출 서식(참가신청서, 기획서)의 원문이 됩니다 |
| `docs/공통_가이드/` | 경어체 | 아니오 | 팀원이 가장 자주 읽습니다. 경고 아이콘이 위험 항목의 앵커로 실제로 쓰입니다 |
| `docs/역할_가이드/` `docs/역할_일정/` | 경어체 | 아니오 | 역할 정의와 팀 내부 진행 추적입니다. 저장소 밖으로 나가지 않습니다 |
| `docs/pr-checklist.md` | 경어체 | 아니오 | 절차 문서이고 아이콘이 단계와 경고의 구분에 쓰입니다 |
| `README.md`, 이슈 본문, PR 본문 | 경어체 | 아니오 | 훑어 읽는 문서입니다. 아이콘이 스캔 속도를 높입니다 |
| PR 리뷰 코멘트 | 경어체 | 아니오 | GitHub 웹에서만 소비되므로 문자 손해가 없습니다. 문체만 적용합니다 |
| `AGENTS.md` `CLAUDE.md` | 해당 없음, 영문 | 아니오 | 에이전트 컨텍스트로 소비되고, 경고 아이콘이 위험 항목의 앵커입니다 |
| 코드 주석 | 해당 없음, 영문 | 아니오 | 영어로 씁니다 |

**저장소 안의 문서 폴더 다섯 개가 모두 표에 있습니다.**
빠진 행이 있으면 그 폴더는 규칙이 없는 것이 아니라 **판정할 수 없는 상태**가 됩니다.
5절 스크립트로 재면 검출은 나오는데 위반인지 아닌지를 아무도 말할 수 없고,
그 상태로 두면 리뷰에서 지적이 갈립니다.

`docs/제출_자료/` 와 `docs/참고_자료/` 는 표에 없습니다.
저장소 밖에 두기로 한 자산이고 `.gitignore` 가 막고 있습니다
([AGENTS.md](../../AGENTS.md) `Not in this repository`).

문자 규칙이 갈리는 기준은 **독자가 아니라 용도**입니다.
이 저장소는 제출 서식 자체를 담지 않으므로 "PDF 변환에서 깨진다"는 이유가 그대로 서지 않습니다.
대신 두 가지가 남습니다.
ADR 은 결정의 근거로 다른 문서가 인용하고, 공유 문서의 텍스트는 제출 서식으로 옮겨집니다.
인용하거나 옮겨 적는 사람이 자기 키보드에 없는 문자를 다시 칠 수 없다는 것이 실제 손해입니다.
반대로 GitHub 웹과 에이전트 컨텍스트에서만 소비되는 문서는
아이콘이 위험 항목의 시각적 앵커로 기능해 훑어 읽는 속도를 실제로 높입니다.

**확정 근거 등급과 문자 규칙은 다른 축입니다.**
`docs/공통_가이드/` 는 팀에게 구속력이 있으면서 문자 규칙 대상이 아닙니다.
어긋난 것이 아닙니다.
근거 등급은 "그대로 따르는가"를 정하고, 문자 규칙은 "밖으로 옮겨지는가"를 정하기 때문입니다.

### 1-a. 기존 문서는 어떻게 하나

**오늘 이후 새로 쓰는 글부터 적용합니다.**
기존 문서는 다른 이유로 손댈 때 그 부분만 함께 고칩니다.
규칙을 맞추는 것만이 목적인 일괄 치환 PR 을 내지 마세요.
[AGENTS.md](../../AGENTS.md) 의 줄바꿈 규칙이 재정렬 전용 PR 을 금지하는 것과 같은 이유입니다.

이 규약을 도입한 시점에 물려받은 검출은 아래와 같습니다(5절 스크립트 실측).

| 폴더 | 문자 규칙 | 검출 |
|---|---|---|
| `docs/adr/` | 대상 | **414건** (가운뎃점 207, em dash 90, 화살표 35, 체크 표시 21 등) |
| `docs/공유_문서/` | 대상 | **22건** (가운뎃점 12, 화살표 6, em dash 4) |
| `docs/공통_가이드/` | 대상 아님 | 1133건이 있으나 위반이 아닙니다 |
| `docs/역할_가이드/` `docs/역할_일정/` | 대상 아님 | 638건이 있으나 위반이 아닙니다 |
| `docs/pr-checklist.md` `README.md` | 대상 아님 | 77건이 있으나 위반이 아닙니다 |

**실제로 갚아야 하는 것은 436건이고, 그것도 1-a 에 따라 지금 갚지 않습니다.**
숨기지 않고 적어 두는 이유는, 적어 두어야 그것이 얼마나 남았는지 세는 기준이 되기 때문입니다.
숨기면 다음 사람이 위반 0건인 저장소라고 오해합니다.

`docs/adr/` 를 대상으로 올린 것은 그것이 확정의 유일한 출처이기 때문입니다.
`docs/공통_가이드/` 를 대상 밖에 둔 것이 1133건의 즉시 위반을 만들지 않는 쪽이기도 하지만,
**그것이 이유는 아닙니다.**
이유는 그 폴더가 저장소 밖으로 옮겨지지 않는다는 것이고,
건수는 그 판단이 옳았는지의 방증입니다.

## 2. 문체: 경어체, ADR 은 평서형

읽는 대상에 심사위원이 포함되므로 `~입니다` 와 `~습니다` 로 씁니다.
`docs/adr/` 만 예외로 `~한다` 와 `~이다` 를 씁니다.
결정문의 문체이고 기존 9건이 이미 그렇게 쓰여 있기 때문입니다.
한 문서 안에서 둘을 섞지 않습니다.

- 표 안의 문장도 같습니다. 명사로 끝나는 셀은 그대로 둡니다.
- **내포절은 원형을 유지합니다.** 경어체는 문장 최종 어미에만 적용합니다.
  - 맞음: 위치 데이터를 세션이 소유한다는 것입니다.
  - 틀림: 위치 데이터를 세션이 소유합니다는 것입니다.
- **다이어그램 라벨은 명사구입니다.** mermaid 노드, 축 제목, 범례에는 경어체를 적용하지 않습니다.
- 영문 문서는 전환이 필요 없습니다. `AGENTS.md` 와 `CLAUDE.md` 가 여기 해당합니다.

## 3. 문자: 키보드로 칠 수 있는 것만

**대상은 `docs/adr/` 와 `docs/공유_문서/` 둘뿐입니다**(1절 표).
그 둘에서는 한글, 숫자, 라틴 문자, ASCII 문장부호만 씁니다.

이유는 두 가지입니다.
인용하거나 제출 서식으로 옮겨 적는 사람이 자기 키보드에 없는 문자를 다시 칠 수 없습니다.
그리고 뷰어와 변환기마다 다르게 렌더링하거나 조용히 누락합니다.

| 쓰지 않을 것 | 대신 쓸 것 |
|---|---|
| 가운뎃점 | 쉼표, 또는 복합어에는 슬래시 |
| em dash, en dash | 하이픈, 콜론, 또는 문장을 나눕니다 |
| 화살표 기호 | `->`, 또는 연결어(따라서, 그래서) |
| 경고 기호, 정보 기호, 체크 이모지 | "주의:", "참고:", 또는 문장으로 |
| 곱셈 기호 | 소문자 x |
| 말줄임표 문자 | 마침표 세 개 |
| 둥근 따옴표, 둥근 아포스트로피 | 곧은 따옴표 |
| 체크 표시, 가위표 | O 와 X, 또는 예 와 아니오 |
| 로마 숫자 글리프, 원문자 숫자 | 1, 2, 3 또는 (1), (2) |
| 부등호 기호 | `<=`, `>=` |
| 섹션 기호 | `2절`, `4-a절` |

### 3-a. 물결표는 양쪽을 띄웁니다

**이 항만은 모든 마크다운 문서에 적용됩니다.**
문체나 제출 여부와 무관한 렌더링 사고이기 때문입니다.

물결표는 키보드로 칠 수 있으므로 범위 표기에 쓸 수 있습니다.
다만 **반드시 띄어 씁니다**: `1 ~ 2`, `07-27 ~ 08-10`.

붙여 쓰면 GFM 이 다음 물결표와 짝을 지어 그 사이를 취소선으로 렌더링합니다.
`1~2 3~4` 는 "2 3" 이 지워진 채로 보입니다.
산문 안의 다른 물결표도 같습니다. 띄우거나 `\~` 로 이스케이프합니다.

### 3-b. 예외

코드, 경로, 명령, 식별자, 파일명은 원문 그대로 둡니다.
백틱으로 감싸고 안쪽은 바꾸지 않습니다.
실행 가능성이 조판보다 우선합니다.

    맞음: `--profile=savers`
    틀림: `—profile=savers`

인용문도 같습니다.
제목, 인용, 소프트웨어가 화면에 실제로 출력하는 문자열을 고쳐 쓰면
시스템의 동작을 잘못 보고하게 됩니다.

## 4. 그 밖의 서식

- 줄바꿈은 [AGENTS.md](../../AGENTS.md) 의 `Markdown line wrapping` 절이 정본입니다.
  문장 경계에서 끊고 한글 약 50자를 상한으로 봅니다. 여기에 복제하지 않습니다.
- 다이어그램은 mermaid 코드 블록으로 씁니다. 이미지는 diff 에 변경이 보이지 않습니다.
  디렉토리 트리는 일반 코드 블록을 유지합니다.
- **규칙에는 이유를 함께 적습니다.** 이유 없는 규칙은 사람도 에이전트도 무시합니다.
- 불확실한 기술 주장에는 신뢰도를 표기합니다.
  라벨과 기준은 [코드_리뷰_가이드.md](코드_리뷰_가이드.md) 4-a 가 정본입니다.
- **확정 표기에는 ADR 번호를 답니다.** 다른 가이드 문서를 가리킨 것은 근거가 아닙니다
  ([AGENTS.md](../../AGENTS.md) `Collaboration / Git`).

## 5. 커밋 전 점검

코드 블록 밖의 비ASCII 문장부호를 훑습니다.
대상은 3절의 두 폴더입니다.

```python
import re, sys, unicodedata

src = open(sys.argv[1], encoding="utf-8").read()
body = re.sub(r"```.*?```", "", src, flags=re.S)   # 펜스 코드 블록 제외
body = re.sub(r"`[^`]*`", "", body)                 # 인라인 코드 제외

for line_no, line in enumerate(body.splitlines(), 1):
    for ch in line:
        if ord(ch) < 128 or "HANGUL" in unicodedata.name(ch, ""):
            continue
        print(f"{line_no}: {ch!r} {unicodedata.name(ch, 'unnamed')}")
```

다이어그램 소스는 펜스 블록 안에 있으므로 이 검사가 건너뜁니다.
mermaid 노드 라벨은 문서에 **보이는 텍스트로 렌더링되므로** 같은 규칙을 따르며,
따로 확인해야 합니다.
