## 2. 세이버스가 해결하려는 문제

세이버스는 스스로 판단·대피하기 어려운 사람들 — 안전취약계층(어린이·노인·장애인)과 언어 장벽이 있는 외국인 근로자 — 을 위한 재난 대응 보조 서비스입니다.

핵심 문제의식은 이렇습니다: **정보가 없는 것이 문제가 아니라, "정보를 개인의 행동으로 전환하는 능력"이 부재하다는 것**입니다.  
기존의 긴급재난문자(CBS)나 안전디딤돌은 모두에게 동일한 지역 단위 정보를 일방적으로 전달할 뿐입니다.  
세이버스는 등록된 사용자에게 재난 경보가 오면, 알림 링크를 여는 그 순간에만 현재 위치를 **1회** 확인(백그라운드 추적 없음, 세션 단위 사용·미저장)하고,  
가드레일로 통제된 개인 맞춤 행동지침을 **PWA 웹푸시(FCM)** 로 전달합니다([ADR-0005](../adr/0005-webpush-primary-channel.md)).

MVP의 1차 대상 재난 유형은 **호우·도시침수**입니다.

## 3. 아키텍처 — 판정은 정부, 계산은 세이버스, 전달은 무설치 채널

서비스는 세 층입니다.
**① 판정**은 정부 기관(기상청·홍수통제소·기후부 도시침수예보)이 하고,
**② 계산**은 세이버스가 하며,
**③ 전달**은 앱스토어 설치 없이 모바일 웹으로 합니다.
**정부가 실시간 계측으로 공개하는 정보를 따르므로 자체 경보 판단은 구현하지 않습니다.**

계산 층에 세이버스 고유의 핵심 기술 셋이 들어갑니다.

1. **대피소 부합도 모델** — 서울시 수해대피소 지정 목록을 정답으로 학습하는 PU(spy 기법) 분류 모델.
    **라벨과 피처를 분리**해 서울 전용 데이터는 정답·검증에만 쓰고,
    입력은 표고·대피 여유고·지하층수·하천 최단거리 등 **전국 공통 공개 데이터 13개**로만 구성합니다.
    출력은 「서울시 지정기준 부합도」이며 SHAP 기여도로 근거를 함께 보여줍니다.
2. **침수 회피 경로** — OSM 도로망을 **OSMnx + networkx** 그래프로 올린 뒤 모든 링크에 침수 위험 등급 R0 ~ R3을 붙이고,
    R2(침수심 0.5 ~ 1.0m)·R3(지하차도·하천변)을 제거한 뒤 남은 경로 중 최단을 고릅니다.
    통과 가능한 길이 없으면 **「경로 없음」으로 표기하고 대피소를 다시 고릅니다.**
3. **보호자 상황 확인 RAG** — 화면 상태·버튼 클릭 **이벤트 로그**를 검색해 보호자 질문에 답합니다.
    관측 → 계획·검색 → 행동·생성 → 응답 검증 → 전달·에스컬레이션의 5단계가
    **30분 무응답이면 관측으로 되돌아가는** 에이전틱 루프이며,
    응답 검증은 문장을 주장 단위로 쪼개 로그와 1:1 대조해
    **미대응이 한 건이라도 있으면 문장 전체를 차단**합니다.
4. **무설치 사용자 터미널** — **PWA 웹푸시(FCM)** 로 전달하며, 생성된 문안은 **변형 없이 그대로** 나갑니다
    (템플릿 슬롯 치환 계층 없음 — [ADR-0005](../adr/0005-webpush-primary-channel.md)).
    사용자 화면은 ①특보 수신 → ②정보 입력 → ③상황 분기 → ④행동 권고(상황 주시/대피 준비/즉시 대피 3단계 신호등) → ⑤경로 안내 순서입니다.
    1차 구현 범위는 **Android 무설치 웹푸시**이고, iOS는 홈 화면 추가(A2HS)를 거쳐야 웹푸시가 열립니다.

**폴백은 안내를 멈추지 않되 무엇이 대체된 값인지 화면에 드러냅니다.**
특보 API 중단 시 Redis 캐시로, 지오코딩·DEM 매칭 실패 시 「판정 불가」로,
로그 대조 검증 실패 시 최소안전문으로 전환합니다.

> 국민행동요령 코퍼스 RAG(`apps/ai-engine`의 청킹·Chroma 인덱싱·조건부 검색)는 예선 구간의 산출물로 그대로 남아 있습니다.
> 보호자 RAG는 **세션 로그 전량을 컨텍스트로 넣는 방식이라 벡터 인덱스를 쓰지 않습니다** — 둘을 섞지 마세요.

## 4. 반드시 지켜야 할 설계 원칙

아래 원칙들은 기획 단계에서 이미 리스크 대응 차원에서 확정된 것으로, 개발 편의를 위해 임의로 바꾸면 안 됩니다.

- **상시 위치 추적 금지**: 위치는 알림을 여는 시점에 딱 1회만 읽고, 세션 단위로만 사용하며 저장하지 않습니다.
- **근거 기반 생성 필수**: LLM은 반드시 검색된 국민행동요령 원문에 근거해서만 답해야 합니다.  
    가드레일은 환각 억제를 위한 핵심 장치이며, 그 on/off 효과 자체가 측정 지표이므로 편의상 우회하거나 제거하면 안 됩니다.
- **당사자에게 설치 부담 없음**: 등록·설정은 당사자가 아니라 보호자·복지관·지자체가 대신하도록 설계되어 있습니다.  
    취약계층 당사자에게 앱 설치나 직접 설정을 요구하는 기능은 이 원칙과 충돌합니다.
- **오프라인/장애 대응 필수**: 공공 재난 API가 지연되거나 장애가 나면,  
    조용히 실패하는 대신 사전 캐시된 대피소, 행동요령으로 전환되는 예비모드가 있어야 합니다.
- **최소 수집·암호화**: 위치, 장애 여부 등 민감정보는 최소한만 수집하고 암호화합니다.  
    새로운 사용자 필드를 추가할 때도 이 기준을 하드 요구사항으로 취급해야 합니다.

## 5. 품질 검증 지표 (사람 채점이 아니라 코드로 재현 가능해야 함)

이 팀의 차별화 전략은 품질을 **설문이 아닌 재현 가능한 자동 채점 스크립트**로 증명하는 것입니다.
기획서 v3의 정량 목표는 **4대 지표**이며, 채점 스크립트·평가셋·학습 코드를 함께 제출합니다.

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| **알림 도달 속도** | 30초 이내 | OTel 종단 스팬으로 `재난 API 수신 → 발송` 구간 p95 측정. **FCM 실발송이 전제** |
| **보호자 응답 정확도** | **로그에 없는 사실 0건** | 골든셋 40건(추천 30 + 기타 10)에 대해 대조 검증기 통과/차단 판정 |
| **위치정보 무저장·무로깅** | 좌표가 저장·로깅되는 지점 **0건** | `scripts/check_privacy.py`(머지·CI 연결 완료) 전 트리 스캔. `/v1/shelters/search`는 좌표를 **받되** 세션·로그·DB 어디에도 쓰지 않음을 확인. 「즉시 파기 준수율 100%」→「미수신」(8/21)→「무저장·무로깅」(8/22, [ADR-0011](../adr/0011-m3-no-storage-not-no-receipt.md) 제안 상태 — 검토 중) |
| **폐루프 2차 발송 성공률** | 100% | 30분 무응답 → 보호자 2차 발송 도달 여부 |

부합도 모델은 별도로 **3겹 검증**합니다 —
① 자치구 GroupKFold 공간 블록 교차검증 ② 비(非)학교 대피소 recall@top-20%(주지표)
③ 침수예상도 베이스라인 대비 lift.
(기획서 [표3]의 4겹 중 ④ 문자열·표준필드·모델 3자 비교는 본선 범위에서 생략하며, 3겹 기준임을 명시합니다.)

**미달 항목은 숨기지 않고 실패 사례로 기재합니다.**
기획서가 그렇게 약속했고, 그것이 이 팀 신뢰도의 근거입니다.
부합도 3차 성능은 아직 실측 전이라 기획서 [표3]에 선행연구 보고치가 목표 구간으로 들어가 있으며,
**본선까지 자체 실측으로 교체**합니다.

> 예선 구간의 지표였던 근거 일치율·환각 억제율·메시지 명확성은 국민행동요령 코퍼스 RAG를 대상으로 한 것이며,
> v3에서 주지표 자리는 위 4대 지표가 대신합니다.
> 코퍼스 RAG의 채점 하네스(`apps/ai-engine/eval/`)는 그대로 남아 있습니다.

## 7. 저장소 구조 컨벤션 (모노레포)

팀이 직접 수행한 역대 수상팀 GitHub 구조 조사(원본 PDF는 public 레포에 올리지 않고 팀 공유 드라이브에 보관 — [AGENTS.md](../../AGENTS.md)의 "Not in this repository" 참고)의  
**본질적 결론**은 **"AI를 인라인 API 호출이 아니라 독립적으로 배포 가능한 엔진/모듈로 두고, 배포·운영 문서까지 README에 정리하라"** 입니다.

우리 팀은 **소규모(접수 시 6인 · 현재 4인) · 해커톤 단기 · Tech Lead 초반 집중** 조건이므로,  
멀티레포의 관리비용(문서·인프라 중복, cross-repo PR 조율, 온보딩 부하)과 통합 부채가 이득보다 큽니다.  
따라서 **단일 모노레포**를 채택하되, AI는 그 안에서 **독립 배포 가능한 서비스**로 유지해 수상작의 본질 조건을 충족합니다.

```
savers-project/            # 단일 레포 (모노레포) — github.com/team-savers/savers-project
  apps/
    frontend/              # PWA — React+Vite+TS, 웹푸시(FCM) + 통합 서비스워커
      package.json         #   백엔드 연동 전이라 mock 어댑터가 기본(VITE_USE_MOCK=true)
    backend/               # FastAPI (데이터 수집·위치 매칭)
      pyproject.toml       #   src/api(얇은 라우터) + src/backend_core(도메인)
    ai-engine/             # 독립 배포: 자체 Dockerfile + README (RAG·LangChain·가드레일)
      pyproject.toml       #   src/ai_engine
      eval/                #   평가 하네스 — 골든셋·지표 함수 (채점 대상과 같은 배포 단위)
  packages/
    contracts/             # OpenAPI 스펙 + 공용 스키마/타입 (단일 진실 공급원, SSOT)
  infra/                   # docker-compose, .env.example, AWS 프로비저닝
  e2e/                     # 앱 가로지르는 관통 테스트 (QA 소유, HTTP 전용, non-required CI)
  notebooks/               # 실험 기록 (배포 대상 아님 — 검증되면 apps/<app>/src 로 이전)
  scripts/                 # setup-dev.sh/.ps1(환경 점검·복구) · run-tests.sh(품질 게이트)
                           #   · setup-github.sh(레포 하드닝)
  docs/                    # ADR(docs/adr/), 설계·운영 가이드
  pyproject.toml           # ⚠️ ruff 설정 전용 — 설치 가능한 패키지가 아님
  .github/workflows/       # pre-commit + 앱 매트릭스 CI (required check 5종)
  CODEOWNERS               # 폴더별 소유자
```

- **문서·인프라·env 공유**: `infra/`·`docs/`에 한 곳으로 모아 중복·드리프트 제거.
- **관리 부하 최소화**: `docker-compose up` 한 번으로 전체 로컬 구동, 단일 PR로 계층 걸친 변경을 atomic 반영.
- **경계 유지**: `CODEOWNERS` + 브랜치 보호로 소유권 분리.
- **CI 구성**: 워크플로는 **required(필터 없음) / non-required(paths 필터)** 두 갈래로 나뉩니다. required status check에 paths 필터를 걸면 해당 경로를 건드리지 않은 PR에서 체크가 생성되지 않아 머지가 영구 블록되기 때문입니다.

| 워크플로 | 잡 | required | 트리거 |
|---|---|---|---|
| `ci.yml` | `Pre-commit hooks`(훅 전량 + gitleaks 전체 트리 스캔) · `Lint & Type Check (backend/ai-engine)` · `Unit tests (backend/ai-engine)` | ✅ 5종 | 모든 PR |
| `frontend-ci.yml` | 프론트 lint/typecheck/build | ❌ | `apps/frontend/**` |
| `docker-build.yml` | 이미지 빌드 + `/health` 스모크, compose config 검증 | ❌ | `apps/*/Dockerfile`·`src/**`·`infra/**` |
| `contracts-check.yml` | OpenAPI 스펙 검증 | ❌ | `packages/contracts/**` |
| `e2e.yml` | 종단 관통 테스트 (스택 기동 → HTTP 관통) | ❌ | `e2e/**`·`apps/**`·`infra/**` |
| `notebook-check.yml` | 노트북 출력 셀 제거 확인 | ❌ | `**.ipynb` |

  non-required 워크플로 4종은 **대상 파일이 아직 없으면 전 단계를 건너뛰도록** 작성돼 있어, 프론트엔드·compose·OpenAPI 스펙이 생기는 순간 별도 설정 없이 활성화됩니다. required 잡을 추가·개명할 때는 `scripts/setup-github.sh`의 `contexts` 배열을 **같은 PR에서** 함께 고치세요 — 이름이 어긋나면 모든 PR이 생성되지 않는 체크를 기다리며 블록됩니다.
- **수상작 본질 충족**: `apps/ai-engine/`은 자체 Dockerfile·README로 "독립 배포 가능한 엔진"임을 증명.
