# ADR-0025: 프리즈 태그는 freeze-YYYYMMDD, 시연 브랜치는 demo/finals 로 고정한다

## 배경 (Context)

이 저장소에는 태그가 하나도 없다.
`git ls-remote --tags origin` 이 비어 있고 origin 에 `demo/finals` 도 없다 -
`확실한 사실`, 2026-08-30 확인.
일정표의 프리즈 시점은 8/29 이고, 리허설이 8/31 ~ 9/1, 본선이 9/2 ~ 9/3 이다.

이름 규칙이 없으면 프리즈 선언이 가리킬 대상을 지목할 수 없다.
코드 프리즈는 태그로 남기게 되어 있고
(역할_가이드/02 "전 역할 합의를 받아 태그로 남깁니다"),
배포는 그 태그를 클론하는 것으로 적혀 있다
(역할_일정/01 8/29 행 "프리즈 태그가 배포되고").

태그를 찍는 자리에서 이름을 즉석에서 정하면 첫 태그는 어떻게든 찍힌다.
문제는 두 번째다.
프리즈 이후 시연 경로 버그 수정이 한 번이라도 나오면
두 번째 태그의 이름을 첫 번째와 맞춰야 하는데,
그 시점은 리허설과 본선 사이여서 규칙을 논의할 자리가 아니다.

규약 본문은 PR #227 이 이미 저장소_운영.md 6절에 넣었다.
남은 것은 기록이다.
[AGENTS.md](../../AGENTS.md) 가 확정의 유일한 출처를 ADR 번호로 정해 두었으므로,
번호가 붙기 전까지 그 절은 스스로를 검토 중으로 표기해야 했다.
날짜와 역할을 적은 "Tech Lead 판정" 표기는 그 출처가 되지 못한다.

## 결정 (Decision)

1. **프리즈 태그는 `freeze-YYYYMMDD` 다.**
   프리즈 후 승인된 수정마다 `.N` 을 증분한다
   (`freeze-20260829` -> `freeze-20260829.1` -> `freeze-20260829.2`).
   어노테이트 태그 (`git tag -a`) 로 찍고 전 역할 합의 근거를 메시지에 적는다.
2. **시연 브랜치는 `demo/finals` 하나로 고정한다.** 날짜를 붙이지 않는다.
3. **시연 브랜치는 무엇을 시연했는지 가리키는 포인터이지 작업 브랜치가 아니다.**
   프리즈 후 수정은 `main` 으로 PR 을 거친 뒤 새 태그를 찍는 경로이며,
   시연 브랜치에 직접 push 하지 않는다.
4. **semver 를 쓰지 않는다.** `v0.10.0` 같은 태그를 만들지 않는다.

근거는 넷이다.

- **기존 이름 축을 그대로 쓴다.**
  사람이 만든 브랜치가 전부 `<목적>/<영문-케밥>` 12종이고,
  날짜가 들어간 브랜치는 `YYYYMMDD` 압축형을 쓴다 (`docs/adr-approvals-20260828`).
  사람이 짓지 않은 이름은 반례로 치지 않는다 - 자동 생성분이 19건 있다 (2026-08-30 기준).
  Dependabot 17건 (`dependabot/pip/apps/backend/...` 처럼 슬래시가 여러 개라
  애초에 `<목적>/<영문-케밥>` 이 아니다) 과
  GitHub 웹 편집기가 만든 `eunnamahn-patch-N` 2건이다.
  새 축을 만들면 이 저장소의 이름 규칙이 둘이 된다.
- **연번 구분자가 하이픈이면 날짜와 섞인다.**
  하이픈은 이미 "목적-날짜" 구분자로 쓰고 있어
  `freeze-20260829-1` 은 날짜의 일부로 읽힌다.
  `.` 은 그 자리에 쓴 적이 없어 구분자로 비어 있다.
- **태그는 한 개가 아니다.**
  프리즈 이후에도 시연 경로 버그 수정은 전 역할 합의를 받아 태그로 남기므로,
  연번 자리가 규약에 처음부터 있어야 한다.
  나중에 붙이면 첫 태그만 형식이 다르다.
  최신 프리즈는 `git tag -l 'freeze-*' --sort=-v:refname | head -1` 로 찾는다.
  기본 정렬 (`| tail -1`) 은 쓰지 않는다.
  사전순은 `.10` 을 `.2` 보다 앞에 놓아, 같은 날 연번이 10 을 넘으면 `.9` 가 최신으로 잡힌다.
  `-v:refname` 은 숫자 구간을 수로 비교하므로 그 경우에도 맞다.
- **semver 는 이 저장소에서 이미 다른 것의 이름이다.**
  `packages/contracts/openapi.yaml` 이 `version: 0.10.0-draft` 를 싣고 있고,
  ADR 2건 (ADR-0014, ADR-0021) 이 "계약 v0.10" 으로 인용한다.
  태그에 같은 문자열을 붙이면 한 이름이 계약 개정판과 프리즈 시점 둘을 뜻하게 된다.
  `apps/*/pyproject.toml` 의 `0.1.0` 은 한 번도 올린 적이 없어 판번호 노릇을 하지 못하므로,
  semver 를 유지할 근거도 되지 못한다.

### 검토하고 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| semver 태그 (`v0.10.0`) | `v0.10` 이 이미 계약 개정판의 이름이다. 그 이름을 인용하는 ADR 2건이 먼저 있으므로, 나중에 온 태그가 이름을 비켜 주는 쪽이 맞다 |
| 하이픈 연번 (`freeze-20260829-1`) | 하이픈이 이미 날짜 앞 구분자다. 연번이 날짜의 일부로 읽힌다 |
| 태그를 하나만 두고 프리즈 후 수정 때마다 옮겨 찍는다 | 이미 배포된 태그가 가리키는 커밋이 바뀐다. 배포 서버가 받은 트리와 저장소의 같은 이름이 다른 것을 가리키게 되고, 리허설에서 무엇을 봤는지 되짚을 수 없다 |
| 태그 없이 커밋 SHA 로 지목한다 | 배포 절차와 일정표가 "프리즈 태그" 로 적혀 있고, SHA 는 사람이 옮겨 적다 틀린다. 옮겨 적기가 틀리면 시연 트리가 달라지는데 그 사실이 화면에 드러나지 않는다 |
| 날짜를 붙인 시연 브랜치 (`demo/finals-20260829`) | 리허설마다 브랜치가 늘고, 본선 당일 어느 것이 진짜인지 가릴 근거가 없다. 시점 정보는 태그가 이미 갖고 있다 |
| 시연 브랜치를 작업 브랜치로 쓴다 | 워크플로의 push 트리거가 전부 `branches: [main]` 이라 CI 가 돌지 않는다. 프리즈 이후 수정이 검사 없이 시연 트리로 들어간다 |

## 결과 (Consequences)

**긍정**

- 저장소_운영.md 6절이 검토 중 표기를 뗀다. 프리즈 선언이 확정된 이름을 가리킨다.
- 프리즈 이후 수정이 몇 번 나오든 이름이 충돌하지 않고,
  최신 프리즈를 명령 한 줄로 찾는다.
- 계약 개정판 이름과 태그 이름이 겹치지 않아 "v0.10" 이 계속 계약 하나만 뜻한다.
- 시연 브랜치가 하나뿐이라 본선 당일 "지금 무엇을 시연 중인가" 에 답이 하나다.

**부정 / 완화**

| 리스크 | 완화 | 상태 |
|---|---|---|
| 시연 브랜치에 직접 push 하면 CI 가 돌지 않는다 | 결정 3번이 경로를 `main` PR 로 못박는다 | 명시함, 저장소_운영.md 6절 |
| `demo/finals` 로 PR 을 열고 그것을 머지하면 시연 브랜치가 사라진다. 저장소가 `delete_branch_on_merge: true` 라 머지 시 head 브랜치를 자동 삭제한다 | 경고문은 리허설 당일의 실수를 막지 못하므로 열 이유 자체를 없앤다 - `demo/finals` 로는 PR 을 열지 않는다. 검사는 이미 끝나 있다 (아래 행) | 명시함, 저장소_운영.md 6절 |
| 태그를 밀어도 CI 가 돌지 않는다. 태그로 트리거되는 워크플로가 없다 | 사람이 되짚을 필요가 없다. 태그는 `main` 커밋에만 찍고, `main` 은 브랜치 보호가 required check 5종을 `strict: true` 로 요구해 검사를 통과한 커밋만 받는다 | 명시함, 저장소_운영.md 6절 |
| 배포 절차의 `git clone <url>` 은 기본 브랜치를 받으므로 태그가 아니다 | `git clone --branch <프리즈 태그> <url>` 로 받아야 "프리즈 태그가 배포되고" 가 성립한다. detached HEAD 가 되지만 배포 서버에서는 정상이다 | 후속 조치, PM |
| Vercel 대시보드의 Deployment Branches 설정이 배포_절차.md 79행과 어긋나 보인다 | 대시보드는 git 이 추적하지 않아 눈으로 확인해야 한다 - `불확실`. 태그를 찍기 전에 확인한다 | 후속 조치, PM |
| 이 결정이 저장소 전체의 브랜치 명명 규약으로 인용된다 | 범위는 프리즈 태그와 시연 브랜치 이름 둘뿐이다. 기존 12종 접두어는 이 결정의 대상이 아니다 | 명시함 |
| 하루에 프리즈를 두 번 해야 하는 상황이 온다 | `.N` 이 같은 날의 두 번째를 이미 표현한다. 날짜를 올리지 않고 연번만 올린다 | 명시함 |
