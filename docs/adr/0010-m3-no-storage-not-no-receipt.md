# ADR-0010: M3 지표를 "위치정보 미수신"에서 "위치정보 무저장, 무로깅"으로 재정정한다

- **상태**: 제안 (Proposed) - PR [#95](https://github.com/team-savers/savers-project/pull/95) 리뷰(신호정) 지적에 따라 작성, Tech Lead 승인 대기
- **날짜**: 2026-08-22
- **결정자**: 안은남 (PM) 제안 / 신호정 (Tech Lead) 승인 대기
- **관련 문서**: [정량목표_검증설계.md 3절](../공유_문서/정량목표_검증설계.md), [서비스_기획서.md](../공유_문서/서비스_기획서.md) 정정 항목 표, `packages/contracts/openapi.yaml`, `apps/backend/src/api/routes/shelters.py`

## 배경 (Context)

2026-08-21, PR #95에서 M3 지표를 "위치정보 즉시 파기 준수율 100%"에서
"위치정보 미수신, 서버에 좌표가 도달하는 지점 0건"으로 바꿨습니다.
근거는 `SessionStore`에 삭제 메서드가 없어 "파기"가 코드로 증명되지 않는다는 것과,
원 기획서 4장이 이미 "받지 않는다"라고 적었다는 것이었습니다.

그런데 PR #95 리뷰(신호정, 2026-08-22)가 실제 계약, 코드를 대조한 결과,
"미수신"이 사실과 다릅니다.

- `packages/contracts/openapi.yaml`의 `POST /v1/shelters/search`가
  `lat`/`lng`를 요청 본문으로 받습니다([집이에요]가 아닌 [밖이에요] 경로).
- `apps/backend/src/api/routes/shelters.py`가 그 값을 `hazard_match`와
  `repository.search`에 실제로 전달합니다.
  코드 주석: "payload.lat/lng end their life here, 저장이나 로깅 없이 그 요청 안에서 소멸".

즉 현재 설계는 **"받되 저장하지 않는다"**이지 **"받지 않는다"**가 아닙니다.
이 상태로 본선 질의응답에서 "서버에는 좌표를 받는 엔드포인트 자체가 없다"고 말하면,
심사위원이 저장소의 `openapi.yaml`만 열어봐도 반증됩니다.

세 가지 대안을 검토했습니다.

1. 문구를 코드에 맞춘다. 아키텍처 변경 없음
2. 계약과 라우트를 걷어내고 행정동 판정, 대피소 선정을 클라이언트로 옮긴다. 원 기획서 4장의 주장대로 되돌림
3. "엔드포인트는 있으나 세션 스코프에서 즉시 소멸, 저장 지점 0건"으로 범위를 명시한다

2안은 아키텍처 변경이라 남은 구현 창구 52시간에 들어갈 자리가 없고
([00-overall.md 6절](../역할_일정/00-overall.md#6-여유-시간-대기-목록--남으면-이-순서로-)의 여유 시간 대기 목록 어디에도 이 작업이 없습니다),
1안과 3안은 사실상 같은 결론(문구 교정)이므로 1안을 채택합니다.

## 결정 (Decision)

M3 지표 문구를 **코드가 실제로 보장하는 것**에 맞춥니다. 아키텍처는 바꾸지 않습니다.

> **M3, 위치정보 무저장, 무로깅. 좌표가 저장되거나 로그에 남는 지점 0건**

- `POST /v1/shelters/search`는 좌표를 **받습니다**. "받지 않는다"고 말하지 않습니다.
- 그 값은 해당 요청 처리(`hazard_match`, `repository.search`)에만 쓰이고,
  세션, 이벤트 로그, DB, 파일 어디에도 쓰이지 않습니다.
- `check_privacy.py`가 검사하는 것은 "좌표를 받는 경로가 없는가"가 아니라
  "좌표가 저장되거나 로깅되는 지점이 있는가"입니다. 이 스캔 정의는 바뀌지 않습니다.
  애초에 저장 여부를 검사하도록 짜여 있었고, 이번 정정은 **표현을 스캔의 실제 범위에 맞추는 것**입니다.

## 결과 (Consequences)

**긍정**

- 실제 코드와 어긋나지 않는 주장이 되어, 질의응답에서 반증 가능한 지점이 사라집니다.
- 아키텍처 변경 없이 문서 수정만으로 처리됩니다.
- 기존 `check_privacy.py` 점검 범위(저장, 로깅 스캔)와 표현이 그대로 일치합니다.

**부정 / 완화**

| 리스크 | 완화 | 상태 |
|---|---|---|
| 원 기획서 4장이 "좌표 수신 엔드포인트가 없다"고 이미 적어 제출본과 어긋납니다 | 원문은 고치지 않습니다(외부 제출본, [AGENTS.md](../../AGENTS.md) "Not in this repository"). [서비스_기획서.md](../공유_문서/서비스_기획서.md) 정정 항목 표에 이 어긋남을 명시합니다 | 완료, 이 PR |
| "무저장, 무로깅"은 "미수신"보다 방어가 한 단계 복잡합니다. 엔드포인트 존재를 먼저 인정해야 합니다 | 질의응답 대본에 "받습니다, 그러나 저장하지 않습니다" 두 문장을 순서대로 넣습니다 | 완료, [정량목표_검증설계.md 3절](../공유_문서/정량목표_검증설계.md) |
