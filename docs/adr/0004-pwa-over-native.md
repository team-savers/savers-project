# ADR-0004: 사용자 터미널은 PWA(웹)로 하고 네이티브/하이브리드 앱을 쓰지 않는다

- **상태**: 승인 (Accepted) — **단, 푸시 채널 부분은 [ADR-0005](0005-webpush-primary-channel.md)로 대체됨 (2026-07-26)**
- **날짜**: 2026-07-25
- **결정자**: 안은남 (PM), 이진호 (Frontend/UX), 김도혁 (QA/Security, 웹푸시 대체경로)
- **관련 문서**: [CLAUDE.md](../../CLAUDE.md) 설계 원칙·Tech stack, [구현_범위.md](../공통_가이드/구현_범위.md) 4절, [개발자_가이드.md](../공통_가이드/개발자_가이드.md) 4절, [역할_가이드/04-프론트엔드-UX.md](../역할_가이드/04-프론트엔드-UX.md), [ADR-0001](0001-monorepo.md)

## 배경 (Context)

사용자 터미널의 **배포 형태(웹 / 네이티브 앱 / 하이브리드)**가 문서에 명시되지 않아,
프론트엔드 구현 방향에 대한 논의가 필요했다. 팀 내부에서 제기된 우려는 두 가지였다.

1. **웹으로 갈 경우** 위치 권한 프롬프트와 알림톡 연동이 쟁점이 될 것이다.
2. **네이티브 앱으로 갈 경우** 개발·배포 자체가 진입 장벽이 될 것이다. (하이브리드는 난이도만 올려 애초에 후보에서 제외)

재검토 결과, 이 결정은 취향이 아니라 이미 확정된 **하드 제약에서 강제**되는 것으로 드러났다.

- 모듈 4의 이름 자체가 **"무설치 사용자 터미널"**이고, 설계 원칙에
  **"당사자에게 설치 부담 없음 — 등록·설정은 보호자·복지관·지자체가 대신"**이 하드 요구사항으로 박혀 있다
  ([개발자_가이드.md](../공통_가이드/개발자_가이드.md) 4절).
- 전달 경로가 **알림톡 딥링크**다. 링크를 탭했을 때 앱이 없으면 스토어로 튕겨 **진입 자체가 깨진다.**
- 우리는 **"상시 위치 추적 금지"**를 원칙으로 두므로, 네이티브의 유일한 위치 이점(백그라운드 위치)은
  **우리가 쓰면 안 되는 기능**이다 → 앱이 줄 실질 메리트가 없다.

우려 ①(위치 권한·알림톡)도 재검토하면 웹의 약점이 아니었다.

- **위치 권한**: 웹 Geolocation은 HTTPS+사용자 제스처에서 1회 프롬프트로 동작 →
  "알림 링크를 여는 순간 1회 확인, 세션 미저장" 설계와 정확히 정합한다.
- **알림톡**은 프론트 통합 대상이 아니다. 발송은 백엔드가 대행사(솔라피/알리고) API를 호출하는
  서버 사이드 작업이고, 프론트는 알림톡에 담긴 딥링크로 진입하는 랜딩일 뿐이다.

## 결정 (Decision)

사용자 터미널은 **PWA(웹) 단일 형태**로 구현한다. 네이티브 앱과 하이브리드 앱은 채택하지 않는다.

- **PWA 채택** — 알림톡 딥링크 → 브라우저 진입 → 위치 1회 확인 → 개인화 행동지침 렌더의 흐름을
  설치 마찰 없이 구현한다. "무설치" 원칙을 형태 수준에서 보장한다.
- **위치 권한 실패는 단일 실패점이 아니다** — 권한 거부/실패 시 **등록 행정동 기반 매칭으로 degrade**한다
  (오프라인 예비모드와 함께 [구현_범위.md](../공통_가이드/구현_범위.md) 1·5절).
- ~~**푸시는 알림톡 1차 / 웹푸시 보조** — iOS Safari 웹푸시는 홈 화면 추가(A2HS) PWA에서만 가능하다는
  플랫폼 한계가 있으나, 알림톡을 1차 채널로 두어 이 한계를 우회한다.~~
  → **[ADR-0005](0005-webpush-primary-channel.md)로 대체.** 웹푸시(FCM)가 1차 채널이 되고 알림톡은
  예선 범위에서 빠졌다. **iOS A2HS 한계의 우회로가 사라졌으므로 잔여 리스크로 승격**됐다.
- **권장 스택** — React + Vite + `vite-plugin-pwa`(Workbox 기반 Service Worker/오프라인 캐싱).

## 결과 (Consequences)

**긍정**

- "무설치" 원칙을 형태 수준에서 보장 → 취약계층 당사자가 아무것도 설치하지 않고 링크 탭만으로 진입.
- 앱스토어 심사 리스크 제거 → [리스크.md](../공통_가이드/리스크.md) 일정 리스크(⑧) 축소.
- 위치 권한 모델이 "1회·세션 미저장" 프라이버시 설계와 자연히 일치.
- 로컬 개발·배포가 웹 단일 파이프라인으로 단순화([ADR-0001](0001-monorepo.md) `apps/frontend`).

**부정 / 완화**

| 리스크 | 완화 |
|---|---|
| iOS 웹푸시가 A2HS PWA에서만 동작 | ~~알림톡을 1차 푸시 채널로 두고 웹푸시는 보조 fallback으로 한정~~ → **완화책 무효([ADR-0005](0005-webpush-primary-channel.md))**. 시연 환경을 안드로이드·데스크톱 크롬으로 고정하고, iOS는 대리등록 절차에 A2HS 안내를 포함 |
| 위치 권한 팝업을 취약계층이 이해 못할 수 있음 | 권한 실패 시 등록 행정동 기반 매칭으로 degrade, 안내 문구·쉬운 글 UI 병행 |
| "웹이라 앱보다 가벼워 보인다"는 심사 인상 | AI 독립 배포 모듈·오프라인 예비모드·PWA 오프라인 캐싱 등 기술 실질로 반박 |

## 재검토 조건

백그라운드 위치·상시 알림 등 **네이티브 고유 기능이 서비스 요구가 되고, 그것이 "무설치"·"상시 추적 금지"
원칙 변경을 동반해 승인될 경우에만** 네이티브(또는 하이브리드) 형태를 재검토한다.
그 전에는 PWA 단일 형태를 유지한다.
