## 배경 (Context)

오늘이 8/31 이고 리허설 구간의 첫날이다.
본선은 9/2 이므로 남은 것은 리허설이지 구현이 아니다.

이 상황에서 Backend 가 발표 전 범위를 여섯 항목으로 정리해 왔다.
그 여섯은 대부분 **새로 좁히는 결정이 아니라 이미 그런 상태**다.
문제는 그 상태가 어디에도 확정으로 적혀 있지 않다는 것이고,
그래서 본선에서 같은 질문을 받으면 답이 사람마다 갈린다.

착수 시점에 확인한 상태는 다음과 같다 - `확실한 사실`,
아래 위치를 직접 열어 확인했다.

| 항목 | 현재 상태 | 확인 위치 |
|---|---|---|
| 경로 코어 | 있다. R2/R3 링크 제거 후 최단 탐색, 후보 재선정, "경로 없음" 상태까지 | `backend_core/route_engine.py` 251행 |
| 경로 배선 | 없다. 이 모듈을 부르는 코드가 모듈 자신과 그 테스트뿐이다 | 저장소 전체 검색 |

### 코드에 있는 것과 화면에 나오는 값은 다른 문장이다

이 문서의 초안은 "대피소 정보는 실제 응답"이라고 적었다.
[PR 232](https://github.com/team-savers/savers-project/pull/232) 리뷰에서 그 근거가 무너졌고,
확인 결과 **발표용 배포본은 목 어댑터로 돌고 있다** - `확실한 사실`,
2026-08-31 에 배포본 번들을 받아 확인했다.
`http.ts` 의 경로 상수(`/v1/shelters/search` 등)가 번들에 0건이고 목 픽스처가 들어 있다.
어댑터 선택이 빌드 시점에 목으로 접히면서 HTTP 분기가 통째로 빠진 모양이다.

그래서 갈라 적는다.
[PR 226](https://github.com/team-savers/savers-project/pull/226) 이
대피소 검색과 행동 이벤트를 실제 API 에 붙인 것은 사실이고 그 코드 경로는 저장소에 있다.
그러나 **발표 화면에 나오는 값은 지도와 대피소 정보 모두 고정 시나리오 데이터**다.
"구현돼 있다"와 "화면에 나온다"를 한 문장에 섞으면 발표에서 반증당한다.

반대로 "침수 회피 경로를 구현했다"도 틀린다.
부르는 API 도, 계약의 경로 스키마도, 링크에 등급을 붙이는 데이터도 없다.

그래서 이 문서가 고정하는 것은 범위만이 아니라 **그 범위를 말하는 문장**이다.

### 프리즈는 이미 지났다

[역할_일정/00-overall.md](../역할_일정/00-overall.md) 26행이 코드 프리즈를 8/29 로 적고,
203행이 그 뒤를 "기능 추가 금지, 시연 경로 버그 수정만"으로 적었다.
선언 권한은 Tech Lead 다.

그런데 프리즈 뒤에 코드가 이미 셋 들어갔다 - `확실한 사실`,
2026-09-01 에 병합 시각을 직접 확인했다.

| PR | 병합 | 내용 |
|---|---|---|
| 220 | 8/30 09:24 | OSMnx 침수 안전 경로 core |
| 231 | 8/31 20:27 | 대피소 전량 제외 E2E |
| 215 | 8/31 22:53 | FCM 실발송, 폐루프 배선, 세션 DB 볼륨 (이슈 181) |

셋 다 시연 경로 버그 수정이 아니므로 203행의 문구대로면 들어갈 수 없는 것들이다.
프리즈 선언이나 연기 기록은 저장소 어디에도 없다 - `불확실`,
채팅 기록까지는 확인하지 못했다.

세 건의 성격은 같지 않다.
220 과 231 은 발표 전 백엔드 작업으로 제시된 항목이고,
215 는 8/29 로 잡혀 있던 시연 환경 배포를 성립시키는 인프라 배선이다
([ADR-0023](0023-explicit-push-channel-selection.md) 후속 조치, 이슈 181).
**셋을 소급해 무효로 만들지는 않는다.**
되돌리는 쪽이 시연 환경을 더 흔들고, 그중 하나는 배포 자체의 선행 조건이다.

**범위만 적고 이 항목을 비워 두면, 이 문서가 프리즈 규정을 조용히 무효로 만든다.**
그래서 결정 6번이 프리즈를 유지한 채 예외를 명시하는 형태로 들어간다.

## 결정 (Decision)

1. **현재 배포본을 시연 기준으로 고정한다.**
   발표 전에 실제 연동으로 전환하지 않고 재배포도 하지 않는다.
   따라서 화면 값은 지도와 대피소 정보 모두 고정 시나리오 데이터다.
   **"대피소 정보는 실제 응답"이라고 말하지 않는다.**
   말하는 방식은 이렇게 셋으로 나눈다 -
   HTTP 어댑터의 코드 경로는 구현돼 있고,
   발표용 배포 화면은 고정 시나리오 데이터를 쓰며, 지도 역시 도식이다.
   **표기를 위한 프론트 변경도 넣지 않는다.**
   지금은 스크린리더 라벨에만 "예시 경로"가 있고 눈에 보이는 표기가 없어
   범례의 "회피 경로"와 "차단 구간"을 계산 결과로 읽을 여지가 있으나 - `높은 신뢰`,
   그 표기는 화면이 아니라 **발표와 시연 대본**에서 먼저 밝히는 것으로 대신한다.
   프리즈 예외를 프론트와 배포까지 넓히지 않는 쪽을 고른 것이다
   (2026-08-31 김도혁,
   [PR 232](https://github.com/team-savers/savers-project/pull/232) 코멘트).
2. **경로 엔진의 배선은 발표 전 범위 밖이다.**
   네 가지다 - 경로 API, 파이프라인 연결, 프론트 연결,
   그리고 edge geometry 기반 경로선 렌더링.
   화면에 경로가 그려지지 않는다는 사실은 감추지 않고 발표에서 먼저 밝힌다.
3. **범위 밖인 것은 배선이지 코어가 아니다.**
   경로 코어 작업은 결정 6번의 제한 안에서 계속한다.
   PR 230 의 스냅샷 로더가 여기 해당한다.
   이 구분을 적지 않으면 결정 2번과 결정 6번이 서로 어긋나 보인다.
4. **600초는 공식 안전 기준이 아니라 운영 파라미터다.**
   설명할 때 세 가지를 함께 말한다.
   (1) 경로가 아니라 **대피소 검색**의 도달 시간 주의 임계값이다.
   직선거리와 보행 속도로 계산하며 경로 계산과 무관하다.
   (2) 후보를 **제외하지 않고 주의만 붙인다**
   ([ADR-0016](0016-shelter-cautions-not-exclusion.md) 결정 1).
   (3) **좌표 기준 검색에서만 붙는다.**
   현재 발표 화면은 등록 행정동으로 검색하므로 이 주의가 표시되지 않는다.
   "신림동 시연 값"이라는 표현은 쓰지 않는다 - 전역 기본값이고
   `SAVERS_EVAC_TIME_LIMIT_S` 로 덮어쓰는 값이다.
5. **비지정 건물 추천은 발표 전 범위 밖이다.**
   건축물대장만으로 안전성을 확정하지 않는다.
   검증된 후보 데이터, 별도 안전 조건, 외부 승인, 매칭 로직이
   갖춰지기 전에는 넣지 않는다.
   이 결정은 부합도 모델의 출력 라벨 규칙
   ("서울시 지정기준 부합도"로 적고 "부적합"으로 적지 않는다) 과 같은 방향이며,
   그 규칙을 넓히거나 좁히지 않는다.
6. **코드 프리즈는 8/29 자로 유지하고, 그 뒤 코드 병합은 세 건으로 제한한다.**
   여기서 세는 것은 **새로 착수하는 작업**이고 셋이 전부다 -
   (1) PR 230 리뷰 대응, (2) 대피소 전량 제외 E2E 보강 (PR 231),
   (3) 시연 회귀검증.
   **시연 경로 버그 수정은 이 셋과 별개로, 개수 제한 없이 계속 받는다** -
   프리즈 규정 자체가 그것만 남겨 둔 것이므로 여기서 좁히지 않는다.
   그 밖의 코드 변경은 받지 않는다.
   **이 제한이 걸리는 것은 이 문서 이후의 새 착수다.**
   프리즈와 이 문서 사이에 이미 병합된 셋(PR 220, 231, 215)은 배경에 사실대로 적었고
   소급해 무효로 만들지 않는다.
   문서와 ADR PR 은 프리즈 대상이 아니다 - 프리즈 규정의 대상은 코드다.
   **프리즈 뒤에 병합한 것은 시연 환경에 자동으로 반영하지 않는다.**
   재배포하면 그때 시연 회귀검증을 다시 돌린다.

근거는 넷이다.

- **범위를 줄이는 결정이 아니라 이미 그런 상태다.**
  배경의 표가 그것이고, 이 문서가 하는 일은 그 상태에 번호를 붙이는 것이다.
  ADR 번호가 없는 항목은 이 저장소에서 검토 중이므로
  ([AGENTS.md](../../AGENTS.md) `Collaboration / Git`),
  지금은 발표에서 같은 질문에 사람마다 다른 답이 나갈 수 있다.
- **과소 진술과 과대 진술이 둘 다 손해다.**
  "대피소 정보는 실제 응답이다"는 배포본 번들을 열면 그 자리에서 반증되고,
  "침수 회피 경로를 구현했다"도 저장소를 열면 반증된다.
  반대로 "전부 mock 이다"는 실제로 붙어 있는 어댑터 코드 경로를 지운다.
  그래서 결정 1번이 코드와 화면을 갈라 말하는 문장 셋을 고정한다.
  발표에서 반증당하는 쪽이 훨씬 비싸다.
- **600초는 지금 화면에 뜨지도 않는다.**
  좌표 기준에서만 붙는 값을 안전 기준으로 설명하면,
  "그럼 지금 화면 어디에 보입니까"에서 무너진다.
  기획서, 구현_범위, 아키텍처 어디에도 600초를 기준으로 적은 문장이 없다 -
  `확실한 사실`, 세 문서를 검색했다.
- **프리즈를 조용히 넘기면 프리즈가 규정이 아니게 된다.**
  다음에 무엇을 더 넣자는 요청이 왔을 때 거절할 근거가 사라진다.
  예외를 적는 쪽이 예외를 못 본 척하는 쪽보다 싸다.

### 검토하고 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| 여섯 항목을 ADR 하나에 담는다 | 유효기간이 다르다. 범위 동결은 본선 후 폐기되고 경로 폴백 설계는 남는다. 한 파일이면 폐기 표시가 살아 있는 결정까지 덮는다 |
| 발표 전에 경로를 화면까지 붙인다 | 계약, 등급 데이터, 배선이 모두 없다. 남은 시간은 리허설 구간이고, 00-overall.md 88행이 여기에 개발을 밀어 넣지 말라고 못박았다 |
| 지도 도식을 지우고 대피소 카드만 남긴다 | 화면이 비고 발표에서 보여줄 것이 없어진다. 도식은 설계 설명으로는 정확하다. 문제는 표기이지 존재가 아니다 |
| 600초를 안전 기준으로 설명한다 | 근거 문서가 없다. 기획서에도 구현_범위에도 아키텍처에도 그런 문장이 없다 |
| PR 230 을 본선 이후로 미룬다 | 리뷰가 이미 진행 중이고, 배선이 0곳이라 시연 경로 동작에 닿지 않는다. 다만 병합 자체는 프리즈 예외이므로 결정 6번에 명시한다 |
| 발표 전에 어댑터를 실연동으로 돌리고 재배포한다 | 프리즈 예외가 프론트와 배포까지 넓어지고, 리허설 구간에 재배포와 회귀검증이 들어간다. 2026-08-31 에 Backend 가 하지 않기로 정했다 (#232 코멘트) |
| 화면 표기 한 줄만 넣고 재배포한다 | 표기 한 줄도 프론트 변경이고 재배포를 부른다. 대본 고지로 같은 목적을 달성하면서 프리즈를 건드리지 않는다 |
| 코드 프리즈를 8/31 로 옮긴다 | 리허설 구간을 구현 구간으로 바꾸는 것이다. 00-overall.md 가 그 16시간을 손대지 말라고 적었다 |
| 프리즈 항목을 이 문서에서 빼고 일정 문서에만 둔다 | 이 문서가 허용하는 세 건이 곧 프리즈 예외다. 허용과 예외를 다른 문서에 두면 둘이 다른 말을 한다 |
| 프리즈 뒤에 이미 병합된 셋(PR 220, 231, 215)을 되돌린다 | 되돌리는 쪽이 시연 환경을 더 흔든다. 215 는 시연 환경 배포 자체의 선행 조건이라 되돌리면 배포가 서지 않는다. 대신 배경에 사실대로 적어 문서가 반증되지 않게 한다 |

## 결과 (Consequences)

**긍정**

- 본선에서 나올 질문 셋에 댈 문서가 생긴다 -
  경로가 화면에 없는 이유, 600초의 성격, 비지정 건물을 넣지 않은 이유.
- 발표자 세 사람의 범위 설명이 한 문장으로 맞는다.
- 프리즈가 규정으로 남는다. 예외가 셋이고 그 셋이 적혀 있다.
- 결정 3번이 있어 Backend 의 코어 작업이 결정 2번과도, 결정 6번과도 충돌하지 않는다.

**부정 / 완화**
