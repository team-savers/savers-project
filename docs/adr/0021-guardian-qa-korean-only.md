## 배경 (Context)

계약의 `Profile.language` 는 `ko` `vi` `zh` `en` 네 값을 열거하고 있다.
이것은 공개 재난안전데이터 API 의 지원 언어가 아니라
대리 등록 시점에 보호자, 복지관, 고용주가 고르는 프로필 값이다.
반면 보호자 응답 Q&A (Guardian RAG) 의 답변 생성은 한국어 기준으로만 만들어져 있었고,
본선 데모에서 네 언어를 다 지원할지 확인이 필요했다.

**계약과 코드는 이 합의를 이미 받았다.**
[PR #134](https://github.com/team-savers/savers-project/pull/134) 가
`GuardianAskRequest.locale` 을 `enum: [ko]` 로 좁혔고,
`backend_core/models.py` 의 `GuardianLocale` 은 `Literal["ko"]` 다.
이 PR 은 2026-08-26 15:07 에 머지됐고, 회의록 PR #138 은 같은 날 17:02 다.
회의록이 "계약 문구 정정을 후속 과제로 넘긴다" 고 적은 시점에
그 정정은 이미 한 시간 55분 전에 끝나 있었다.

남은 것은 기록뿐이다.
저장소 규칙상 ADR 번호가 없는 항목은 확정이 아니라 검토 중이므로,
회의록은 스스로를 "검토 중, ADR 미발행" 으로 표기해 왔다.
그 사이 구현은 이 합의를 전제로 진행됐다.

## 결정 (Decision)

1. **본선 데모의 보호자 응답 Q&A 답변 생성 언어는 한국어 하나다.**
   `GuardianAskRequest.locale` 의 허용값은 `ko` 뿐이고 목록 밖 값은 422 다.
   **한국어 폴백을 두지 않는다.**
   폴백이 성립하려면 요청한 언어와 실제 생성 언어가 다르다는 사실을 화면이 알아야 하는데,
   `GuardianAnswer` 에 그것을 실을 자리가 없다.
   다국어를 열 때 실제 생성 언어를 응답에 함께 싣고, 그때 이 열거를 넓힌다.
2. **다국어는 3 ~ 6개월 추진계획으로 옮기고 영어 -> 중국어 -> 베트남어 순으로 확대한다.**
   네 언어를 한 번에 넣지 않는다.
   영어가 1순위인 근거는 규모가 아니라 공용 폴백이라는 성격이다 -
   공통 모국어가 없는 다국적 체류자를 한 언어로 가장 넓게 덮고,
   안전 검증 자산이 가장 성숙해 검증기 확장 위험이 가장 낮다.
   중국어가 베트남어보다 앞서는 근거는 규모다 -
   법무부 체류외국인 통계 (2025년 12월 말) 에서 중국 국적자가 베트남 국적자보다 많다.
3. **이 결정의 범위는 보호자 Q&A 답변 생성뿐이다.**
   UI 문구, 등록 화면의 언어 선택, 프로필 언어 값,
   국민행동요령 코퍼스 챗봇의 출력 언어는 이 결정이 건드리지 않는다.
   계약에 남아 있는 `[ko, vi, zh, en]` 네 곳 -
   `Profile.language`, `ChatRequest.locale`, `RecipientContext.language`, `AnswerRequest.locale` -
   은 이 결정의 대상이 아니다.
   **그 넷을 좁히는 것은 이 ADR 의 이행이 아니라 새 결정이며, 별도 ADR 이 필요하다.**
4. **확대 착수 시점에 `i18n.ts` 의 기존 `vi` 자산을 재활용할지 순서대로 새로 만들지를 착수 전에 정한다.**
   정하는 사람은 신호정 (Tech Lead) 과 김소원 (AI/RAG) 이다.

근거는 셋이다.

- **비용이 답변 생성에서 끝나지 않는다.**
  보호자 응답은 세션 이벤트 로그를 옮겨 적는 결정적 문안이고,
  검증기가 문장을 주장 단위로 쪼개 로그와 1:1 로 대조한다 (ADR-0012 2절).
  언어를 하나 늘리면 생성만이 아니라 그 대조를 언어마다 다시 만들어야 한다.
  남은 구현 시간은 1인당 52시간이다.
- **거절이 폴백보다 정직하다.**
  요청한 언어와 다른 언어로 답이 돌아왔다는 사실을 화면이 알 수 없다면,
  그 폴백은 사용자에게 조용한 오해로 도착한다.
  이 프로젝트는 대체된 것을 감추지 않고 드러내는 쪽을 택해 왔다.
- **UI 를 함께 좁힐 이유가 없다.**
  UI 문구는 이미 한국어와 베트남어 완역본이 있어 없앨 비용 이득이 없고,
  없애면 데모 시드 `p002` (Nguyen Van A, `registered_by: employer`, `language: vi`) 의
  베트남어 화면 경로가 사라진다.
  외국인 노동자 언어 장벽은 이 서비스가 내세운 대상 문제 자체다.

## 결과 (Consequences)

**긍정**

- 계약과 코드가 이미 이 모양이라 이 결정으로 고칠 구현이 없다.
- 검증기를 언어별로 늘리지 않아 M2 (보호자 응답 정확도) 의 확장 위험이 생기지 않는다.
- 외국인 노동자 페르소나의 UI 다국어 시연은 그대로 남는다.
- 확대 순서가 정해져 있어, 본선 이후 착수 시 순서를 다시 논의하지 않는다.

**부정 / 완화**

| 리스크 | 완화 | 상태 |
|---|---|---|
| 한국어를 못 읽는 보호자는 Q&A 답변을 읽지 못한다 | 본선 데모 범위에서 수용한 한계다. 화면 문구 자체는 `vi` 완역본이 있어 읽힌다 | 수용 |
| 계약에 남은 네 언어 열거가 다국어 지원 약속으로 읽힌다 | 계약이 해당 자리에 "화면 언어를 그대로 실어 보내면 422" 를 이미 적어 두었다 | 계약 v0.10 |
| 확대 순서 (영어 -> 중국어 -> 베트남어) 가 이미 구현된 UI 자산 순서 (`ko` -> `vi`) 와 반대다 | 2026-08-25 대화에서 이 불일치를 확인하고 순서를 그대로 유지하기로 했다. 자산 재활용 여부는 결정 4번으로 넘긴다 | 명시함 |
| 이 ADR 이 등록 화면 언어 선택 제거의 근거로 인용된다 | 결정 3번이 범위를 못박는다. 등록 화면은 이 결정의 대상이 아니다 | 명시함 |
| 회의록의 "알려진 불일치" 절이 해소된 사실을 계속 미해소로 전한다 | 이 PR 에서 정정한다 (후속 조치 1번) | 이 PR |
