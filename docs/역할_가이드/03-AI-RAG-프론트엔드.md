# AI 모델 · RAG · 프론트엔드 역할 매뉴얼

> **2026-08-11 개정.** 팀 재편(6인 → 4인)으로 옛 `04-프론트엔드-UX.md`(Frontend/UX)가  
> 이 문서에 흡수됐습니다. AI/RAG와 프론트엔드는 이제 한 사람(김소원)이 겸하므로,  
> 아래 각 절을 **AI/RAG**와 **프론트엔드** 하위 항목으로 나눠 두되 원문 내용은 그대로 보존합니다.

## 담당 범위

**AI/RAG** — 국민행동요령 전처리·청킹, Chroma 구축·인덱싱, 시맨틱 검색 정교화, 근거 일치율 측정.  
모듈 2(Advanced RAG 파이프라인)의 실무 구현을 책임집니다.

**프론트엔드** — PWA·웹푸시(FCM) 연동, 대화형 챗봇 UI/UX, 접근성(다국어·쉬운 글·음성) 구현, 가독성 지표 계측.  
모듈 4(무설치 사용자 터미널)의 실무 구현을 책임집니다.

**1차 알림 채널은 PWA 웹푸시(FCM)이고, 카카오 알림톡은 채택하지 않습니다**(→ [ADR-0005](../adr/0005-webpush-primary-channel.md)).  
예선 한정이 아니라 도입 여지 자체가 없습니다 — 알림톡은 사전 승인된 고정 템플릿 + 변수 치환이 원칙이라  
매번 달라지는 생성 문안을 그대로 실어 보낼 수 없고(설계 충돌, 일차 사유),  
발신 프로필이 사업자등록 기반 비즈니스 인증을 요구해 팀에 확보 경로가 없습니다(자격 요건, 이차 사유).

프론트엔드 배포 형태는 **PWA(웹)로 확정**되어 있으며 네이티브·하이브리드는 제외입니다(→ [ADR-0004](../adr/0004-pwa-over-native.md)).  
"무설치 사용자 터미널"·"당사자 설치 부담 없음" 원칙과 정합하고,  
웹푸시 알림의 딥링크 → 브라우저 진입 → 위치 1회 확인 흐름이 웹 권한 모델과 일치하기 때문입니다.  
네이티브의 유일한 이점(백그라운드 위치)은 "상시 추적 금지" 원칙상 우리가 써서는 안 되는 기능이라 메리트가 없습니다.  
권장 스택은 **React + Vite + `vite-plugin-pwa`(Workbox 기반 SW/오프라인 캐싱)** 입니다.

## 직접 구현해야 하는 부분

### AI/RAG

- **청킹 전략** — 국민행동요령 문서 특유의 구조(재난유형별 항목, 단계별 행동요령)를 반영한 분할 규칙.  
    범용 텍스트 스플리터를 그대로 쓰면 문맥이 끊겨 검색 품질이 떨어지므로,  
    도메인에 맞는 청크 경계·오버랩 전략을 직접 설계해야 합니다.
- **재난유형 + 취약계층 프로필 조건부 검색 로직** — 단순 유사도 검색이 아니라  
    메타데이터 필터(재난유형, 프로필)와 시맨틱 검색을 결합하는 세이버스 고유 검색 로직.
- **근거 일치율 측정 스크립트** — 생성 메시지와 원문 대조 채점 로직, 평가셋(30~50건) 설계·구축.
- **평가셋 확장 계획** — [리스크.md](../공통_가이드/리스크.md) ⑥에서 지적된 "평가셋이 통계적으로 작다"는 문제에 대응해,  
    최소한의 신뢰구간을 가질 수 있는 표본 설계.

### 프론트엔드

- **Interactive Care 챗봇 대화 흐름/의도 분기 로직** — 사용자가 "도움"이라고 답장하는 등 추가 질의에 응답하는 시나리오는 세이버스 고유 설계이며,  
    오픈소스 챗봇 UI는 뼈대만 제공할 뿐 흐름 자체는 직접 만들어야 합니다.
- **접근성 통합 UX** — 쉬운 글 표시 + 음성 재생 버튼 + (필요시) 원문 대조 화면을 하나의 사용자 경험으로 엮는 작업.  
    개별 기능(TTS, 번역)은 외부 API지만, 조합 방식은 취약계층·외국인 근로자 각각의 사용성을 고려해 직접 설계해야 합니다.
- **가독성 지표 계측 훅** — 행정용어 치환율, "실행 가능한 단일 행동" 포함 여부를 프론트엔드 단에서 로깅하거나 검증할 수 있는 계측 지점.
- **생성 문안 무변형 렌더링** — 생성된 본문을 **한 글자도 바꾸지 않고** 화면에 올립니다.  
    ⚠️ **템플릿 슬롯 치환 계층(렌더링 어댑터)을 만들지 마세요.** [ADR-0005](../adr/0005-webpush-primary-channel.md)가  
    폐기하며 재도입하지 않는다고 명시한 계층입니다 — 슬롯에 끼우는 순간 채점한 문안과 도달한 문안이  
    달라져 근거 일치율·메시지 명확성 지표의 의미가 훼손됩니다.  
    프론트가 본문에 대해 하는 유일한 개입은 **표시 여부 판단**입니다: 근거를 주장하는 본문에  
    인용이 없으면 본문을 숨깁니다(계약 불변식). 쉬운 글·음성·번역은 원문을 대체하지 않고 **덧붙이는** 층입니다.
- **웹푸시 알림 진입 랜딩(딥링크 → 개인화 페이지)** — 발송은 백엔드가 FCM Admin SDK로 처리하므로,  
    프론트는 푸시 페이로드의 딥링크로 진입해 세션 토큰을 받고 개인화 페이지를 렌더하는 랜딩이 핵심입니다.  
    ⚠️ **알림의 액션 버튼에 의존하지 마세요.** 플랫폼별 최대 2개 제한이 있어 신뢰할 수 없으므로,  
    **[집이에요]/[밖이에요] 분기는 랜딩 첫 화면**에서 수행합니다(ADR-0005).  
    위치 권한 거부·실패 시 **등록 행정동 기반 매칭으로 degrade**(단일 실패점이 되지 않도록)하는 UX도 여기서 처리합니다.

## 기능 통합이 필요한 부분

### AI/RAG

- **Chroma 벡터 DB** — 오픈소스 그대로 배포·운용, 자체 벡터 DB를 만들 필요 없음.
- **임베딩 모델** — HyperCLOVA X Embedding API 또는  
    공개 한국어 임베딩 모델(BGE-M3, KURE, BGE-m3-ko, multilingual-e5 등 최신 세대)을 그대로 통합.
- **문서 파싱** — 국민행동요령이 PDF/HWP 형태일 경우 PyMuPDF, pdfplumber, pyhwp 등 기존 라이브러리로 파싱 자체는 해결하고,  
    파싱 후 구조화(섹션 인식)만 직접 구현.
- **텍스트 스플리터 뼈대** — LangChain의 RecursiveCharacterTextSplitter 등을 베이스로 사용하고, 그 위에 도메인 특화 규칙만 추가.
- **RAG 평가 프레임워크(RAGAS 등)** — 근거 일치율/환각 측정의 기본 계측 로직을 가져다 쓰고, 세이버스 지표 정의만 커스터마이즈.

### 프론트엔드

- **PWA 서비스워커/오프라인 캐싱** — Workbox 등 기존 라이브러리로 상당 부분 대체 가능.
- **웹푸시 인프라** — Firebase Cloud Messaging(FCM) 통합. 이것이 **1차 채널이고 대체 채널이 없습니다.**  
    ⚠️ iOS Safari 제약(16.4+ **및** 홈 화면 추가 상태에서만 웹푸시 동작)에는 **우회로가 없습니다** —  
    알림톡 1차로 비켜 가는 구조가 사라졌기 때문입니다(ADR-0005).  
    그래서 시연 환경을 **안드로이드·데스크톱 크롬으로 고정**하고, iOS는 대리등록 절차에 A2HS 안내를 포함합니다.  
    A2HS를 **대리등록자가 수행**하면 "당사자 설치 부담 없음" 원칙은 지켜집니다 — 당사자가 스스로 해야 하는  
    상황이 생기면 그 시점에 원칙이 침식되므로 대리등록 흐름 설계에서 흡수해야 합니다.
- **첫 접촉 경로(대리등록)** — 웹푸시는 전화번호만으로 도달하지 않고 **사전에 브라우저에서 FCM 토큰을 등록**해야  
    첫 알림이 갑니다. `/ops` → QR → `/join` 흐름이 그 경로이고, 당사자가 하는 행위는 QR 스캔과 알림 허용 탭뿐입니다.  
    ⚠️ 등록을 **생성**하는 API는 아직 계약 밖이고 임시 저장소에 접근 인증이 없습니다  
    (→ [후속_과제.md](../공통_가이드/후속_과제.md) 3·4번).
- **TTS** — 클로바보이스, Google TTS 등 외부 API 통합.
- **번역** — 파파고 API, Google Cloud Translation 등 외부 API 통합.
- **채팅 UI 컴포넌트** — 오픈소스 채팅 UI 라이브러리로 뼈대 구성, 로직만 직접 연결.

## 다른 역할과의 인터페이스

| 받는 것 | 역할 | 주는 것 |
|---|---|---|
| 국민행동요령 원문 데이터 | (외부 공공 데이터) | 청킹·인덱싱된 검색 API |
| 검색 조건 입력 스키마 | Tech Lead | 검색 결과(근거 문단 + 출처) |
| 생성된 페르소나별 메시지 | Tech Lead | 렌더링/발송 결과, UX 피드백 |
| 위험구역·대피소 거리 정보(표시용) | Backend | 알림 화면 요구사항 |
| 웹푸시 발송 결과·세션 토큰 | Backend | FCM 구독 토큰 등록(`/v1/devices`) |
| 근거 일치율·가독성 지표 실측치 | PM | 평가 결과 리포트, UX 데모 시나리오 조율 |
| 가드레일 검증용 테스트 케이스 | PM (QA/보안 겸임) | 근거 일치율 채점 스크립트 공유 |

> AI/RAG와 프론트엔드가 이제 한 사람이므로, 옛 03↔04 사이의 상호 인터페이스 행  
> ("생성된 메시지"를 AI/RAG가 만들어 프론트엔드가 받던 흐름 등)은 내부 작업 순서로 흡수되어 표에서 뺐습니다.

## 관련 리스크

- **⑥ 목표 수치의 근거 박약** — 평가셋·채점 방법론의 엄밀성, 그리고 메시지 명확성 지표(치환율 등)가 이 역할에 달려 있음.  
    가독성 자동 채점 결과가 목표에 못 미칠 경우 UI 표시 로직으로 보완할 수 있는지 확인.
- **⑦ 교차 채점 모델 선정 미정** — 생성 모델과 다른 채점 모델을 조기에 확보해야 함.
- **② 안전 관련 오작동** — 검색 품질(청킹·필터링)이 나쁘면 가드레일이 아무리 강해도 잘못된 근거를 인용할 수 있음.
- **알림 권한 거부** — 알림톡에는 없던 **새 실패 모드**이고, ADR-0005에 `⚠️ 미해결`로 남아 있습니다.  
    거부 시 대체 도달 경로가 **없습니다.** 프론트가 지켜야 하는 완화는 하나 — 권한 요청을 페이지 로드 즉시  
    띄우지 않고 **사용자 제스처에서만** 수행합니다. 한 번 거부되면 브라우저가 다시 묻지 않기 때문입니다.
- **iOS 웹푸시 제약** — iOS 16.4+ **및** 홈 화면 추가(A2HS) 상태에서만 동작합니다.  
    ADR-0004 시점에는 "알림톡 1차로 우회"한다고 적혀 있었으나 **그 우회로가 사라져 제약이 승격됐습니다.**  
    실기기 검증이 필요하고, 그 전제는 배포본 준비 상태입니다 —  
    HTTPS·도달성·Firebase 앱 config·VAPID·서비스워커·매니페스트를 먼저 확인합니다.

`리스크.md`의 번호는 재작성 예정이라([이슈 #38](https://github.com/team-savers/savers-project/issues/38))  
채널 리스크 두 항목(알림 권한 거부·iOS 제약)은 여기서 번호로 참조하지 않습니다.

## 관련 외부 승인

- **A. 국민행동요령 원문 활용 허가** — 공공저작물 자유이용허락(제1~4유형) 표시와 출처 표기 의무를 소스별로 확인해야  
    청킹·인덱싱 대상 원문을 확정할 수 있음. 코퍼스 구축의 선행 조건.
- **D. HyperCLOVA X Embedding API** — 임베딩을 외부 API로 쓸 경우 NCP 계정·이용 신청이 필요  
    (공개 한국어 임베딩 모델로 대체하면 이 의존 없이 진행 가능).  
    교차 채점(⑦)용 별도 모델의 계정·API 한도도 초반에 함께 확보.
- **C. 웹푸시(FCM) 발신 설정** — **1차 채널**의 발신 설정입니다.  
    웹푸시에는 발신 전 외부 심사가 없어 이 항목은 더 이상 최장 리드타임이 아닙니다(ADR-0005).  
    남은 것은 심사가 아니라 계정·콘솔 작업입니다 — Firebase 프로젝트 소유권, 앱 config 6종 주입,  
    그리고 **재배포**(Vite는 `VITE_*`를 빌드 시점에 번들에 박으므로 값만 넣으면 반영되지 않습니다).
- **HTTPS 배포처** — 웹푸시는 localhost 외에 HTTPS가 필수라, 배포처가 없으면 실기기 검증 자체가 불가능합니다.  
    프론트는 정적 호스팅으로 나갑니다(→ [ADR-0008](../adr/0008-frontend-static-hosting.md)).
