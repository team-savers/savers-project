## 담당 범위

- **AI 모델** — 대피소 부합도 모델 학습·검증, SHAP 기여도
- **RAG** — 보호자 상황 확인 RAG의 **생성부 + 로그 1:1 대조 검증기**
- **프론트엔드** — 보호자 화면·Q&A 블록 UI, 시연 사용자 화면 5종
  <br>※ **신호등 UI와 시연 화면 비주얼·문구는 PM이 가져갔습니다**(2026-08-21) — 이 포지션의 버퍼가 0이라서입니다.
  소관은 이 포지션이되 **구현은 PM**, 이 포지션은 데이터 연결만 합니다.

**생성과 검증이 한 흐름이라 한 사람이 함께 소유합니다.**
검증기는 생성부의 사후 필터가 아니라, "무엇을 근거로 말할 수 있는가"를 정의하는 같은 문제의 뒷면입니다.
프론트가 여기 붙은 것도 같은 이유입니다 — 부합도 점수와 SHAP 기여도를 화면에 어떻게 드러내느냐가
모델의 설명 가능성 주장을 완성합니다.

> ⚠️ **이 포지션의 일정에는 버퍼가 없습니다.** (2026-08-21 갱신)
> 구현 창구 52시간에 확정 48h + 조건부 4h가 들어 있어 **여유가 정확히 0**입니다.
> 압축 카드는 이미 다 썼습니다 —
> **「기타」 자유질문은 뺐고**(추천 3버튼 + 「확인할 수 없습니다」 폴백만),
> **SHAP은 지도 클릭 대신 고정 카드 3장**으로 되돌렸으며,
> **부합도 검증은 3겹 → 2겹**입니다.
> 남은 조건부는 **SHAP 하나(컷오프 8/28 저녁)**이고, **판정은 PM이 합니다.**
> 한 칸이라도 밀리면 SHAP이 자동으로 날아갑니다 — **막히면 그날 저녁에 PM에게 알리십시오.**

## 직접 구현해야 하는 부분

### ① 대피소 부합도 모델

- **라벨과 피처의 분리** — 절대 원칙입니다.
  서울 전용 데이터(수해대피소 지정 목록·침수예상도)는 **정답과 검증에만** 쓰고,
  모델 입력은 표고·대피 여유고·지하층수·하천 최단거리처럼 **전국 공통 공개 데이터 13개**로만 구성합니다.
  이 분리가 깨지면 "목록 없는 16개 시·도에 적용한다"는 주장이 통째로 무너집니다.
- **spy 기법 PU 학습** — 미분류 데이터에 정답 일부를 위장해 섞고,
  그보다 정답 같지 않은 데이터만 신뢰 negative로 학습합니다. 구현은 LightGBM 기반.
- **3겹 검증** — ① 자치구 GroupKFold 공간 블록 교차검증
  ② 비(非)학교 대피소 recall@top-20% (주지표) ③ 침수예상도 베이스라인 대비 lift.
  기획서 [표3]의 4겹 중 **④ 문자열·표준필드·모델 3자 비교는 본선 범위에서 생략**하며,
  3겹 기준임을 [표3]에 명시합니다.
- **결과가 규칙 기반(2차)을 넘지 못하면 그대로 실패 사례로 기재합니다.**
  규칙으로 되는 일을 모델로 포장하지 않는 것이 이 팀이 지키는 선입니다.
- **SHAP 기여도** — 지도 위 임의의 점을 클릭하면 부합도 점수와 상위 기여 인자가 뜹니다
  (「대피 여유고 0m 미만 −0.31, 하천 최단거리 140m −0.22」 형태).
  출력 라벨은 **「서울시 지정기준 부합도」** 이며, 미지정이 곧 부적합은 아니므로 **「부적합」이라 단정하지 않습니다.**

### ② 보호자 상황 확인 RAG — 생성부와 검증기

- **이벤트 로그 스키마 초안** — 기존 `SessionStore`에 `events` 배열을 얹는 형태이지 신설이 아닙니다.
  Tech Lead 리뷰와 Backend의 로그 API가 둘 다 이것을 기다리는 **전체의 단일 출발점**이므로 최우선으로 냅니다.
- **생성부(추천 3질문)** — 그 세션의 로그 전량을 컨텍스트로 넣습니다. **벡터 검색은 없습니다.**
  「안전합니다」·「괜찮습니다」는 금지어이고,
  **「무엇이 언제 눌렸다/안 눌렸다」 형태로만** 답합니다 — 챗봇은 로그를 풀어 쓸 뿐 안전 여부를 판단하지 않습니다.
- **로그 1:1 대조 검증기** — 문장을 주장 단위로 쪼개 로그와 대조하고,
  **미대응이 한 건이라도 있으면 문장 전체를 차단**합니다.
  「기타」 폴백 판정도 이 검증기가 겸합니다 — 전부 차단되면 그 상태가 곧 「확인할 수 없습니다」입니다.
  별도 판정기를 만들지 마세요.
- **거절 방향의 기본값** — 애매하면 거절 쪽으로.
  과소거절(로그에 없는데 답함)이 주지표 「로그에 없는 사실 0건」을 직접 깨기 때문입니다.

### ③ 프론트엔드

- **행동 권고 3단계 신호등** — 상황 주시 / 대피 준비 / 즉시 대피.
  특보 등급을 신호등 체계로 바꾸어 「내가 지금 나가야 하는가」의 판단을 돕는 장치입니다.
  색·라벨·전환만 구현하고 애니메이션은 넣지 않습니다.
  **※ 본선 구간에서는 PM이 구현합니다**(이 포지션 버퍼 0). 디자인 결정만 확인해 주세요.
- **SHAP 기여도 표시** — **대표 대피소 3곳의 고정 카드**입니다. 조건부(P2)이고 컷오프는 8/28 저녁.
  지도 클릭 인터랙션은 본선 이후로 미뤘습니다 — 시간이 남으면 되살릴 1순위 후보입니다.
- **Q&A 블록 UI** — **추천 버튼 3개만.** 기타 입력창은 이번 구간에서 뺐습니다.
  기존 `ChatDock` 패턴을 재사용합니다.
- **시연 사용자 화면 5종** — **기존 화면을 고치지 말고 새 라우트를 쓰십시오.**
  고치면 24h, 새로 쓰면 8h입니다. 비주얼·문구는 PM이 맡고, 이 포지션은 데이터 연결을 합니다.
- **모르는 것을 숨기지 않는 표기** — 모든 안내에 판단 시점과 데이터 기준 시각을 답니다
  (「기상청 특보 21:12 기준 / 대피소 정보 21:20 기준」).
  위치 확인 실패 시 「등록하신 동 기준」, 산출 실패 시 「판정 불가」로 적습니다.

## 기능 통합이 필요한 부분

- **LightGBM · SHAP** — 학습·설명 라이브러리는 그대로 씁니다. 직접 구현할 것은 라벨 설계와 PU 구조뿐입니다.
- **지도 렌더링** — 기존 `ShelterMap` 컴포넌트를 확장합니다.
- **Chroma·임베딩** — 국민행동요령 코퍼스 RAG(`apps/ai-engine`의 기존 파이프라인)는 그대로 두되,
  보호자 RAG는 **로그 전량 컨텍스트 방식이라 벡터 인덱스를 쓰지 않습니다.** 둘을 섞지 마세요.
- **채팅 UI 뼈대** — `ChatDock` 재사용. 새 컴포넌트를 만들지 않습니다.
