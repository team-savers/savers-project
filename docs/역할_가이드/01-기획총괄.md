# PM · QA/보안 · 인프라 역할 매뉴얼

담당: 안은남 (팀장) · 일정: [역할_일정/01-기획총괄.md](../역할_일정/01-기획총괄.md)

## 담당 범위

네 갈래를 한 사람이 가집니다.

- **PM** — 전체 마일스톤·통합·리스크, 본선 발표·시연 총괄
- **QA/보안** — 품질·보안 판정. 위치 미저장 검증, 골든셋 관리, 실패 모드 시연 대본
- **인프라** — `infra/`·배포·서버 운영·계측(OTel p95, 위치 미저장 확인)
- **실험·튜닝** — 가드레일 임계값 실험(#84 유사도 하한, #23 SUPPORT_THRESHOLD, #24 과잉거절)

**구현을 하지 않는다는 사실 자체가 QA 자격의 근거입니다.**
자기가 쓴 코드를 자기가 통과시키지 않는 구조라 판정이 독립적입니다.
같은 이유로, 여기서 "실행"과 "판단"을 나눕니다 — 임계값 실험은 PM이 돌리고,
값의 최종 확정은 Tech Lead가 합니다([02-테크리드.md](02-테크리드.md)).

## 직접 구현해야 하는 부분

PM의 "구현"은 대부분 코드가 아니라 **의사결정 도구와 검증 산출물**입니다.
다만 인프라·계측이 이 포지션으로 넘어오면서 **직접 손대는 코드·설정이 생겼습니다.**

- **배포 운영 전 사이클** — SSM 접속 → 배포 명령 → Caddy 확인까지 PM 단독으로 한 바퀴 돌 수 있어야 합니다.
  절차는 [배포_절차.md](../공통_가이드/배포_절차.md)에 있고,
  **8/26에 Backend 없이 혼자** 한 바퀴 돌아 인수를 완료하고, **8/29 시연 환경 배포는 PM 단독**으로 합니다.
  한 사람만 아는 설정이 남으면 본선 당일 장애 때 고칠 사람이 없습니다.
  IAM 역할 생성·정책 부여는 **계정 관리자(PM)만** 가능합니다 — Backend의 `PowerUserAccess`가 `iam:*`을 막습니다.
- **4대 지표 계측·취합** — 알림 도달 30초 / 보호자 응답 정확도(로그에 없는 사실 0건) /
  **위치정보 무저장·무로깅(좌표가 저장·로깅되는 지점 0건)** / 폐루프 2차 발송 성공률 100%.
  세 번째는 원래 「즉시 파기 100%」였으나 `SessionStore`에 파기 메서드가 없어
  **8/21에 「미수신」으로, 8/22에 다시 「무저장·무로깅」으로 바꿨습니다** — `/v1/shelters/search`가
  좌표를 실제로 받기 때문입니다. 근거는 [ADR-0010](../adr/0010-m3-no-storage-not-no-receipt.md)(제안 상태, 검토 중),
  작업 문서는 [정량목표_검증설계.md §3](../공유_문서/정량목표_검증설계.md).
  증명은 `scripts/check_privacy.py`(PR #76)가 맡으며, **머지 후 CI 연결까지가 완료**입니다.
  계측 코드는 이미 있는 OTel 스팬을 그대로 돌리고,
  PM이 만드는 것은 **목표 대비 실측 표**입니다.
  미달 항목은 숨기지 않고 실패 사례로 기재합니다 — 기획서가 그렇게 약속했습니다.
- **위치 무저장·무로깅 검증** — 로그·DB에 원본 좌표가 없음을 스캔으로 확인.
  좌표는 `/v1/shelters/search` 요청 안에서만 쓰이므로(→ [개인정보_체크리스트.md](../공통_가이드/개인정보_체크리스트.md)),
  검증은 "지우는지"가 아니라 **"저장·로깅 지점이 있는지"** 를 확인하는 형태입니다.
- **보호자 응답 골든셋** — 40건(추천 30 + 기타 10).
  기타 10건은 답할 수 있는 것 5 / 없는 것 5로 나누고,
  각 건에 정답·금지 문장·폴백 기대값을 답니다.
  이것이 과잉거절·과소거절 튜닝의 유일한 기준선입니다.
- **실패 모드 시연 대본(5케이스)** — 역대 수상작 대부분이 성공 경로만 보여준다는 점에서 이 팀의 차별점입니다.
  API 장애 → 캐시 / 위치 실패 → 「등록하신 동 기준」 / 가드레일 이탈 → 최소안전문 /
  경로 없음 → 대피소 재선정 / 근거 없는 기타 질문 → 「확인할 수 없습니다」.
- **롤백 절차서** — 1페이지. 문서만 있고 실제로 해본 적이 없으면 본선에서 못 씁니다.
  작성은 PM, **실제 롤백 리허설은 Backend**가 합니다(9/1).
- **리스크 대장·발표 스토리라인** — [리스크.md](../공통_가이드/리스크.md) 항목별 담당자·완화 조치·확인 시점 매핑,
  문제 정의 → 차별화 3축 → B2B/B2G 지속가능성 → 3단계 확산 로드맵.

## 기능 통합이 필요한 부분

- **계측 도구** — OTel 스팬·p95 집계는 이미 붙어 있는 것을 실행만 합니다. 새로 만들지 않습니다.
- **진행 상황 리포팅** — GitHub Issues/Projects를 그대로 씁니다. 별도 대시보드를 만들 필요 없습니다.
- **점검 체크리스트** — 자체 법률 해석 대신 개인정보보호위원회 공개 가이드라인을 매핑해 씁니다
  (→ [개인정보_체크리스트.md](../공통_가이드/개인정보_체크리스트.md)).
- **최종 발표자료** — 각 역할이 내는 다이어그램·수치·시연 화면을 하나의 스토리라인으로 통합.

## 다른 역할과의 인터페이스

| 받는 것 | 역할 | 주는 것 |
|---|---|---|

| 3겹 검증 수치·[표3] 교체본, 데모 시연 | AI/RAG/FE | 골든셋 40건, 과잉·과소거절 튜닝 결과 |
| 「경로 없음」 재선정 동작, CCTV 좌표·스트림 API, 현장 인프라 실행 | Backend | 시드 픽스처 CSV, 롤백 절차서, **인프라 인수 후 단독 배포** |

## 관련 리스크

- **⑧ 일정** — 가장 직접적인 소관. 임계 사슬 셋(보호자 RAG · 부합도 모델 · 경로 안내)이
  AI/RAG와 Backend를 번갈아 지나므로, 한쪽이 밀리면 반대쪽이 대기합니다.
- **② 안전 오작동** — 실패 모드를 사전에 발견하고 시연에서 정직하게 다루는 것이 완화책입니다.
- **⑨ 민감정보** — 암호화·최소수집 원칙의 실제 준수 여부를 검증하는 최종 관문.
- **⑥⑦ 지표 신뢰성** — 심사 대응 논리를 최종 정리해야 하므로 근거 부족 여부를 미리 파악.

## 관련 외부 승인

- **F. 해커톤 행정** — 예선 제출 완료(2026-08-10), **운영사무국 인원 변경 재통보(6인 → 4인)** 와
  참가서약서 원본 확인이 남아 있습니다.
  규정상 명단 탈퇴 처리가 되지 않으므로 통보 기록이 유일한 방어입니다.
- **E. 개인정보/법적 검토** — 처리방침·민감정보 별도 동의 절차 수립과 준수 검증 모두 이 포지션 소관
  (예전에는 PM과 QA 공동이었으나, 두 역할이 합쳐지면서 단독이 됐습니다).
- **A·D (공공 API·클라우드 계정)** — 신청 주체는 Backend지만 상태 추적은 리스크 대장과 함께 PM이 봅니다.
