# Backend 역할 매뉴얼

담당: 김도혁 · 일정: [역할_일정/04-백엔드.md](../역할_일정/04-백엔드.md)

## 담당 범위

침수 회피 경로, **이벤트 로그 파이프라인**(수집·저장·조회), FCM 실발송 재연결,
보호자 2차 발송, 폐루프 오케스트레이션.

폐루프의 검증기와 생성이 **이 로그 위에서** 도는 구조라, 기반을 이 포지션이 소유합니다.

> **인프라는 이 포지션이 아닙니다.** `infra/`·배포·서버 운영·계측은 PM 소관으로 넘어갔습니다
> (→ [01-기획총괄.md](01-기획총괄.md)).
> 다만 **본선 당일 현장 인프라 주(主) 대응은 Backend**입니다 — PM은 무대에 있어 서버를 볼 수 없습니다.
> 그래서 시연 환경 배포는 **PM과 반드시 함께** 하고, 롤백은 문서만 읽지 말고 **실제로 한 번 해봅니다.**

## 직접 구현해야 하는 부분

### ① 침수 회피 경로 — 최단이 아니라 지나갈 수 있는 길

평시 도보시간은 폭우 상황에서 무의미합니다.
OSM 도로망을 그래프로 올린 뒤 **모든 링크에 침수 위험 등급 R0 ~ R3을 붙여 통과 여부를 먼저 정합니다.**
R2(침수심 0.5 ~ 1.0m)·R3(지하차도·하천변) 링크를 제거한 뒤 남은 경로 중 최단을 고릅니다.

> **⚠️ 계산 엔진이 OSRM이 아닙니다 (2026-08-21 결정 — 검토 중, ADR 대기).**
> 본선 구현본은 **OSMnx로 OSM을 읽어 networkx 인메모리 그래프**에 올립니다.
> **바뀌는 것은 엔진 이름 하나뿐**이고 등급 부여·제외·「경로 없음」 폴백은 위 서술 그대로입니다.
> OSRM 파이프라인(`extract`→`partition`→`customize`→`routed`) 세팅에 8시간이 드는데
> 본선 구현 창구 52시간에 자리가 없습니다.
> **기획서에는 「OSM+OSRM」이 두 곳에 적혀 있으므로 제출본에 정정 표기가 필요합니다**
> → [서비스_기획서.md 맨 앞 「본선 제출본 정정 항목」](../공유_문서/서비스_기획서.md).
> 전국 확장 시에는 OSRM이 필요하므로 **본선 이후 로드맵 첫 항목**으로 잡았습니다.

- **범위를 좁히세요** — 데모 행정동 1곳으로 한정하고, 등급은 **사전 계산한 정적 표**로 붙입니다.
  실시간 등급 계산까지 가면 압축 일정 안에 끝나지 않습니다.
- **「경로 없음」 폴백** — 통과 가능한 길이 없으면 「경로 없음」으로 표기하고 **대피소를 다시 고릅니다.**
  기획서에 명시된 동작이자 실패 모드 시연의 네 번째 케이스입니다.
- **환경 선행 확인** — OSM 도로망 확보와 **보행 그래프 적재**는 착수 **전에** 끝내 둡니다.
  완성이 아니라 뜨는지만 확인하는 일이고, 본작업이 사흘 통으로 붙기 때문에
  환경 문제로 막히면 되돌릴 시간이 없습니다.

### ② 이벤트 로그 파이프라인

AI/RAG가 낸 스키마대로 `SessionStore`를 확장합니다.

- 엔드포인트 2개(기록·조회), **인덱스 없음**, 페이지네이션 없음 —
  한 세션의 이벤트는 상한 수십 건이라 그 이상이 필요 없습니다.
- 저장 대상은 화면 상태·버튼 클릭 시퀀스·도착 이벤트이며, **조회는 세션 단위**입니다.
- 세션을 넘는 시계열 질의(「평소에도 이랬나요」)는 범위 밖이고 「확인할 수 없습니다」로 폴백합니다 —
  그것만 인덱싱이 필요하기 때문입니다.

### ③ FCM 실발송 재연결 · 보호자 2차 발송

`dispatch.py`의 기본 `RecordingDispatcher`는 주석 그대로 **기록만 하고 실제로 보내지 않습니다**
(Admin SDK 자격증명이 배포 VM에만 있어서입니다).
**「도달 30초」·「2차 발송 성공률 100%」 두 지표는 실발송 없이는 측정 자체가 불가능합니다.**
30분 무응답 → 보호자 알림이 실제로 도달하려면 FCM이 먼저 살아야 하므로 한 묶음으로 처리합니다.
보호자 알림은 1차(행정동 단위)와 30분 무응답 시 2차로 나눕니다.

### ④ 폐루프 오케스트레이션

관측 → 계획·검색 → 행동·생성 → 응답 검증 → 전달·에스컬레이션,
**30분 무응답 시 ①로 재진입**하는 5단계 상태기계입니다.
네 번째 칸이 AI/RAG의 대조 검증기, 마지막 칸이 이 포지션의 2차 발송이라
**둘 다 끝난 뒤 조립**합니다. 재진입은 테스트로 증명해야 합니다 —
기획서가 「에이전틱」이라 주장하는 근거가 정확히 이 루프이기 때문입니다.

## 기능 통합이 필요한 부분

- **OSMnx · networkx · OSM** — 라우팅 라이브러리와 도로망은 오픈소스 그대로. 직접 구현하는 것은 링크 등급 부여와 필터입니다. (OSRM 전환은 본선 이후)
- **FCM** — Admin SDK로 발송. 푸시 인프라 자체를 만들지 않습니다.
- **Redis 캐시** — 특보 API 중단 시 캐시로 폴백합니다(→ [아키텍처.md](../공통_가이드/아키텍처.md) 폴백 절).
- **기상청·행안부 Open API** — 신청·인증·폴링 연동은 통합 작업입니다.
- **Shapely** — 위험구역 point-in-polygon 연산은 라이브러리로 해결합니다.

## 다른 역할과의 인터페이스

| 받는 것 | 역할 | 주는 것 |
|---|---|---|
| Q&A 계약(OpenAPI), 폐루프 5단계 상태 전이표 | Tech Lead | 로그 API·폐루프 구현체, 계약 준수 여부 |
| 이벤트 로그 스키마, 대조 검증기 | AI/RAG/FE | 이벤트 로그 저장·조회 API |
| 시드 픽스처 CSV, 롤백 절차서 | PM | 「경로 없음」 재선정 동작, CCTV 좌표·스트림 API, 롤백 실연 동반, 본선 당일 현장 인프라 **실행** |

## 관련 리스크

- **④ 공공 API 의존성** — 특보 API 중단 시 Redis 캐시 폴백이 실제로 도는지 확인해야 합니다.
- **⑤ 위치 정밀도·행정동 경계** — 지오코딩·DEM 매칭 실패는 「판정 불가」로 표기하고 넘어갑니다.
- **③ 30초 지연** — FCM 실발송 경로가 살아 있어야 측정 자체가 성립합니다.
- **⑧ 일정** — 로그 API가 밀리면 AI/RAG 생성부가, 검증기가 밀리면 폐루프가 대기합니다.

## 관련 외부 승인

- **A. 공공 Open API** — 기상청·행정안전부 API는 승인 기관이 달라 별도 신청이며 호출 한도를 사전 확인합니다.
- **B. 위치/지도 API** — 카카오맵 역지오코딩 키, 행정동 코드표 최신본.
- **C. 웹푸시(FCM)** — 프로젝트가 **팀 계정 소유**여야 하고, 실기기 검증에는 HTTPS 배포처가 필요합니다.
- **D. AWS·NCP 계정** — 결제수단 등록 상태를 PM과 함께 확인합니다.
