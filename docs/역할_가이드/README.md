# 세이버스(SAVERS) 역할별 실행 매뉴얼

`CLAUDE.md`, `개발자_가이드.md`, `구현_범위.md`, `아키텍처.md`, `리스크.md`, `외부_승인.md`와 `docs/adr/`의 결정 기록에서 정리된 내용을 역할(직함) 단위로 재구성한 문서입니다. 특정 인물이 아니라 **역할** 기준으로 작성했으므로, 팀 내 담당자가 바뀌거나 한 사람이 여러 역할을 겸해도 그대로 적용할 수 있습니다.

> **2026-08-11 개정 (팀 재편 반영).** 팀이 6인 → 4인으로 줄며 문서가 6개에서 4개로 줄었습니다 —  
> 옛 `04-프론트엔드-UX.md`는 [03-AI-RAG-프론트엔드.md](03-AI-RAG-프론트엔드.md)에,  
> `06-QA-보안.md`는 [01-기획총괄.md](01-기획총괄.md)에 흡수됐고,  
> `05-백엔드-인프라.md`는 [04-백엔드.md](04-백엔드.md)로 이름을 바꾸며 인프라 운영 항목이 01로 옮겨졌습니다  
> (인프라 소유가 `AGENTS.md` 팀 구성표에 따라 안은남(PM)으로 넘어갔기 때문입니다).  
> 번호 체계는 [역할_일정/](../역할_일정/README.md)과 1:1로 맞춰 두었습니다.

각 매뉴얼은 동일한 구조를 따릅니다.

1. **담당 범위** — 이 역할이 책임지는 영역
2. **직접 구현해야 하는 부분** — 외부 모듈로 대체할 수 없는, 이 역할 고유의 구현 작업
3. **기능 통합이 필요한 부분** — 외부 API/오픈소스/다른 역할의 산출물을 가져와 엮는 작업
4. **다른 역할과의 인터페이스** — 무엇을 주고, 무엇을 받는지
5. **관련 리스크** — [리스크.md](../공통_가이드/리스크.md) 중 이 역할이 직접 관리해야 할 항목
6. **관련 외부 승인** — [외부_승인.md](../공통_가이드/외부_승인.md) 중 이 역할이 신청·확인 주체가 되는 항목 (리드타임이 긴 항목은 예선 개시 직후 최우선 처리)

## 전체 그림

이 매뉴얼이 "누가·무엇을"이라면, 각 역할이 그 작업을 **언제** 하는지(시간축·마일스톤·페이즈)는 [역할_일정/](../역할_일정/README.md)에 정리돼 있으니 함께 보세요. 역할 간 데이터가 어떻게 넘어가는지는 [아키텍처.md](../공통_가이드/아키텍처.md)의 파이프라인·모듈 다이어그램을 참고하세요. 대략적인 대응 관계는 다음과 같습니다.

- 모듈 1(위치 매칭 엔진) → 주로 **Backend**
- 모듈 2(RAG 파이프라인) → 주로 **AI 모델·RAG·프론트엔드**
- 모듈 3(에이전틱 LLM 생성) → 주로 **Tech Lead** + **AI 모델·RAG·프론트엔드**
- 모듈 4(무설치 터미널) → 주로 **AI 모델·RAG·프론트엔드**
- 인프라·운영 전반 → **PM** (소유) + **Backend** (본선 당일 현장 실행)
- 전체 통합·일정·QA/보안 → **PM**
