# 세이버스(SAVERS) 역할별 실행 매뉴얼

`CLAUDE.md`, `개발자_가이드.md`, `구현_범위.md`, `아키텍처.md`, `리스크.md`, `외부_승인.md`와 `docs/adr/`의 결정 기록에서 정리된 내용을 역할(직함) 단위로 재구성한 문서입니다. 특정 인물이 아니라 **역할** 기준으로 작성했으므로, 팀 내 담당자가 바뀌거나 한 사람이 여러 역할을 겸해도 그대로 적용할 수 있습니다.

각 매뉴얼은 동일한 구조를 따릅니다.

1. **담당 범위** — 이 역할이 책임지는 영역
2. **직접 구현해야 하는 부분** — 외부 모듈로 대체할 수 없는, 이 역할 고유의 구현 작업
3. **기능 통합이 필요한 부분** — 외부 API/오픈소스/다른 역할의 산출물을 가져와 엮는 작업
4. **다른 역할과의 인터페이스** — 무엇을 주고, 무엇을 받는지
5. **관련 리스크** — [리스크.md](../공통_가이드/리스크.md) 중 이 역할이 직접 관리해야 할 항목
6. **관련 외부 승인** — [외부_승인.md](../공통_가이드/외부_승인.md) 중 이 역할이 신청·확인 주체가 되는 항목 (리드타임이 긴 A·C 항목은 예선 개시 직후 최우선 처리)

## 전체 그림

이 매뉴얼이 "누가·무엇을"이라면, 각 역할이 그 작업을 **언제** 하는지(시간축·마일스톤·페이즈)는 [역할_일정/](../역할_일정/README.md)에 정리돼 있으니 함께 보세요. 역할 간 데이터가 어떻게 넘어가는지는 [아키텍처.md](../공통_가이드/아키텍처.md)의 파이프라인·모듈 다이어그램을 참고하세요. 대략적인 대응 관계는 다음과 같습니다.

- 모듈 1(위치 매칭 엔진) → 주로 **Backend/Infra**
- 모듈 2(RAG 파이프라인) → 주로 **AI/RAG Engineer**
- 모듈 3(에이전틱 LLM 생성) → 주로 **Tech Lead** + **AI/RAG Engineer**
- 모듈 4(무설치 터미널) → 주로 **Frontend/UX**
- 인프라·운영 전반 → **Backend/Infra** + **QA/Security**
- 전체 통합·일정 → **PM**
