# Backend/Infra 역할 매뉴얼

## 담당 범위

기상청·소방청 API 실시간 연동, 위치 매칭 엔진, FastAPI 백엔드, 인프라 이중화, 오프라인 예비모드.  
모듈 1(실시간 위치 매칭 엔진)과 인프라·운영 계층의 실무 구현을 책임집니다.

## 직접 구현해야 하는 부분

- **등록 사용자 ↔ 실시간 위치 매칭 로직** — 평상시 행정동 기반 매칭과, 경보 시 좌표 기반 위험구역 판정을 잇는 핵심 비즈니스 로직.  
    서비스의 존재 이유와 직결되어 외부 모듈로 대체할 수 없습니다.
- **세션 단위 위치 처리·미저장 원칙 구현** — 위치정보를 저장소에 남기지 않고 요청-응답 생명주기 안에서만 사용하도록 하는 처리 흐름.  
    [CLAUDE.md](../../CLAUDE.md)의 비타협 설계 제약 중 하나로, 편의상 캐싱하거나 로그에 남기지 않도록 코드 레벨에서 강제해야 합니다.
- **위험구역 폴리곤 판정 데이터 파이프라인** — 위험구역 원본 데이터(GIS 등)를 수집·정제해  
    판정 가능한 형태로 적재하는 부분(기하 연산 자체는 아래 통합 항목 참고).
- **오프라인 예비모드 전환 로직** — 공공 API 장애·지연 시 사전 캐시된 대피소·행동요령으로 전환하는 판단 기준과 전환 트리거.
- **종단 지연시간 계측용 커스텀 스팬·속성** — 종단간 추적(API 수신 → 알림 발송)과 p95 집계 자체는 아래 통합 항목의 OpenTelemetry로 해결하고,  
    여기서 직접 구현하는 것은 세이버스 고유 파이프라인 단계에만 붙이는 **커스텀 스팬·속성(재난유형, 취약계층 프로필 등)** 입니다.  
    타임스탬프 로깅을 처음부터 자체 제작할 필요는 없습니다.

## 기능 통합이 필요한 부분

- **기상청·소방청·행정안전부 Open API** — 신청·인증·폴링 연동은 통합 작업(API 자체를 만들지 않음).
- **카카오맵 역지오코딩·길찾기 API** — 좌표→행정동 변환, 대피소까지 실제 경로 계산에 통합.
- **행정동 코드 매칭 테이블** — 공공데이터포털의 법정동/행정동 코드표를 그대로 적재, 자체 제작 불필요.
- **위험구역 기하 연산** — Python 백엔드 표준인 **Shapely**로 point-in-polygon 연산 자체는 대체하고,  
    대량 판정 시 GeoPandas·STRtree 공간 인덱스를 활용(직접 알고리즘 구현 불필요).  
    직선거리만 필요하면 하버사인 공식은 직접 구현, 실제 도보 경로·거리는 카카오맵 길찾기 API로 대체.
- **종단 지연시간 계측 인프라** — **OpenTelemetry 분산 트레이싱**으로 "API 수신 → 발송" 구간의 종단 지연·p95를 스팬 연결로 자동 측정하고,  
    집계·시각화는 OTel 백엔드(Grafana Tempo·Jaeger 등)를 활용.  
    세이버스 고유 스팬·속성만 위에 얹습니다(→ [구현_범위.md](../공통_가이드/구현_범위.md) 5절).
- **AWS 단일 VM(서울 리전) + docker-compose** — 예선/데모는 단일 VM에 전체 스택을 올려 운영하고,  
    배포·운영 절차를 README에 정리(심사 요건).  
    관리형 이중화(ALB·ASG·RDS Multi-AZ)는 확장 시로 유보하며  
    README에 전환 경로만 1줄 문서화(→ [ADR-0003](../adr/0003-single-vm-seoul.md)).
- **컴퓨트는 CPU 전용** — 생성(HyperCLOVA X)·임베딩이 외부 API 기반이라 GPU 인스턴스 불필요.  
    자체 서버는 CPU VM으로 구성하며, GPU는 오픈 LLM 자체 호스팅 전환 시에만 재검토.

## 다른 역할과의 인터페이스

| 받는 것 | 역할 | 주는 것 |
|---|---|---|
| 검색 조건 입력 스키마 요구사항 | Tech Lead / AI-RAG | 위험구역 여부, 대피소 거리, 매칭된 프로필 |
| 알림 발송 채널 요구사항 | Frontend/UX | FCM 구독 토큰(`/v1/devices`), 발송 트리거 API |
| 지연시간·장애 실측치 | PM | 리스크 대장 업데이트 |
| 민감정보 처리 요구사항 | QA/Security | 위치정보 미저장 구현 증빙 |

## 관련 리스크

- **④ 실시간 공공 API 의존성** — 가장 직접적인 소관. API 신청·승인 일정을 조기에 확보해야 함.
- **⑤ 위치 정밀도와 행정동 경계 불일치** — 위험구역 판정 로직의 정확도에 직접 영향.
- **③ 30초 지연시간 목표** — 위치 확인·매칭 단계가 전체 예산의 앞부분을 차지하므로 실측이 필요.
- **⑨ 민감정보 처리** — 위치·장애 여부 암호화 및 미저장 원칙 구현의 실무 담당.

## 관련 외부 승인

- **A. 공공 Open API 승인 (리드타임 최장 중 하나)** — 기상청·소방청·행정안전부 API는 승인 기관이 각각 달라  
    **별도로** 활용신청해야 하며, 심사에 수일이 걸리고 호출 한도(레이트리밋)를 사전에 확인해야 합니다.  
    실시간 연동 착수의 선행 조건이므로 예선 개시 직후 최우선 신청(→ [리스크.md](../공통_가이드/리스크.md) ④).
- **B. 위치/지도 API** — 카카오맵 역지오코딩·길찾기 API 키 발급(무료 호출 한도·유료 전환 조건 확인),  
    공공데이터포털 법정동/행정동 코드표 최신본 확보.
- **D. AWS 계정** — 결제수단 등록 및 해커톤·스타트업 크레딧(AWS Activate 등) 신청 가능 여부 확인.  
    HyperCLOVA X(NCP) 계정 신청은 Tech Lead/AI-RAG와 공유.
