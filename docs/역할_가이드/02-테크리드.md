# Tech Lead 역할 매뉴얼 (설계·계약 전담)

담당: 신호정 · 일정: [역할_일정/02-테크리드.md](../역할_일정/02-테크리드.md)

## 담당 범위

시스템 아키텍처, **모듈 간 계약 소유**, 검증기 규칙·폐루프 로직 스펙 정의, 설계 승인,
코드 프리즈 판정, 본선 기술 Q&A 방어.

**이 포지션은 코드를 쓰지 않습니다.** 설계와 스펙을 내리고 판정만 합니다.
이유는 둘입니다.

1. **구현자가 설계까지 하면 압축 일정에서 반드시 어긋납니다.**
   검증기(AI/RAG)와 폐루프(Backend)는 같은 상태 전이표 위에서 만들어져야 하는데,
   두 사람이 각자 자기 설계를 하면 조립 시점에 어긋난 것이 드러납니다 — 고칠 시간이 없는 시점에.
2. **코드를 쓰지 않으니 이해관계 없이 얼릴 수 있습니다.**
   코드 프리즈 선언과 가드레일 임계값 최종 판정이 이 포지션에 있는 것은 그래서입니다.

작업은 **초반 집중형**입니다(→ [ADR-0002](../adr/0002-frontloaded-tech-lead.md)).
예선 구간에서 아키텍처·계약·워킹 스켈레톤·가드레일 초안을 이미 확정했고,
본선 준비 구간에서는 **스펙 3건을 8/22(둘)·8/24(하나)에 몰아 내린 뒤** 리뷰·판정으로 전환합니다.
모든 아키텍처 결정은 `docs/adr/`에 ADR로 남깁니다.

## 직접 정의해야 하는 것 (코드 아님)

- **이벤트 로그 스키마 설계 리뷰** — AI/RAG가 올린 초안을 **같은 날** 확정합니다.
  Backend의 로그 저장·조회 API가 이것을 기다리고, 그 API를 AI/RAG 생성부가 다시 기다립니다.
  **전체의 단일 출발점**이라 반나절 지연이 이틀이 됩니다.
- **보호자 Q&A 계약** (`/v1/guardian/{token}/ask`) — 기존 `ChatResponse`와 같은 모양으로 맞춥니다.
  계약에 반드시 명문화할 두 가지:
  **「검색 대상은 그 세션의 이벤트 로그 전량이며 세션을 넘지 않는다」**,
  그리고 **「sources가 비면 answer는 null」** 불변식.
  앞엣것이 없으면 범위가 흔들리고, 뒤엣것이 없으면 근거 없는 문장이 새어 나갑니다.
- **검증기 규칙 · 폐루프 로직 스펙** — 주장 단위 분해 규칙과 5단계 상태 전이표.
  관측 → 계획·검색 → 행동·생성 → 응답 검증 → 전달·에스컬레이션,
  30분 무응답 시 관측으로 재진입. 이 루프가 기획서가 「에이전틱」이라 주장하는 근거 그 자체입니다.
- **가드레일 임계값 최종 판정** — PM이 돌린 실험 결과를 보고 값을 확정하고 근거를 기록합니다.
  **실행은 PM, 판단은 Tech Lead.**
- **조건부 항목 컷오프에 대한 기술 의견** — 「남은 시간으로 끝나는 상태인가」를 봅니다.
  **판정 자체는 PM이 합니다**(2026-08-21 변경) — 자를 때 달라지는 발표 대본·[표3]·지표 취합이 PM 소관이고,
  예비 시간을 들고 있는 사람도 PM이라 「자를까 / 받아줄까」를 같은 자리에서 정할 수 있기 때문입니다.
  **코드 프리즈 선언은 그대로 이 포지션 소관**입니다.
- **코드 프리즈 선언 · 시연 브랜치 고정** — 이후 기능 추가·리팩터링·버전 업 금지,
  시연 경로 버그 수정만 허용. 전 역할 합의를 받아 태그로 남깁니다.
- **아키텍처 문서 갱신** — [아키텍처.md](../공통_가이드/아키텍처.md)를 실제 구현에 맞춰 유지.

## 기능 통합이 필요한 부분

- **OpenAPI / `packages/contracts`** — 계약은 코드보다 먼저 여기에 존재해야 합니다.
  구두 합의는 계약이 아닙니다(→ [ADR-0002](../adr/0002-frontloaded-tech-lead.md)의 인수인계 보험).
- **LangChain·HyperCLOVA X·Chroma** — 오케스트레이션 뼈대와 생성·검색 엔진은 오픈소스/외부 API 그대로 씁니다.
  설계 대상은 그 위에 얹는 흐름과 가드레일뿐입니다.

## 다른 역할과의 인터페이스

| 받는 것 | 역할 | 주는 것 |
|---|---|---|
| 이벤트 로그 스키마 초안, 검증기 구현체 | AI/RAG/FE | 스키마 확정, 검증기 규칙 스펙, 통합 리뷰 결과 |
| 로그 API·폐루프 구현체 | Backend | 보호자 Q&A 계약(OpenAPI), 폐루프 5단계 상태 전이표 |
| 임계값 실험 결과(#23·#24·#84), 일정 압박 신호, **컷오프 판정 요청** | PM | 가드레일 임계값 최종 판정, 코드 프리즈 선언, **컷오프 기술 의견** |

## 관련 리스크

- **② 안전·가드레일 품질** — 검증기 규칙의 엄밀성이 「로그에 없는 사실 0건」 지표를 좌우합니다.
- **③ 30초 지연** — 폐루프 단계 수·호출 순서가 종단 지연에 직접 영향.
- **⑧ 일정** — 스펙 3건이 **8/22(스키마 리뷰)·8/24(Q&A 계약·검증기 스펙)** 에 내려가지 않으면
  구현 두 사람이 동시에 대기합니다. 이 포지션의 지연은 팀 전체의 지연입니다.
  특히 **8/22는 오후 4시간뿐**이고(오전은 이 포지션의 하네스 작업 구간),
  그 안에 AI/RAG가 스키마 초안부터 확정까지 가야 하므로
  **리뷰는 「설계 논의」가 아니라 「범위 확인」이어야 합니다.**
- **① 채널 제약 (해소됨)** — 알림톡 템플릿 제약은 [ADR-0005](../adr/0005-webpush-primary-channel.md)의
  웹푸시 전환으로 소멸했습니다. 생성 문안은 슬롯에 맞출 필요 없이 **그대로** 전달되며,
  치환 계층을 재도입하지 마세요.

## 관련 외부 승인

- **D. AI 플랫폼 계정** — HyperCLOVA X(NCP) 이용 신청·API 키.
  사용량 기반 과금이라 결제수단 확보 상태를 PM과 함께 확인합니다(신청 주체는 Backend와 공유).
