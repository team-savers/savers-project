# Tech Lead 역할 매뉴얼

## 담당 범위

시스템 아키텍처 설계, Agentic RAG·LangGraph 오케스트레이션, 가드레일 프롬프트 엔지니어링.  
모듈 2(RAG)와 모듈 3(에이전틱 LLM 생성)의 설계 축을 책임지며, 4개 모듈이 하나의 파이프라인으로 이어지도록 인터페이스를 정의합니다.

작업은 **초반 집중형**입니다.  
프로젝트 초반에 아키텍처·모듈 간 계약·Walking Skeleton(전체 흐름 관통 뼈대)·가드레일 설계 초안·스캐폴딩을  
집중적으로 확정해 이후 각 모듈이 병렬로 진행되게 만들고, 이후에는 리뷰·자문 중심으로 참여합니다(→ [ADR-0002](../adr/0002-frontloaded-tech-lead.md)).  
모든 아키텍처 결정은 `docs/adr/`에 ADR로 남겨 계약·골격 지식이 한 사람에게 고이지 않도록 합니다.  
저장소 형태(단일 모노레포, AI는 그 안의 독립 배포 엔진)와 인프라 기준선은 이미 결정돼 있으므로  
([ADR-0001](../adr/0001-monorepo.md)·[ADR-0003](../adr/0003-single-vm-seoul.md)) 스캐폴딩은 이 결정을 전제로 시작합니다.

## 직접 구현해야 하는 부분

- **가드레일 프롬프트 설계** — 검색된 국민행동요령 원문 밖의 내용을 생성하지 못하도록 강제하는 규칙, 원문 부재 시 폴백 응답, 이탈 탐지 방식.  
    [리스크.md](../공통_가이드/리스크.md) ②(안전 오작동)와 직결되는 프로젝트의 핵심 차별화 요소이며 외부 라이브러리로 대체할 수 없습니다.
- **에이전틱 오케스트레이션 구조** — LangGraph 위에서 "검색 → 근거 검증 → 페르소나 조정 → 생성 → 후처리 검증"으로 이어지는  
    체인/에이전트 흐름을 프로젝트 요구사항에 맞게 직접 설계해야 합니다.  
    상태·분기·가드레일 폴백이 있는 흐름은 LangGraph(LangChain 생태계)가 실무 표준이지만,  
    프레임워크는 뼈대일 뿐 흐름 자체는 도메인 지식이 필요합니다.
- **모듈 간 인터페이스(API 계약) 정의** — 위치 매칭 엔진의 출력(위험구역 여부, 대피소 거리, 프로필)이 RAG 검색 조건으로,  
    RAG 결과가 LLM 프롬프트 입력으로 어떤 스키마로 전달되는지 확정.
- **시스템 아키텍처 문서화** — [아키텍처.md](../공통_가이드/아키텍처.md)를 실제 구현에 맞춰 지속적으로 갱신.

## 기능 통합이 필요한 부분

- **LangGraph / LangChain 생태계** — 오케스트레이션 뼈대는 오픈소스 그대로 사용, 커스텀 체인·상태 그래프만 얹습니다.
- **HyperCLOVA X API** — 생성 모델 자체는 통합 대상이며 직접 학습/구축하지 않습니다.
- **Chroma 벡터 DB** — AI/RAG Engineer가 구축한 인덱스를 오케스트레이션 레이어에서 호출하도록 통합.
- **RAGAS/TruLens 같은 RAG 평가 프레임워크** — 가드레일 on/off 비교 실험의 계측 뼈대로 활용 가능(완전히 새로 만들 필요 없음),  
    세이버스 고유 지표만 위에 얹습니다.

## 다른 역할과의 인터페이스

| 받는 것 | 역할 | 주는 것 |
|---|---|---|
| 위험구역·대피소 거리·프로필 데이터 | Backend/Infra | 필요한 입력 스키마 정의 |
| 청킹·인덱싱된 검색 결과 | AI/RAG Engineer | 검색 조건(재난유형+프로필) 인터페이스 |
| 생성 메시지 스트림/완성 결과 | Frontend/UX | 메시지 포맷(변수 슬롯 여부 등) |
| 가드레일 검증 테스트 케이스 | QA/Security | 가드레일 로직 자체 |
| 아키텍처 우선순위 | PM | 일정·리스크 피드백 |

## 관련 리스크

- **② 안전 관련 오작동** — 가드레일 설계 품질에 직접 좌우됨.
- **③ 30초 지연시간 목표** — 오케스트레이션 체인의 단계 수·호출 순서가 지연시간에 직접 영향.
- **① 카카오 알림톡 템플릿 제약** — 생성 메시지가 자유 텍스트인지 변수 슬롯 기반인지에 따라 오케스트레이션 출력 포맷을 미리 조정해야 함.
- **⑥·⑦ 평가지표 신뢰성** — 가드레일 on/off 비교 실험 설계의 학술적 엄밀성 확보 필요.

## 관련 외부 승인

- **D. AI 플랫폼 계정** — HyperCLOVA X(NCP) 이용 신청·API 키가 오케스트레이션·가드레일 v0 구현의 전제.  
사용량 기반 과금이라 팀 예산·결제수단 확보를 초반에 확인(신청 주체는 Backend와 공유하되, 생성 레이어 설계 착수 시점이 이 승인에 묶임).
