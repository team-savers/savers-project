# Frontend/UX 역할 매뉴얼

> 개정 2026-07-27 — 1차 알림 채널이 카카오 알림톡에서 **웹푸시(FCM)** 로 전환됨 (2026-07-26 팀 결정).
> ⚠️ 이 전환의 ADR 등록과 공통 문서(`AGENTS.md`·`아키텍처.md`·`리스크.md`·`구현_범위.md`·`비용_산정.md`·`외부_승인.md`) 갱신은
> 각 소관자 몫으로 남아 있습니다. **아직 그 문서들은 알림톡 전제이므로, 그쪽을 근거로 삼지 마십시오.**
> 이에 따라 **렌더링 어댑터(변수 슬롯 매핑) 작업은 폐기**되었고, 알림톡 관련 항목은 전부 예선 범위 밖입니다.

## 담당 범위

PWA·웹푸시(FCM) 수신 연동, 대화형 챗봇 UI/UX, 접근성(다국어·쉬운 글·음성) 구현, 가독성 지표 계측.
모듈 4(무설치 사용자 터미널)의 실무 구현을 책임집니다.

프론트엔드 배포 형태는 **PWA(웹)로 확정**되어 있으며 네이티브·하이브리드는 제외입니다(→ [ADR-0004](../adr/0004-pwa-over-native.md)).
"무설치 사용자 터미널"·"당사자 설치 부담 없음" 원칙과 정합하고,
푸시 알림 탭 → 브라우저 진입 → 위치 1회 확인 흐름이 웹 권한 모델과 일치하기 때문입니다.
네이티브의 유일한 이점(백그라운드 위치)은 "상시 추적 금지" 원칙상 우리가 써서는 안 되는 기능이라 메리트가 없습니다.
권장 스택은 **React + Vite + `vite-plugin-pwa`(Workbox 기반 SW/오프라인 캐싱)** 입니다.

## 직접 구현해야 하는 부분

- **통합 서비스워커** ★ — FCM은 `firebase-messaging-sw.js`를 요구하고 `vite-plugin-pwa`도 자체 SW를 등록해 **같은 스코프에서 충돌**합니다.
    `strategies: 'injectManifest'` + 커스텀 `src/sw.ts` 하나로 Workbox 오프라인 캐싱과 `onBackgroundMessage`를 **함께** 처리합니다.
    루트에 별도 `firebase-messaging-sw.js`를 두지 않고, `getMessaging` 초기화 시 통합 SW의 registration을 명시적으로 전달합니다.
- **푸시 진입 랜딩(딥링크 → 개인화 페이지)** — 발송 자체는 백엔드(Admin SDK) 소관이므로,
    프론트는 알림 탭으로 `/a?t={session_token}&s={stage}`에 진입해 세션 토큰을 받고 개인화 페이지를 렌더하는 랜딩이 핵심입니다.
    **첫 페인트에 행동지시 문장이 텍스트로 존재**해야 하며(위치·API 실패와 무관하게 내용이 보여야 함),
    위치 권한 거부·실패 시 **등록 행정동 기반 매칭으로 degrade**(단일 실패점이 되지 않도록)하는 UX도 여기서 처리합니다.
- **집/밖 분기 UI** — 웹푸시 알림의 액션 버튼은 플랫폼별 **최대 2개** 제한이 있어 신뢰할 수 없습니다.
    알림은 제목+본문+탭으로 단순화하고, **[집이에요]/[밖이에요]/[도움 요청] 분기는 랜딩 첫 화면에서** 수행합니다.
- **Interactive Care 챗봇 대화 흐름/의도 분기 로직** — 사용자가 "도움"이라고 답장하는 등 추가 질의에 응답하는 시나리오는 세이버스 고유 설계이며,
    오픈소스 챗봇 UI는 뼈대만 제공할 뿐 흐름 자체는 직접 만들어야 합니다. 배치는 **1·2단계 하단 컴포넌트 전용**(3단계에서는 숨김).
- **접근성 통합 UX** — 쉬운 글 표시 + 음성 재생 버튼 + (필요시) 원문 대조 화면을 하나의 사용자 경험으로 엮는 작업.
    개별 기능(TTS, 번역)은 외부 API지만, 조합 방식은 취약계층·외국인 근로자 각각의 사용성을 고려해 직접 설계해야 합니다.
- **가독성 지표 계측 훅** — 행정용어 치환율, "실행 가능한 단일 행동" 포함 여부를 프론트엔드 단에서 로깅하거나 검증할 수 있는 계측 지점.

## 기능 통합이 필요한 부분

- **PWA 서비스워커/오프라인 캐싱** — Workbox 등 기존 라이브러리로 상당 부분 대체 가능. 단 위 "통합 서비스워커" 제약을 지킬 것.
- **웹푸시 인프라 (1차 채널)** — Firebase Cloud Messaging(FCM). 프로젝트 `savers-45f1c` / 웹앱 `savers-web` / VAPID 키 발급 완료 상태이며 프론트는 이 설정을 받아 통합만 합니다.
    ⚠️ 알림톡이 사라지면서 **iOS 제약이 더 이상 우회되지 않습니다.** iOS 웹푸시는 16.4+ **및 홈 화면 추가(A2HS)** 상태에서만 동작하므로,
    **시연 환경을 안드로이드 크롬 / 데스크톱 크롬으로 고정**하고 `apps/frontend/README.md`에 제약을 명시합니다.
    발송(Admin SDK 서비스계정 JSON)은 백엔드 소관이며 **프론트 코드·저장소에 절대 들어오지 않습니다.**
- ~~**카카오 알림톡 발송 대행사(솔라피/알리고)**~~ — 예선 범위 밖. [구현_범위.md](../공통_가이드/구현_범위.md) 4절의 대행사 선정은 이 개정으로 무효(Tech Lead/PM 갱신 대기).
- **보행자 경로** — 카카오맵 기본 API에 도보 길찾기가 없어 **TMAP 보행자 경로 API**를 채택합니다. 폴백은 직선거리 + 방향·거리 안내.
    TMAP 키는 비공개 등급이므로 프록시 경유가 권장되나, 프록시 유무는 Backend/QA와 확정이 필요합니다.
- **지도** — 카카오맵 JS SDK. 개발 서버 포트는 **3000 고정**(SDK 허용 도메인이 `http://localhost:3000`으로 등록되어 있음). 배포 도메인은 콘솔에 추가 등록 필요.
- **TTS** — 클로바보이스, Google TTS 등 외부 API 통합. 자동재생은 크롬 정책 검증 후, 우선 수동 재생 버튼부터.
- **번역** — 파파고 API, Google Cloud Translation 등 외부 API 통합.
- **채팅 UI 컴포넌트** — 오픈소스 채팅 UI 라이브러리로 뼈대 구성, 로직만 직접 연결.

## 관련 리스크

- **iOS 웹푸시 제약** — 알림톡 폐기로 **우회 수단이 사라져 승격된 리스크.** 16.4+ 및 A2HS 상태에서만 동작.
    시연 환경 고정 + README 명시 + 미지원 화면 캡처로 대응하고, 실기기에서 확인합니다.
- **알림 권한 거부** — 알림톡에는 없던 실패 모드. 권한 요청을 페이지 로드 즉시 띄우지 않고 **사용자 제스처에서만** 수행하며,
    거부 상태에서도 링크 진입만으로 랜딩·액션 허브가 완전히 동작해야 합니다.
- **HTTPS 배포 의존** — 웹푸시는 localhost 외에 HTTPS 필수. 배포처가 없으면 안드로이드 실기기 검증이 불가능합니다.
- **⑥ 목표 수치의 근거 박약** 중 메시지 명확성 지표 — 가독성 자동 채점 결과가 목표(치환율 90% 등)에 못 미칠 경우 UI 표시 로직으로 보완 가능한지 확인.
