# apps/ai-engine/eval/

평가 자산(골든 데이터셋·지표) 공간입니다. `src/`와 라이프사이클이 달라 별도 디렉토리로 두되,
**채점 대상(RAG 검색·가드레일 출력)과 같은 배포 단위 안**에 둡니다 — 엔진이 바뀌면 채점 기준도
같은 PR에서 함께 움직여야 측정이 재현되기 때문입니다
([아키텍처.md](../../../docs/공통_가이드/아키텍처.md) 4절, [ADR-0001](../../../docs/adr/0001-monorepo.md)).

SAVERS의 차별화 전략은 **"품질을 재현 가능한 자동 스크립트로 증명한다"** 입니다. 사람이 눈으로
확인한 결과가 아니라, 여기 있는 스크립트의 출력이 제출물의 근거가 됩니다.

## 측정 대상 (목표치는 실측으로 대체되는 가설값 — `AGENTS.md` 참조)

| 지표 | 정의 | 목표(가설) | 여기서 채점하나 |
|---|---|---|---|
| 알림 도달 속도 | 재난 API 수신 → 개인화 알림 발송까지 end-to-end | ≤30초 (100회 평균+p95) | ✅ `run_latency_eval.py` |
| 근거 일치율 | 생성 메시지 ↔ 국민행동요령 원문 일치 | ≥85% (30~50 케이스) | ✅ `run_grounding_eval.py` |
| 환각 억제율 | 동일 셋에 가드레일 on/off 비교 | 환각 ≥50% 감소 | ✅ `run_grounding_eval.py` |
| 메시지 명확성 | 쉬운 말 대체율 / 단일 행동지침 포함률 | ≥90% / 100% | ⚠️ 포함률만 — 대체율은 프론트 채점기가 이 보고서를 이어받아 채점 (아래 참고) |

## 지금 있는 것

| 파일 | 무엇 |
|---|---|
| `metrics.py` | 순수 지표 함수. 입력이 같으면 결과가 같고, I/O·시계·네트워크가 없습니다 |
| `dataset.py` | 골든셋 로더 + 스키마 검사 |
| `golden_dataset/flood_v0.jsonl` | 호우 시나리오 6건 (**전부 `[더미]`** — 실제 코퍼스 확보 전 자리표시자) |
| `test_metrics.py` · `test_golden_dataset.py` | CI가 돌리는 회귀 검사 |
| `run_grounding_eval.py` | 근거 일치율·환각 억제율 채점 → JSON 보고서 |
| `run_latency_eval.py` | 알림 도달 속도 실측(HTTP) → JSON 보고서 |

```bash
# 저장소 루트에서
pip install -e "./apps/ai-engine[dev]"

python apps/ai-engine/eval/run_grounding_eval.py            # 서버 불필요
python apps/ai-engine/eval/run_latency_eval.py --runs 100   # 스택 기동 필요
```

보고서는 `eval/reports/`에 쌓이고 **커밋하지 않습니다**(루트 `.gitignore`).
수치는 스크립트를 다시 돌려 재현하는 것이 원칙이고,
커밋된 보고서는 코드가 바뀐 뒤에도 그대로 남아 거짓말을 합니다.

## ⚠️ 지금 나오는 수치를 그대로 인용하면 안 되는 이유

하네스는 동작하지만, **채점 대상이 아직 스텁**입니다.

- **환각 억제율은 `null`로 나옵니다.** `StubGenerator`는 근거 블록에서 문장을 조립하므로
  환각을 만들 수 없고, 가드레일 on/off 문안이 동일합니다.
  보고서의 `guardrailOffIsIdentical: true`가 그 상태를 표시합니다.
  0%가 아니라 **측정 불가**로 나오는 것이 맞습니다 — 실제 모델을 붙인 뒤에 의미를 가집니다.
- **근거 일치율 100%도 같은 사정입니다.** 원문을 그대로 인용하는 생성기를 원문과 대조한 값입니다.
- **코퍼스가 더미입니다.** `[더미]` 표시가 붙은 픽스처를 기준으로 잰 일치율은
  자리표시자와의 일치율입니다.
- **도달 속도는 하한선입니다.** 기상청 폴링·FCM 왕복·HyperCLOVA X 호출이 전부 빠진 값이라,
  이음매를 하나씩 실물로 바꾸며 다시 재야 합니다. 그 추이 자체가 보여줄 만한 자료입니다.

지금 이 하네스의 값어치는 수치가 아니라 **수치를 만들 자리와 규칙이 고정됐다는 것**입니다.

## 채점 규칙에서 정한 것 (읽지 않으면 수치를 잘못 읽습니다)

- **문장 단위로 셉니다.** 근거 일치율은 "지지되는 문장 / 채점 가능한 문장"입니다.
  본문 전체를 한 덩어리로 겹쳐 보면 인용문이 많은 메시지에서 지어낸 한 문장이 묻힙니다.
  그 한 문장이 이 지표가 잡으려는 실패입니다.
- **정형 문구(프레임)는 채점에서 뺍니다.** 실제 문안은 `프레임 + 모델 출력`입니다
  (행정동·특보를 알리는 도입부, 백엔드가 고른 대피소를 지시하는 마무리).
  둘 다 국민행동요령 원문이 아니라서 그대로 채점하면 모든 메시지가 절반쯤 "근거 없음"으로 나옵니다.
  프레임 문구는 **골든 케이스가 `framePhrases`로 선언**합니다 — 엔진 상수를 import하지 않습니다.
  프레임을 넓히면 골든셋 diff로 드러나야 하기 때문입니다.
- **못 잰 것은 `null`이지 0이 아닙니다.** 근거가 0건이거나 분모가 0이면 `null`을 반환합니다.
  0으로 채우면 채점되지 않은 케이스가 평균을 끌어내려, 낮은 점수가 아니라 **틀린 점수**가 됩니다.
  프론트엔드 `readability.ts`도 같은 규약이라 두 보고서를 나란히 읽을 수 있습니다.
- **지표 함수는 `ai_engine`을 import하지 않습니다.** `guardrail.verify`가 비슷한 계산을 하지만,
  가져다 쓰면 임계값을 낮춰 가드레일을 통과시킬 때 근거 일치율이 같이 올라갑니다.
  채점 대상이 움직일 때 같이 움직이는 값은 지표가 아닙니다. 중복이 의도입니다.
  (`percentile`이 `backend_core`와 겹치는 것은 다른 이유입니다 — 앱 간 import 금지 규약.)

## 명확성 지표가 절반만 여기 있는 이유

**단일 행동지침 포함률**은 여기서 잽니다(`directive_present`).
**용어 치환율**은 여기서 재지 않습니다.

행정용어 사전과 치환 로직이 이미 프론트엔드
[`apps/frontend/src/lib/readability.ts`](../../frontend/src/lib/readability.ts)에 있고,
그쪽이 이 지표의 소관입니다(`AGENTS.md` 역할표).
파이썬으로 사전을 다시 만들면 **같은 제출 지표에 진실이 둘**이 되고,
두 사전이 어긋나는 순간 어느 쪽 수치를 낸 것인지 아무도 답할 수 없습니다.

그래서 용어 치환율은 프론트엔드의
[`apps/frontend/scripts/measure-clarity.ts`](../../frontend/scripts/measure-clarity.ts)가
**이 채점기의 보고서를 입력으로 이어받아** 채점합니다
(후속_과제.md 5번을 닫은 구현).
`run_grounding_eval.py`가 케이스별로 전달 문안(`body`)·근거 인용(`sourceQuotes`)·
수신자 언어(`language`)를 보고서에 실어 주고,
프론트 스크립트는 같은 실행의 같은 문안을 치환율로 채점합니다 —
케이스도 문안도 사전도 각각 하나만 존재합니다.

```bash
# 1) 여기(eval/)에서 문안 생성 + 근거 채점
python run_grounding_eval.py --out reports/grounding_report.json
# 2) 프론트에서 같은 보고서로 치환율 채점 (Node >= 22.18)
cd ../../frontend
npm run eval:clarity -- --in ../ai-engine/eval/reports/grounding_report.json
```

CI에서는 [.github/workflows/clarity-eval.yml](../../../.github/workflows/clarity-eval.yml)
(비필수)이 두 단계를 한 실행으로 돌려 보고서 2종을 아티팩트로 올립니다.
치환율은 두 기준으로 나옵니다 — **화면 표시 문안 기준이 KPI**이고
(한국어 화면은 `substituteAdminTerms` 적용 후, 베트남어 화면은 사전이 없어
원문 그대로 — EasyText와 동일 분기), 생성 문안 그대로의 값은 참고치입니다
(verbatim 인용이 설계라 낮은 것이 정상).

## 파일 이름 규칙 (CI 동작을 가릅니다)

이 디렉토리는 pytest 수집 대상입니다
(`pyproject.toml`의 `testpaths = ["tests", "eval"]`) — 지표 함수가 제출물의 근거인 만큼
회귀 검사가 필요하기 때문입니다. 따라서:

- `test_*.py` → **순수 지표 함수·골든셋 검사 전용**. 외부 API를 부르면 안 됩니다.
- 실제 채점 실행(LLM 호출·골든셋 전량 채점)은 `run_*.py` 처럼 `test_` 로 시작하지 않게
  이름 지으세요. CI가 수집하면 비용이 발생하고 결과가 비결정적이 됩니다.

## 그 밖의 규칙

- **골든 데이터셋(`golden_dataset/`)은 평가 기준 자체**: 신중히 변경하고 이유를 커밋
  메시지에 명시하세요.
- 골든셋 `*.csv` / `*.jsonl`은 루트 `.gitignore`의 `!apps/ai-engine/eval/**/*` 예외로 커밋
  가능합니다 (그 외 위치의 데이터 파일은 커밋 금지 — 디렉토리를 옮기면 이 예외도 함께 옮기세요).
- **알림 도달 속도는 backend까지 걸친 end-to-end 지표**입니다. 여기서 채점하되 backend를
  파이썬 import 하지 말고, 기동된 서비스에 HTTP로 측정하세요(앱 간 import 금지 규칙).
  `run_latency_eval.py`가 그렇게 돼 있습니다.
- **채점 모델은 생성 모델과 달라야 합니다** — 자기채점 편향을 피하기 위한 규약이며, 심사에서
  방법론 신뢰도로 직결됩니다. 현재 채점은 전부 어휘 기반이라 이 조건에 걸리지 않지만,
  교차 모델 채점을 붙이는 시점에 반드시 지켜야 합니다.
- 앱 코드를 import해 채점하려면 해당 앱이 설치돼 있어야 합니다
  (`pip install -e "./apps/ai-engine[dev]"`).
