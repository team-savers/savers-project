# packages/contracts — 모듈 간 계약 (단일 원천)

담당: 신호정(Tech Lead). **구두 합의 금지** — 모든 모듈 간 인터페이스는 여기에 스펙/스키마로
존재해야 합니다. Tech Lead 참여 비중이 줄어든 뒤에도 팀이 독립적으로 작업하려면 이 디렉토리가
사실상의 조정 지점이 됩니다(ADR-0002).

## 상태

`openapi.yaml` — 두 구간이 v0 초안으로 채워져 있습니다.

| 구간 | 상태 |
|---|---|
| frontend ↔ backend (세션·대피소·챗봇·기기등록·보호자 5개) | v0 초안 있음 (2026-07-27, 이진호 제안 / Tech Lead 확정 대기) |
| backend ↔ ai-engine (`POST /v1/generate`, `generation` 태그) | v0 초안 있음 (2026-07-28, Tech Lead 작성) |
| 재난 이벤트 스키마 (수집→매칭) | 미작성 |

**두 구간을 한 파일에 둔 이유**는 [`contracts-check.yml`](../../.github/workflows/contracts-check.yml)이
`packages/contracts/openapi.yaml` **하나만** 검증하기 때문입니다 — 파일을 나누면 새 스펙이
유효성 검사를 못 받습니다. 소비자가 다른 구간은 태그(`generation`)와 경로 단위 `servers`
오버라이드(:8100)로 구분하며, 내부 구간은 `security: []`로 세션 토큰을 요구하지 않습니다.
⚠️ 내부 구간 경로는 **배포에서 외부에 열지 마세요** — 공개되면 취약계층 프로필이 인증 없이
새어 나갑니다.

**초안의 목적은 확정이 아니라 병렬화입니다.** 응답의 모양이 먼저 고정되면 프론트는 mock으로
화면을 완성할 수 있고, 백엔드·AI 엔진은 나중에 합류해도 같은 모양만 맞추면 그대로 붙습니다.
필드명·구조·에러 규약은 리뷰에서 바뀔 수 있으며, 바뀌면 소비자 앱 변경과 **같은 PR**에 담습니다.

남은 구간은 각 소관자가 같은 파일에 덧붙이면 됩니다.

## 규칙

- `openapi.yaml`이 추가되면 [`.github/workflows/contracts-check.yml`](../../.github/workflows/contracts-check.yml)이
  자동으로 스펙 유효성을 검증합니다(non-required, `paths` 필터). 파일이 없는 지금은 건너뜁니다.
  ⚠️ 이 검사는 **스펙 자체의 유효성까지**입니다 — 라우터 응답이 스펙과 다른 드리프트는
  각 앱의 계약 준수 테스트로 잡아야 합니다.
- 계약 변경은 **소비자 앱 변경과 같은 PR**에 담습니다(모노레포를 택한 이유가 이 원자성입니다).
- 계약이 바뀌면 `docs/adr/`에 배경을 남기세요 — "왜 이 모양인지"가 복원 가능해야 합니다.
- 민감 필드(위치, 장애 여부)는 **최소 수집·암호화**가 전제입니다. 스키마에 필드를 추가할 때
  이 조건을 만족하는지 먼저 확인하세요.
